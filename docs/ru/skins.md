# Внешний вид скина

Оформление внешнего вида — это настройки системного уровня. Скин, переключенный после входа в систему, будет сохранен в `active_skin_id` в таблице `settings` на сервере, и все устройства и браузеры будут использовать один и тот же набор текущих скинов.

## Используйте вход

1. Войдите в веб-интерфейс.
2. Откройте «Настройки».
3. Введите «Внешний вид кожи».
4. Выберите существующий скин или установите собственный скин, загрузив zip-файл или репозиторий Git.

Встроенный идентификатор скина — `classic`. Если текущий настроенный скин не существует, имеет недопустимый формат или не может прочитать CSS, интерфейс автоматически возвращается к `classic` и записывает информацию об ошибке в список скинов.

## Формат скин-пака

Корневой каталог пакета скина должен содержать `skin.json` и содержать хотя бы один файл записи CSS.

```json
{
  "id": "midnight-sample",
  "name": "Midnight Sample",
  "version": "1.0.0",
  "entry": "theme.css",
  "description": "Sample dark skin using OutlookEmail CSS variables",
  "preview": "preview.png"
}
```

Описание поля:

| Поле | Обязательное | Описание |
| --- | --- | --- |
| `id` | — идентификатор скина |. Можно использовать только строчные буквы, цифры, подчеркивания и тире, до 64 символов; `classic` | нельзя использовать
| `name` | — отображаемое имя | |.
| `version` | — версия скина | |.
| `entry` | — это путь к файлу записи CSS |, который должен указывать на файл `.css` | в пакете.
| `description` | Нет | Описание скина |
| `preview` | Путь к изображению предварительного просмотра | отсутствует, поддерживаются `png`, `jpg`, `jpeg`, `gif`, `webp` |

Образец скина доступен в репозитории: [`docs/skin-example`](../skin-example).

## CSS-переменные

Пользовательские скины в основном меняют внешний вид интерфейса, переопределяя переменные CSS. В настоящее время поддерживаются следующие основные переменные:

```css
:root {
    --skin-app-bg: #ffffff;
    --skin-surface: #ffffff;
    --skin-surface-muted: #fafafa;
    --skin-surface-soft: #f8fafc;
    --skin-surface-hover: #f0f0f0;
    --skin-border: #e5e5e5;
    --skin-border-strong: #d9dce3;
    --skin-text: #1a1a1a;
    --skin-text-muted: #666666;
    --skin-text-soft: #64748b;
    --skin-primary: #1a1a1a;
    --skin-primary-hover: #111827;
    --skin-primary-text: #ffffff;
    --skin-accent: #2563eb;
    --skin-accent-soft: #eff6ff;
    --skin-accent-border: #bfdbfe;
    --skin-danger: #dc3545;
    --skin-shadow: rgba(15, 23, 42, 0.08);
    --skin-overlay: rgba(0, 0, 0, 0.4);
}
```

В текущей версии завершена только первая партия изменений основной области. Цвета мелких деталей по-прежнему могут контролироваться базовым стилем, а более темные обложки необходимо будет проверить на контрастность и читаемость на реальной странице.

## загрузка в формате zip

Загруженный файл должен представлять собой zip-архив, а корневой каталог пакета должен содержать `skin.json`. Сервер выполнит следующую проверку:

- Максимальный размер zip-файла — 5 МБ.
- Максимальный размер файла CSS — 200 КБ.
- Максимальный размер изображения для предварительного просмотра — 1 МБ.
- Отклоняйте абсолютные пути, обходы путей и символические ссылки.
- Отклоняйте неразрешенные типы файлов, такие как сценарии, HTML, исполняемые файлы и т. д.
- Устанавливайте только скины, прошедшие проверку `skin.json`.

Загрузка скинов с тем же идентификатором и источником приведет к перезаписи старой версии; если тот же идентификатор был установлен из других источников, в установке будет отказано.

## Исходный код хранилища Git.

Исходный код Git подходит для создания независимых складов скинов. Корневой каталог хранилища должен содержать файлы записей `skin.json` и CSS.

Заполните страницу настроек:

- Адрес склада Git, например `https://github.com/user/outlook-skin.git`.
- Необязательная ссылка, например имя ветки, тег или разрешимая ссылка фиксации.

Сервер использует `git clone --depth 1` для извлечения данных со склада. Отсутствие установки или обновления не приведет к изменению текущего активированного скина и не перезапишет существующие файлы скина.

Примечание:

- `git` должен быть установлен в операционной среде.
- Специальной записи управления для учетных данных частного репозитория не существует; не записывайте учетные данные непосредственно в URL-адрес в среде, видимой многим людям.
- Установка Git позволит серверу активно обращаться к указанному адресу склада. Рекомендуется открывать вход в настройки только доверенным администраторам.

## Хранение и резервное копирование файлов

Файлы скинов сохраняются в каталоге `skins/` в том же каталоге, что и файл базы данных. Например, если базой данных по умолчанию является `data/outlook_accounts.db`, каталог скина будет следующим:

```txt
data/skins/
```

Если во время развертывания Docker `./data:/app/data` был смонтирован в соответствии с рекомендациями, файлы базы данных и оформления будут сохраняться вместе. При резервном копировании или миграции вам также следует сохранить:

- `outlook_accounts.db`
- `skins/`

Только резервное копирование базы данных сохранит текущий идентификатор скина, но не файлы пользовательского скина; после восстановления он вернется к `classic`.

## Граница безопасности

Система скинов отвечает только за загрузку CSS и не выполняет сценарии или команды установки в пакете скинов. Сервер будет отклонять распространенные сценарии и файлы HTML.

Еще нужно обратить внимание на:

- CSS может изменить внешний вид интерфейса, скрыть элементы или загрузить удаленные ресурсы.
- Пользовательские скины следует считать конфигурацией, которой доверяют администраторы, и обычные пользователи не должны иметь права загружать их.
- При развертывании в общей среде с несколькими людьми рекомендуется ограничить источник доступа к странице настроек с помощью контроля доступа к сети или обратного прокси-сервера.
