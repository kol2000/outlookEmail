# Область хранения локальной почты

## Область применения

Этот первый этап охватывает обычное чтение почтовых ящиков для учетных записей Outlook/Hotmail и общих учетных записей IMAP. Сохраняемые данные предназначены для обеспечения возможности использования обычного списка рассылки и тела сообщения при перезапуске приложения, временных сбоях поставщика и автономных запусках.

Включенные пути к почтовым ящикам:

- Учетные записи OAuth Outlook/Hotmail с использованием списка/подробного чтения Microsoft Graph.
- Учетные записи OAuth Outlook/Hotmail, которые используют IMAP для обычного чтения почтовых ящиков.
- Стандартные учетные записи провайдеров IMAP.

## Переключатель конфигурации

Обычное локальное хранение почты контролируется `normal_mail_local_retention_enabled` и по умолчанию отключено. Приложение сохраняет обычное удаленное чтение почтового ящика до тех пор, пока пользователь явно не включит этот параметр на странице настроек.

Если эта функция включена, при хранении сохраняются обычные метаданные списка почтовых ящиков и только те тела сообщений, которые были просмотрены или явно заполнены обратно для локального резервного копирования. Сохраненные строки находятся в локальном SQLite. Этот переключатель применяется к обычным потокам списка/подробных сведений о почтовых ящиках Outlook/Hotmail и стандартному IMAP; это не общий архив вложений или архив необработанных сообщений.

Серверная часть хранит этот переключатель в небольшом локальном кэше процесса для путей к горячим спискам рассылки. Обновления настроек через обычный поток `/api/settings` немедленно обновляют кэш; прямые изменения базы данных вне приложения следует рассматривать как неподдерживаемые эксплуатационные изменения до тех пор, пока процесс не будет перезапущен или настройка не будет снова сохранена через приложение.

## Загрузка локального списка

Если сохранение включено, обычные представления списка почтовых ящиков должны сначала загружать сохраненные локальные строки для выбранной учетной записи и папки. Пользовательский интерфейс может отображать этот сохраненный список немедленно, не дожидаясь Microsoft Graph или IMAP, сохраняя обычный порядок получения дат и семантику нумерации страниц. Для продолжения нумерации страниц списка необходимо продолжать использовать локальный сохраненный источник (`source=local`), пока видимый список находится в режиме «сначала локально», чтобы пользователи могли загружать больше первой страницы, даже если удаленный поставщик все еще недоступен.

Если удаленный провайдер недоступен, ограничен по скорости или работает медленно, сохраненный список остается видимым для пользователя резервным вариантом, а не очищается. Локальные строки следует рассматривать как состояние кэшированного почтового ящика, а не как отдельный режим почтового ящика. Если сохранение отключено, клиент не должен запрашивать источник локального списка и должен показывать обычный удаленный результат или явное сообщение об отключении локального хранилища.

Для фильтрации ключевых слов могут потребоваться полные тела. Если сохраненная строка уже имеет кэшированное тело, фильтрация должна сначала проверить это локальное тело и избежать дополнительной удаленной выборки подробностей для того же сообщения. Удаленная выборка подробных данных зарезервирована для строк, чьи кэшированные темы, предварительный просмотр и текст недостаточны для определения соответствия ключевого слова.

## Фоновая удаленная синхронизация

После отображения включенного локального списка приложение может начать фоновую удаленную синхронизацию для той же учетной записи и папки, когда доступны учетные данные и доступ к сети. Успешная удаленная синхронизация должна обновить метаданные списка в SQLite, используя идентификатор поставщика для сообщения, обновить временные метки кэша и избежать дублирования для одной и той же учетной записи, папки, идентификатора сообщения поставщика и режима идентификатора.

Удаленная синхронизация не должна блокировать первоначальный рендеринг списка. Неудачная синхронизация должна оставить сохраненный список нетронутым и отображать подсказку об ошибке или устаревшем состоянии только там, где в существующем пользовательском интерфейсе есть место для этого.

## Уведомление о новом сообщении

Когда фоновая синхронизация обнаруживает сообщения, которые еще не были сохранены локально, клиент должен отображать неразрушающее уведомление о новом сообщении. Уведомление сообщает пользователю, что новые удаленные сообщения доступны без резкой замены списка во время чтения.

Фоновая синхронизация должна выполнять этапирование вновь обнаруженных строк без немедленного объединения их с текущим видимым списком. После того как пользователь принимает уведомление, клиент объединяет промежуточные строки в текущий список, выделяет новые видимые сообщения, обновляет кэш списка и запускает максимально возможное сохранение тела для вновь принятых строк.

## Детальное удержание тела

Если сохранение включено, при открытии сведений о сообщении предпочтение должно отдаваться сохраненному телу, если оно уже кэшировано для этой сохраненной строки списка. Если сохраненная строка еще не имеет тела, приложение должно получить тело из пути активного поставщика, а затем сохранить нормализованное тело отображения и связанные метаданные тела для будущего чтения.

Если удаленная выборка подробных сведений не удалась, но сохраненное тело существует, в подробном представлении сохраненное тело должно отображаться как запасной вариант и указывать, что содержимое кэшировано или может быть устаревшим. Если сохраненного тела не существует и удаленная выборка не удалась, существующий путь ошибки должен оставаться видимым.

Учетные записи OAuth Outlook/Hotmail, использующие резервный вариант IMAP, должны сохранять режим идентификатора сообщения поставщика вместе со строкой. `id_mode=uid` — значение по умолчанию для отсутствующих или недействительных запросов на детали и вложения; `id_mode=sequence` принимается только тогда, когда вызывающая сторона воспроизводит элемент списка на основе последовательности. Это предохраняет чтение UID и порядкового номера от случайного смешивания.

## Статистика удержания

На странице настроек отображается видимая пользователю статистика хранилища от `/api/settings/normal-mail-retention/status`:

- `saved_message_count`: сохранены обычные строки почтового ящика.
- `cached_body_count`: сохраняются строки с кэшированным телом отображения.
- `estimated_retained_bytes`: предполагаемая текстовая нагрузка, сохраняемая в обычных почтовых строках.
- `db_file_bytes`: текущий размер файла базы данных SQLite.
- `clear_status`: состояние и сообщение очистки локального кэша процесса.

Эти поля предназначены для принятия решений по прозрачности и очистке, а не для точного учета квот.

## Очистка кэша

На странице настроек предусмотрено отдельное действие очистки кэша, которое удаляет строки из `retained_normal_mail_messages` без отключения `normal_mail_local_retention_enabled`. Это позволяет пользователям освобождать локальное хранилище, сохраняя при этом возможность сохранения данных в будущем.

Отключение переключателя удержания требует отдельного обновления настроек. Если сохраненные строки существуют, пользовательский интерфейс запрашивает деструктивное подтверждение перед сохранением отключенной настройки. После подтверждения браузер отправляет обновление настроек, а затем вызывает `/api/settings/normal-mail-retention/clear`; серверная часть выполняет очистку в фоновом потоке и сообщает `idle`, `running`, `succeeded` или `failed` через объект очистки состояния.

Во время очистки повторяющиеся запросы на очистку должны повторно использовать текущий статус выполнения вместо запуска другого разрушительного задания. Работник повторяет временные сбои SQLite `database is locked`, прежде чем сообщить `failed`, а пользовательский интерфейс настроек опрашивает состояние с отсрочкой, а не с фиксированным односекундным циклом. После успешной очистки сохраненная таблица обычной почты должна стать пустой, а отключенные запросы локального списка должны оставаться заблокированными с отключенным сообщением локального хранилища.

## Явно вне этой фазы

На этом этапе не сохраняются двоичные файлы вложений, а также не загружается и не сохраняется необработанный MIME-контент. Сохранение двоичных файлов вложений и поведение сохранения/загрузки необработанного MIME должны обрабатываться в более поздней отдельной области.
