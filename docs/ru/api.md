# Документация по API

Этот документ основан на текущей реализации кода. Цель состоит в том, чтобы позволить агентам ИИ, сценариям или внешним системам напрямую подключаться к полному API, а не к разрозненным инструкциям, которые видны только людям.

## Обзор стыковки AI

- Базовый адрес: `http(s)://<host>:<port>`
- Все маршруты находятся по адресу `/api/*`.
- Интерфейсы делятся на две категории:
  - Внешний API: `/api/external/*`, используйте ключ API.
  - Полный API управления: для оставшихся `/api/*` сначала войдите в Интернет, а затем используйте Session Cookie.
- Расширение браузера может использовать `POST /api/extension/login` для обмена одноразовым адресом перехода через пароль для входа в Интернет, а затем установить обычный веб-сеанс.
- Операции записи по умолчанию используют тело запроса JSON, `Content-Type: application/json`.
- Большинство интерфейсов возвращают JSON; несколько загрузок обратных файлов или потоков событий SSE

Рекомендуемая последовательность стыковки:

1. Войдите в Интернет и сохраните сеансовый файл cookie.
2. Вызовите `GET /api/csrf-token`, чтобы получить токен CSRF.
3. Прочтите интерфейс и настройте `GET` напрямую.
4. Интерфейс записи имеет `X-CSRFToken` в заголовке запроса.

## Сертификация

### Внешний API

Внешний API использует аутентификацию ключа API, поддерживая два метода:

- Header: `X-API-Key: your-api-key`
- Query: `?api_key=your-api-key`

Настраивается в веб-интерфейсе `Настройки -> Внешний ключ API`.

### Полный API

Полный API требует входа в веб-интерфейс и использования сеансовых файлов cookie.

### Вход в Интернет и действительность сеанса

Вызовите `POST /login`, чтобы установить сеанс, используя пароль для входа в Интернет. `session_duration_days` — необязательное поле, разрешены только `7`, `30`, `90`, `180` или `permanent`. Если этот параметр опущен, `30` используется по умолчанию:

```json
{
  "password": "web-login-password",
  "session_duration_days": "permanent"
}
```

После успешного входа в систему сеанс с ограниченным сроком истечет в соответствии с выбранным количеством дней с момента успешного входа; последующий доступ не будет продлен. `permanent` не устанавливает абсолютного срока действия, но он все равно истечет после активного выхода из системы, смены версии сеанса из-за изменения пароля для входа, изменения SECRET_KEY или очистки файлов cookie браузера. Возврат `400` при явной отправке других значений не приведет к созданию или перезаписи сеанса входа в систему. Страница веб-входа запоминает последнюю выбранную дату истечения срока действия локально в текущем браузере, но не сохраняет пароли, файлы cookie сеанса или абсолютное время истечения срока действия.

### Пароль для входа в расширение браузера

Расширения браузера не используют внешние ключи API. Расширение сначала вызывает `POST /api/extension/login` и заменяет пароль для входа в Интернет на одноразовый `launch_url`, действительный в течение 60 секунд; затем откройте URL-адрес на вкладке браузера, и сервер напишет обычный веб-сеанс под своим собственным доменным именем и перейдет к веб-консоли.

Тело запроса:

```json
{
  "password": "web-login-password",
  "next": "/#settings"
}
```

Успешный ответ:

```json
{
  "success": true,
  "launch_url": "/extension-login/<token>?next=/%23settings",
  "expires_in": 60
}
```

Описание:

- `next` Необязательно, должен быть внутрисайтовый путь; недопустимые значения вернутся к `/`
- Ссылка `launch_url` одноразовая. Просроченная или повторно открытая ссылка возвращает на страницу входа.
- Расширенный вход в систему не обеспечивает выбора периода. Веб-сеанс, установленный билетом потребления, по умолчанию действителен в течение 30 дней и фиксируется с момента установления сеанса.
- После того, как расширение откроет консоль, последующие веб-страницы по-прежнему работают в соответствии с правилами Session + CSRF API полного управления.

### CSRF

Все внутренние операции записи по умолчанию должны содержать заголовок запроса `X-CSRFToken`, а значение берется из `GET /api/csrf-token`.

Типичный заголовок запроса:

```http
Content-Type: application/json
X-CSRFToken: <csrf-token>
Cookie: session=<session-cookie>
```

### Вторая проверка учетной записи и пароля.

`GET /api/accounts/<account_id>` возвращает только признаки `has_password` и `has_imap_password`, без паролей в открытом виде. Для просмотра пароля вызовите `POST /api/accounts/<account_id>/secrets` и передайте текущий пароль веб-интерфейса в теле JSON. Параметр `field` со значением `password` или `imap_password` позволяет получить только нужное поле. Если `field` не указан, для совместимости возвращаются оба поля:

```json
{
  "password": "web-login-password",
  "field": "password"
}
```

Возврат после успешной проверки:

```json
{
  "success": true,
  "secrets": {
    "password": "account-password"
  }
}
```

Если при обновлении учетной записи поле `password` или `imap_password` опущено в теле запроса, бэкэнд сохранит существующее значение; соответствующий пароль будет обновлен только в том случае, если это поле будет передано явно.

### Общие правила реагирования

Большинство интерфейсов JSON следуют следующим соглашениям:

- `success=true` указывает, что вызов в целом прошел успешно.
- `success=false` означает, что вызов не выполнен, обычно одновременно возвращается `error` или `message`.
- Некоторые интерфейсы вернутся:
  - `partial=true`: Частичный успех
  - `details`: Более подробные причины сбоя.
  - `total`, `count`, `items`: список или статистика.
- Неперехваченные исключения возвращаются единообразно:
  - HTTP `500`
  - `{"успех": false, "ошибка": "<информация об исключении>"}`
- При сбое интерфейсов, связанных с почтой, IMAP и Graph, `error` иногда представляет собой не строку, а структурированный объект:

```json
{
  "code": "IMAP_CONNECT_FAILED",
  "reason_code": "MAIL_NETWORK_FAILED",
  «сообщение»: «Ошибка сетевого подключения: невозможно подключиться к почтовой службе, проверьте DNS, брандмауэр, прокси-сервер и адрес службы»,
  "type": "IMAPConnectError",
  "status": 502,
  "details": "",
  "trace_id": "...",
  "category": "network",
  "proxy_configured": false,
  "retryable": true
}
```

Среди них `code` сохраняет исходный код ошибки интерфейса, а `reason_code` предоставляет более подробные причины сбоя прокси-сервера, тайм-аута, TLS или сбоя сети. AI-клиент должен сначала определить `success`, а затем быть совместимым с `error`. Это может быть строка или объект.

## Описание псевдонима электронной почты

Обычные учетные записи теперь поддерживают настройку нескольких псевдонимов почтовых ящиков.

- И внешний API, и внутренний почтовый интерфейс могут обращаться к одной и той же учетной записи, если они отправлены в основной почтовый ящик или псевдоним почтового ящика.
- Возвращенные результаты могут включать в себя:
  - `requested_email`: адрес электронной почты, переданный в запросе.
  - `resolved_email`: фактический основной почтовый ящик обращения.
  - `matched_alias`: если выбран псевдоним, это соответствующий псевдоним; иначе оно пусто
- Псевдоним почтового ящика поддерживает распространенные специальные символы, такие как `+`, `@`, `&`.
  - Символ `@` можно передавать без кодирования.
  - `+` рекомендуется кодировать как `%2B`.
  - `&` должен быть закодирован как `%26`.

Типичное использование:

1. Автоматически пересылать электронные письма из внешнего почтового ящика B в почтовый ящик A, управляемый этим проектом.
2. Установите почтовый ящик B в качестве псевдонима почтового ящика A.
3. Впоследствии напрямую используйте API этого проекта и используйте адрес электронной почты B в качестве параметра `email`, чтобы получить адрес электронной почты или код подтверждения.

#### Описание режима агрегирования

Когда `folder=all`:

- Серверная часть будет захватывать `inbox` и `junkemail` одновременно.
- `top` — «сколько букв взято из каждой папки»
- Например, при `top=1` будет возвращено не более конвертов `Входящие 1 + Спам 1 = 2`.
- `skip` задаёт число пропускаемых писем отдельно для каждой папки.
- `top=0` является юридически безопасным результатом анализа и возвращает пустой список вместо возврата к номеру по умолчанию.

  - `success: true`
  - `partial: true`
  - `details` содержит сообщение об ошибке для папки с ошибкой.

Если адрес запроса — `@gmail.com` или `@googlemail.com`, разрешение учетной записи сначала возвращается к поиску кандидата на основе исходного адреса и исходного суффикса плюс адрес; после обоих промахов повторите попытку с другим суффиксом. Например, потенциальный заказ для `user+code@gmail.com`:

1. `user+code@gmail.com`
2. `user@gmail.com`
3. `user+code@googlemail.com`
4. `user@googlemail.com`

Если используется резервный кандидат, ответ будет содержать такие поля, как `resolved_query_email`, `fallback_used`, `fallback_email` и т. д.

### POST `/api/external/outlook/upload`

Загрузите учетную запись электронной почты и пароль Outlook и сохраните их в независимой временной таблице загрузки `outlook_upload_accounts`. Значение по умолчанию поля «Разрешено или нет» в складской записи не разрешено (`is_authorized = 0`). Поддерживает загрузку заметок сразу или партиями.

> Примечание. Этот интерфейс отвечает только за хранение и не запускает процесс авторизации; загруженный пароль будет зашифрован и сохранен, а ответ интерфейса не будет отражать пароль.

#### Тело запроса

Отдельный элемент:

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| `email` | строка | — это учетная запись электронной почты |. Перед входом в базу данных он будет преобразован в нижний регистр и удалены начальные и конечные пробелы; дубликаты будут пропущены |
| `password` | строка | — пароль электронной почты | |
| `remark` | строка | Нет | Примечания |

Пакетный режим (выберите один из двух вышеперечисленных):

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| `accounts` | массив | — это массив, элементы | которого — `{email, password, remark?}`; если он не пуст, он будет обрабатываться пакетами |

#### Пример запроса

```bash
# Одиночный
curl -X POST -H "X-API-Key: your-api-key" -H "Content-Type: application/json" \
  -d '{"email":"user@outlook.com","пароль":"pwd123","remark":"optional"}' \
  "http://localhost:5000/api/external/outlook/upload"

# Пакетная обработка
curl -X POST -H "X-API-Key: your-api-key" -H "Content-Type: application/json" \
  -d '{"accounts":[{"email":"a@outlook.com","password":"p1"},{"email":"b@outlook.com","password":"p2"}]}' \
  "http://localhost:5000/api/external/outlook/upload"
```

#### Пример успешного ответа

```json
{
  "success": true,
  "total": 2,
  "added": 1,
  "duplicate": 1,
  "invalid": 0,
  "results": [
    { "email": "a@outlook.com", "status": "added", "id": 5 },
    { "email": "b@outlook.com", "status": "duplicate" }
  ]
}
```

#### Инструкции по возврату

- `total` / `added` / `duplicate` / `invalid`: общее количество этой обработки и количество каждого статуса.
- Значения `results[].status`:
  - `added`: успешно добавлено с помощью `id`.
  - `duplicate`: `email` уже существует и пропускается (исходная запись не будет перезаписана)
  - `invalid`: `email` отсутствует. `@` или `password` пуст и не включен в библиотеку.
- Пароль для загрузки зашифрован и сохранен, а ответ не отображается `password`.
- Входящие записи `is_authorized` всегда `0` (неавторизованные)
- HTTP 400 возвращается, когда в теле запроса нет ни `email`, ни пустого `accounts`.
- Если ключ API отсутствует/недействителен, уровень аутентификации возвращает HTTP 401/403.

### Управление учетной записью загрузки Outlook

Эти интерфейсы используются терминалом веб-управления для поддержки учетной записи автоматической авторизации Outlook в `outlook_upload_accounts`.

Ограничения безопасности:

- Серверная часть сохраняет зашифрованный пароль электронной почты.
- Ответ списка возвращает пакетный текст `password`, который можно использовать для переключения отображения/скрытия таблицы на стороне управления.
- Новые/измененные ответы не возвращают обычный текст `password`.
- Внешний интерфейс использует `has_password`/`password_length`, чтобы определить, был ли сохранен пароль, и использует `password` для переключения отображения в таблице.

#### GET `/api/outlook-upload-accounts`

Запросить учетную запись загрузки по страницам.

Параметры запроса:

| Параметр | Тип | Обязательный | Описание |
| --- | --- | --- | --- |
| `page` | целое число | Нет | Номер страницы, по умолчанию `1` |
| `page_size` | целое число | Нет | Число на странице, API по умолчанию — `20`, максимум — `1000`; на стороне управления по умолчанию используется `20`, обеспечивающий шестерни `10`, `20`, `50`, `100` |.
| `keyword` | строка | Нет | Нечеткий поиск по электронной почте или заметке |
| `auth_status` | строка | Нет | Статус авторизации: `all` (по умолчанию), `authorized`, `unauthorized`; неизвестные значения обрабатываются как `all` |

Когда `keyword` и `auth_status` вводятся одновременно, они фильтруются комбинацией И. `total` и `total_pages` в ответе рассчитываются по результатам комбинированной фильтрации.

`items[]` в ответе содержит расшифрованное поле `password`; `proxy_url` — это агент уровня учетной записи, сохраненный во временной записи, он не включает агента группового наследования. Имя пользователя, пароль, путь и параметры запроса в URL-адресе будут удалены во время сериализации списка; `tags` взят из официального аккаунта с тем же адресом электронной почты в `account_tags`/`tags`. ## Управление группой

| метод | путь | параметр | описание |
| --- | --- | --- | --- |
| GET | `/api/groups` | Нет | Получить все группы, вернуть `parent_id`, `level`, `account_count`, `descendant_account_count`, `sort_position` |
| GET | `/api/groups/<group_id>` | Параметр пути `group_id` | Получить сведения об одной группе |
| POST | `/api/groups` | JSON: `name`, `description?`, `color?`, `proxy_url?`, `sort_position?`, `parent_id?` | Создать группу |
| PUT | `/api/groups/<group_id>` | JSON: `name`, `description?`, `color?`, `proxy_url?`, `sort_position?`, `parent_id?` | Обновить группировку или переместить родительский |
| DELETE | `/api/groups/<group_id>` | Параметры пути `group_id` | Удалить группу; если есть подгруппы, каскадно удалите подгруппы и переместите учетную запись обратно в группу по умолчанию |
| PUT | `/api/groups/reorder` | JSON: `group_ids: number[]`, `parent_id?` | Изменение порядка обычных группировок под одним родительским элементом |

Пример запроса на создание или обновление группы:

```json
{
  «имя»: «Группа агентов»,
  «description»: «Отправляйтесь в Гонконг, агент»,
  "color": "#1a1a1a",
  "proxy_url": "http://127.0.0.1:7890",
  "sort_position": 2,
  "parent_id": null
}
```

Группировка поддерживает до трех уровней дерева:

- `parent_id=null` представляет группировку первого уровня; если указать группировку первого уровня в качестве родительской, будет создана группировка второго уровня, а если указать группировку второго уровня в качестве родительской, будет создана группировка третьего уровня.
- Подгруппы нельзя создавать в группах третьего уровня; временные группы почтовых ящиков нельзя использовать в качестве родительских групп или перемещать в другие группы.
- `sort_position` действует только в пределах одного `parent_id`. Метод `PUT /api/groups/reorder` также меняет порядок только тех `group_ids`, у которых общий родитель.
- `account_count` — количество прямых учетных записей текущей группы, а `descendant_account_count` — количество учетных записей текущей группы и всех дочерних групп.
- Удаление родительской группы приведет к удалению всех дочерних групп и перемещению обычных учетных записей электронной почты из удаленной группы в группу по умолчанию.

## Экспорт и вторичная проверка

Интерфейс экспорта сначала проверит пароль для входа один раз, а затем начнет экспорт после получения `verify_token`. `verify_token` в настоящее время является одноразовым токеном, действительным по умолчанию в течение 5 минут. При экспорте по группе будут включены учетные записи группы и всех подгрупп; когда родительско-дочерние группы передаются одновременно, учетные записи будут экспортированы только один раз.

Метод | | путь | параметр | возврат |
| --- | --- | --- | --- |
| POST | `/api/export/verify` | JSON: `password` | JSON, возврат `verify_token` |
| GET | `/api/groups/<group_id>/export` | Запрос: `verify_token` | `text/plain` Загрузка файла |
| GET | `/api/accounts/export` | Запрос: `verify_token` | `text/plain` Загрузка файла |
| POST | `/api/accounts/export-selected` | JSON: `group_ids: number[]` или `account_ids: number[]`, `verify_token` | `text/plain` Загрузка файла |

Пример запроса двухэтапной проверки:

```json
{
  "password": "your-login-password"
}
```

Пример успешного ответа на второй этап проверки:

```json
{
  "success": true,
  "verify_token": "..."
}
```

Получить список учетных записей.

#### Параметры запроса

| Параметр | Тип | Обязательный | Описание |

#### Тело запроса

### POST `/api/accounts/<account_id>/reauthorize`

Повторно авторизуйте существующую учетную запись Outlook OAuth. Этот интерфейс поддерживает только учетные записи Outlook и не поддерживает учетные записи IMAP.

Тело запроса:

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| `redirected_url` | строка | — это полный URL-адрес обратного вызова | в адресной строке браузера после завершения | авторизации Microsoft.

Интерфейс будет анализировать код авторизации от `redirected_url`, обменивать его на новый токен обновления от Microsoft, а затем только обновлять `client_id`, зашифрованные `refresh_token`, `refresh_token_updated_at` и обновлять поля статуса целевой учетной записи. После успешного сохранения информации об авторизации интерфейс очистит старые ошибки обновления и немедленно запустит проверку обновления токена для одной учетной записи. `success` в ответе указывает, что данные авторизации сохранены; `validation.success` указывает, пройдена ли проверка автоматического обновления.

Пример запроса:

```json
{

```

```json
    "status": "success",
    "message": "Токен успешно обновлен",
    "authorization_type": "graph"

}
```

Пример ответа на ошибку при обновлении проверки:

```json
{
  "success": true,
  «сообщение»: «Повторная авторизация сохранена, но проверка автоматического обновления не удалась»,

  "validation": {
    "success": false,
    "status": "failed",
    "error": {
      "code": "TOKEN_REFRESH_FAILED",
```

Распространенные ошибки:

- `ACCOUNT_REAUTH_UNSUPPORTED`: учетная запись IMAP не поддерживает повторную авторизацию.

- `ACCOUNT_REAUTH_SAVE_FAILED`: не удалось сохранить новую информацию для авторизации.

### POST `/api/accounts/<account_id>/outlook-auto-auth`

Добавьте существующую официальную учетную запись Outlook в очередь автоматической авторизации Outlook. Этот интерфейс считывает адрес электронной почты и пароль официальной учетной записи с сервера, записывает их во временную таблицу `outlook_upload_accounts` и не возвращает простой текстовый пароль. Поддерживаются только учетные записи Outlook, учетные записи IMAP не поддерживаются.

Этот интерфейс не запускает задачу автоматической авторизации Graph немедленно; пользователю по-прежнему необходимо выполнить авторизацию во всплывающем окне автоматической авторизации Outlook. Временная запись, которая уже существует для того же почтового ящика, перезапишет пароль и вернет его в неавторизованное состояние.

Тело запроса: параметры не требуются.

Пример успешного ответа:

```json
{
  "success": true,
  "message": "Добавлена автоматическая авторизация",
  "upload_account_id": 42,
  "email": "user@outlook.com",
  "status": "added"
}
```

Значения `status`:

- `added`: добавлена временная запись.
- `updated`: перезапись существующих временных записей (перестановка в очередь)

Распространенные ошибки:

- `ACCOUNT_NOT_FOUND` (404): учетная запись не существует.
- `ACCOUNT_AUTO_AUTH_UNSUPPORTED` (400): учетные записи IMAP не поддерживают присоединение к автоматической авторизации Outlook.
- `ACCOUNT_PASSWORD_MISSING` (400): пароль учетной записи пуст или не может быть расшифрован.
- `ACCOUNT_AUTO_AUTH_INVALID` (400): неверный адрес электронной почты или пароль.

> ** Ограничение безопасности **: этот интерфейс не возвращает пароль в ответе. Пароль считывается только из зашифрованных данных, сохраненных на сервере, и записывается в зашифрованную промежуточную таблицу.

При добавлении автоматической авторизации `group_id`, теги и `proxy_url` официального аккаунта будут скопированы одновременно во временную таблицу для удобства использования при создании нового официального аккаунта в дальнейшем.

## Управление проектом

Интерфейс проекта используется для управления «независимым статусом почтового ящика в рамках определенного проекта» с помощью `project_key`.

- Один и тот же почтовый ящик может существовать в нескольких проектах одновременно.
- Статусы внутри проекта поддерживаются независимо и не влияют друг на друга.
- Текущий статус проекта включает в себя:
  - `toClaim`: можно собрать.
  - `claiming`: Получение
  - `done`: успешно использовано, больше не выделяется автоматически.
  - `failed`: последнее потребление не удалось, и его необходимо сбросить вручную, прежде чем его можно будет снова распределить.
  - `removed`: выход за пределы проекта вручную.
  - `deleted`: Учетная запись в главной таблице системы была удалена, но история проекта все еще сохраняется.

### POST `/api/projects/start`

Запустите проект.

Этот интерфейс сочетает в себе две семантики: «создать проект» и «полный объем проекта»:

- Если `project_key` не существует:
  - Создать новый проект
  - Сохранить объем проекта
  - Добавьте в проект адреса электронной почты из указанного диапазона.
- Если `project_key` уже существует:
  - Рассматривается как повторный запуск того же проекта.
  - По умолчанию используется исходный диапазон.
  - Если на этот раз `group_ids` будет передан явно, диапазон будет обновлен, а затем заполнен.
  - Будет добавлен только новый адрес электронной почты, а статус существующих проектов не будет сброшен.

Удалить правила компенсации:

- При запуске проекта будут проверены потерянные аккаунты в истории проекта.
- Если учетная запись, соответствующая записи проекта, была удалена из основной таблицы `accounts`, запись проекта будет помечена как `deleted`.
- Если тот же адрес электронной почты позже будет повторно импортирован в систему, старая запись проекта будет повторно использоваться по адресу электронной почты при запуске проекта, а не рассматриваться как новый адрес электронной почты.

Правила псевдонимов почтовых ящиков:

- При `use_alias_email=false` проект заносится в пул по основному адресу электронной почты.
- При `use_alias_email=true` приоритет отдается входу в пул согласно псевдониму учетной записи и адресу электронной почты.
- Если для учетной записи не настроен псевдоним, она все равно вернется к использованию основного адреса электронной почты при `use_alias_email=true`.
- Если при перезапуске существующего проекта `use_alias_email` не передан явно, будет использоваться текущая конфигурация проекта.

| `project_key` | строка | — это идентификатор проекта |, который будет внутренне преобразован в нижний регистр и удалены начальные и конечные пробелы. |

## Обновление и пересылка операций и обслуживания.

### Обновление токена

| метод | путь | параметр | описание |
| --- | --- | --- | --- |
| POST | `/api/accounts/<account_id>/refresh` | Параметр пути `account_id` | Обновление одного токена учетной записи Outlook |
| POST | `/api/accounts/refresh-selected` | JSON: `account_ids: number[]` | Обновить выбранную учетную запись Outlook, автоматически пропустить IMAP или несуществующую учетную запись |
| POST | `/api/accounts/refresh-selected-stream` | JSON: `account_ids: number[]` | Инициализировать выбранную задачу обновления потоковой передачи учетной записи и вернуть `task_id` и `stream_url` |
| GET | `/api/accounts/refresh-selected-stream/<task_id>` | Параметр пути `task_id` | Подписаться на выбранную задачу обновления потоковой передачи учетной записи и вернуть `text/event-stream` |
| GET | `/api/accounts/refresh-all` | Нет | Обновить все учетные записи Outlook и вернуть `text/event-stream` |
| POST | `/api/accounts/<account_id>/retry-refresh` | Параметры пути `account_id` | Повторить единичное неудачное обновление учетной записи |
| GET | `/api/accounts/refresh-failed-stream` | Нет | Потоковая передача повторяет попытку текущей неудачной учетной записи и возвращает `text/event-stream` |
| POST | `/api/accounts/refresh-failed` | Нет | Повторите попытку учетной записи, для которой не удалось выполнить последнее обновление |
| GET | `/api/accounts/trigger-scheduled-refresh` | Запрос: `force=true/false` | Вручную запустить логику «запланированного обновления» один раз и вернуть `text/event-stream` |
| POST | `/api/accounts/stop-full-refresh` | Нет | Запросы на остановку текущей задачи полного обновления |

`/api/accounts/refresh-all`, `/api/accounts/refresh-failed-stream`, `/api/accounts/refresh-selected-stream/<task_id>` и `/api/accounts/trigger-scheduled-refresh` будут возвращать потоки событий SSE. Общие типы событий включают в себя:

- `start`
- `progress`
- `delay`
- `complete`

Чтобы выбрать обновление потоковой передачи учетной записи, вам необходимо сначала инициализировать задачу:

```json
{
  "account_ids": [1, 2, 3]
}
```

`POST /api/accounts/refresh-selected-stream` Возврат в случае успеха:

```json
{
  "success": true,
  "task_id": "task-token",
  "stream_url": "/api/accounts/refresh-selected-stream/task-token"
}
```

Затем используйте `EventSource`, чтобы подписаться на `stream_url`. В этой задаче используется краткосрочное сохранение состояния в процессе, а при развертывании службы необходимо поддерживать одного работника; если задача не существует или срок ее действия истек, SSE вернет событие `type=error`.

`POST /api/accounts/stop-full-refresh` Возврат в случае успеха:

```json
{
  "success": true,
  «message»: «Запрошено остановить текущую задачу полного обновления»
}
```

Если в данный момент не выполняется задача полного обновления, будет возвращен HTTP `409`:

```json
{
  "success": false,
  «message»: «В настоящее время задача полного обновления не выполняется»
}
```

Пример запроса `POST /api/accounts/refresh-selected`:

```json
{
  "account_ids": [1, 2, 3]
}
```

Этот интерфейс вернет:

- `requested_count`
- `processed_count`
- `success_count`
- `failed_count`
- `skipped_count`
- `failed_list`
- `skipped_list`

| метод | путь | параметр | описание |
| --- | --- | --- | --- |
| GET | `/api/accounts/refresh-logs` | Запрос: `limit`, `offset` | Получить все журналы обновлений |
| GET | `/api/accounts/<account_id>/refresh-logs` | Запрос: `limit`, `offset` | Получить журнал обновления отдельной учетной записи |

`GET /api/accounts/refresh-logs/failed` возвращает «снимок почтового ящика, который все еще находится в состоянии сбоя» и больше не является списком журнала исторических ошибок.

| метод | путь | параметр | описание |

- `trigger_check`: запускать ли проверку пересылки сразу после сброса, по умолчанию `true`.

## Почтовый интерфейс

### GET `/api/emails/<email_addr>`

Интерфейс внутреннего списка рассылки. Поддерживает основной почтовый ящик или псевдоним почтового ящика; если почтовый ящик содержит `+`, сначала он будет сопоставлен по полному адресу. Если попадания нет, `+suffix` будет удален шаг за шагом справа налево в соответствии с локальной частью. Резервное сопоставление совместимо с основным почтовым ящиком и псевдонимом почтового ящика. Если доменное имя — `gmail.com` или `googlemail.com`, оно будет продолжать использовать другой суффикс после того, как ни один из исходных кандидатов на суффикс не будет сопоставлен.

#### Параметры запроса

| Параметр | Тип | Обязательный | Описание |
| --- | --- | --- | --- |
| `folder` | строка | Нет | `inbox`, `junkemail`, `deleteditems`, `all` |
| `skip` | int | Нет смещения страницы |, по умолчанию `0`; нецифровые значения используют значение по умолчанию, отрицательные числа обрабатываются как `0` |
| `top` | int | Нет | возвращает количество, значение по умолчанию — `20`; нецифровые числа используют значение по умолчанию, а отрицательные числа обрабатываются как `0`. Максимальное удаленное чтение — `50`, а локальное зарезервированное чтение не усекается до |.
| `source` | строка | Нет | При передаче `local` считывается только локальный список резервирования обычного почтового ящика; `normal_mail_local_retention_enabled=true` | требуется
| `local_only` | bool | no | `1` / `true` / `yes` / `on` эквивалентно `source=local` |
| `subject_contains` | строка | Нет | Сохраняйте в теме только электронные письма, содержащие это ключевое слово, и сохраняйте символы `+` при чтении |
| `from_contains` | строка | Нет | Сохраняйте электронные письма, содержащие это ключевое слово, только у отправителя и сохраняйте символы `+` при чтении |
| `keyword` | строка | Нет | Выполнить дальнейшую фильтрацию по ключевым словам в теме, предварительном просмотре и тексте, а также сохранить символ `+` | при чтении.

При использовании `folder=all` поведение соответствует внешнему API: захват `inbox` и `junkemail` одновременно, объединение и сортировка по времени.

Успешный ответ дополнительно будет содержать `requested_email` и `resolved_email`; когда почтовый ящик запроса достигает псевдонима, он также будет содержать `matched_alias`. Если вы используете Gmail/Googlemail или резервные обращения с дополнительным адресом, также включаются поля `resolved_query_email`, `fallback_used`, `fallback_email` и т. д.

Пометить массовые электронные письма как прочитанные.

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| `email` | строка | — основной почтовый ящик | или псевдоним почтового ящика |.
| `method` | строка | Нет | Значение по умолчанию `graph`, можно передать `imap` |
| `folder` | строка | Нет | Папка по умолчанию, по умолчанию `inbox` |
| `ids` | array<string> | Требуется условие | Режим сокращений, прямая передача массива идентификаторов электронной почты |
| `items` | массив<объект> | Требуется условие | Полный режим, можно указать папку и режим идентификатора для каждого письма отдельно |

Каждый элемент, поддерживаемый в режиме `items`:

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` / `message_id` | строка | Идентификатор электронной почты |
| `folder` | string | `inbox`、`junkemail`、`deleteditems`、`all` |
| `id_mode` | string | `graph`、`uid`、`sequence` |

#### Пример запроса

Режим сокращений:

```json
{
  "email": "user@outlook.com",
  "ids": ["AAMk...", "AAMk..."],
  "folder": "inbox"
}
```

Полный режим:

```json
{
  "email": "user@outlook.com",
  "method": "imap",
  "items": [
    {
      "id": "12345",
      "folder": "inbox",
      "id_mode": "uid"
    },
    {
      "id": "AAMk...",
      "folder": "junkemail",
      "id_mode": "graph"
    }
  ]
}
```

#### Поля ключей ответа

| Поле | Описание |
| --- | --- |
| `success` | `true` | только если все успешно.
| `success_count` | Количество писем, успешно помеченных как прочитанные |
| `failed_count` | Количество отказов |
| `updated_ids` | Список адресов электронной почты успешно обновлен |
| `errors` | Подробный список неисправностей |
| `error` | Первое сообщение об ошибке, совместимое со старой логикой внешнего интерфейса |.

### POST `/api/emails/retain-bodies`

Завершите кэширование подробного текста для зарезервированных строк общего списка почтовых ящиков для локальных списков приоритетов, приглашений на новую почту после слияния и последующего отката автономных сведений. Этот интерфейс выполняется только тогда, когда `normal_mail_local_retention_enabled=true`; при закрытии возвращает `local_retention_enabled=false` и пропускает все элементы.

#### Поля запроса

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| `email` | строка | — это обычный адрес электронной почты | или псевдоним |.
| `folder` | строка | Нет | Папка по умолчанию, по умолчанию `inbox`; один элемент `items` может перезаписать |
| `method` | строка | Нет | Метод чтения по умолчанию, по умолчанию `graph`; один элемент `items` может покрывать |
| `items` | массив | Нет | Перечислите элементы, которые необходимо заполнить. Каждый элемент может включать `id`/`message_id`, `folder`, `method`, `id_mode` |.
| `ids` | массив | Нет | совместим со старыми вызовами; если `items` не передан, он используется в качестве заполняемого списка идентификаторов |

#### Поле ответа

| Поле | Описание |
| --- | --- |
| `cached_count` | Количество успешно завершенных текстов на этот раз |
| `skipped_count` | Количество |, пропущенных из-за существующего кеша, неполных параметров или превышения верхнего предела сервера.
| `failed_count` | Количество неудачных удаленных операций чтения |
| `limit` | Верхний предел сервера, который можно заполнить за один раз |
| `results` | Результат одиночного завершения |
| `errors` | Причина единичного отказа |

### POST `/api/emails/delete`

Удалять электронные письма пакетами (безвозвратное удаление).

#### Тело запроса

```json
{
  "email": "user@outlook.com",
  "method": "graph",
  "folder": "inbox",
  "items": [
    {
      "id": "AAMk...",
      "folder": "inbox",
      "id_mode": "graph"
    }
  ]
}
```

Совместимо со старыми форматами:

```json
{
  "email": "user@outlook.com",
  "ids": ["AAMk...", "AAMk..."]
}
```

Описание:

- Рекомендуется передавать `items` (включая `id` / `folder` / `id_mode`) и `method`, в соответствии с `/api/emails/mark-read`.
- Учетные записи Outlook разделены по `id_mode`/`method`: `graph` использует Graph API, `uid`/`sequence` использует OAuth IMAP.
- Стандартная учетная запись IMAP навсегда удалена через IMAP `STORE \\Deleted` + `EXPUNGE`.
- По-прежнему принимаются старые клиенты, которые передают только `ids`; в настоящее время по умолчанию используется обработка графов.

### Управление каналами Cloudflare

Cloudflare Temp Email поддерживает многоканальную конфигурацию. Каждый канал содержит `name`, `worker_domain`, `email_domains`, `admin_password`, `enabled`, `is_default`. `email_domains` является необязательным. Если оставить это поле пустым, канал все равно можно сохранить, но имя домена не может быть выбрано автоматически при создании электронного письма; пароль администратора передается только при сохранении; в ответе списка возвращается только `admin_password_configured`.

Создание каналов:

```http
POST /api/cloudflare/channels
```

```json
{
  "name": "cfmail-us",
  "worker_domain": "cfmail-us.example.workers.dev",
  "email_domains": "mail-us.example.com, alt-us.example.com",
  "admin_password": "ADMIN_PASSWORD",
  "enabled": true,
  "is_default": true
}
```

При обновлении существующих каналов `admin_password` можно оставить пустым, что указывает на сохранение исходного пароля; `email_domains` также можно оставить пустым, и интерфейс запроса доменного имени вернет успешный ответ и пустой список. Перед удалением канала система проверит, существует ли еще временный почтовый ящик Cloudflare, ссылающийся на канал; указанный канал нельзя удалить, и его можно сначала деактивировать.

### GET `/api/cloudflare/messages`

### GET `/api/skins`


Описание поля:

| Поле | Описание |
| --- | --- |

### POST `/api/skins/<skin_id>/activate`

Включить указанный скин. Этот параметр является параметром системного уровня. После сохранения все устройства, вошедшие в систему, будут использовать один и тот же текущий скин.

Пример успешного ответа:

```json
{
  "success": true,
  «сообщение»: «Скин включен»,
  "active_skin": {
    "id": "classic",
    "source_type": "builtin",
    "active": false,
    "status": "ok"
  },
  "asset_hash": "classic"
}
```

Распространенные ошибки при сбое:

- `Неверный идентификатор скина`
- `Скина не существует`
- `Скин недоступен`

Вы также можете отправить `active_skin_id` через `PUT /api/settings`, чтобы добиться того же эффекта.

### POST `/api/skins/git/install`

Установите скин из репозитория Git. Корневой каталог хранилища должен содержать файлы записей `skin.json` и CSS.

Пример запроса:

```json
{
  "git_url": "https://github.com/user/outlook-skin.git",
  "git_ref": "main"
}
```

Описание:

- Требуется `git_url`.
- `git_ref` необязателен: укажите ветку, тег или другую ссылку, которую поддерживает `git clone --branch`.
- `git` должен быть установлен в операционной среде.
- Специального входа для управления учетными данными частного склада не существует, и не рекомендуется записывать учетные данные непосредственно в URL-адрес, видимый нескольким людям.

Успешный ответ соответствует интерфейсу загрузки. Если установка не будет выполнена, текущий активированный скин не изменится.

### POST `/api/skins/<skin_id>/git/update`

Обновите установленный исходный скин Git. Сервер будет использовать `git_url` и `git_ref`, сохраненные в скине, чтобы снова получить его, и потребует, чтобы обновленный `skin.json.id` соответствовал исходному идентификатору скина.

Пример успешного ответа:

```json

  "success": true,

  "skin": {
    "id": "midnight-sample",
    "source_type": "git",
    "status": "ok"
```

Существующие файлы скинов не будут перезаписаны при сбое обновления.

### POST `/api/settings/normal-mail-retention/clear`

Запустите задачу фоновой очистки, чтобы удалить локальные сохраненные данные обычного почтового ящика в `retained_normal_mail_messages`. Этот интерфейс не будет автоматически отключать `normal_mail_local_retention_enabled`; Выключение осуществляется независимо `PUT /api/settings`.

Задачи очистки находятся в состоянии «в процессе»: повторные запросы не запускают второй поток удаления, а вместо этого возвращают текущее состояние `running` с помощью `already_running=true`. Когда фоновое удаление сталкивается с кратковременным SQLite `database is locked`, оно повторяется ограниченным образом; окончательный результат опрашивается через интерфейс состояния.

#### Пример успешного ответа

```json
{
  "success": true,
  "already_running": false,
  "status": {
    "state": "running",
    «message»: «Очистка локального кэша хранения обычных почтовых ящиков»
  }
}
```

## Описание

### Использование прокси

API, связанный с почтовым ящиком учетной записи, в настоящее время отдает приоритет конфигурации прокси-сервера на уровне учетной записи; только если учетные записи `proxy_url`, `fallback_proxy_url_1` и `fallback_proxy_url_2` пусты, конфигурация прокси-сервера группы, к которой принадлежит учетная запись, будет унаследована. Если в текущей группе не настроен прокси-сервер, она продолжит поиск прокси-сервера родительской группы вверх, пока не найдет группу-предка с конфигурацией прокси-сервера или не достигнет группы первого уровня:

- Получение графического токена
- Список рассылки графиков
- Подробности графика по электронной почте
- Получение токена Outlook OAuth IMAP
- Список IMAP OAuth Outlook/Подробности/Удалить
- Пароль Список IMAP/Сведения/Удалить
- Прямой опрос для сбора сообщений/сведения.

### Правила конфликта псевдонимов

Псевдоним будет проверен при сохранении:

- Он не может совпадать с основным адресом электронной почты этой учетной записи.
- Он не может совпадать с основным адресом электронной почты других учетных записей.
- Невозможно повторить с другими псевдонимами учетной записи.
- Не может конфликтовать с временным адресом электронной почты.

### Особые типы ответов

Следующие интерфейсы не являются обычными интерфейсами данных JSON:

- `GET /api/accounts/refresh-all`: `text/event-stream`
- `GET /api/accounts/refresh-failed-stream`: `text/event-stream`
- `GET /api/accounts/trigger-scheduled-refresh`: `text/event-stream`
- `GET /api/groups/<group_id>/export`: загрузка файла `text/plain`
- `GET /api/accounts/export`: загрузка файла `text/plain`
- `POST /api/accounts/export-selected`: загрузка файла `text/plain`
