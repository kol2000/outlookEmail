# Документация по API

Этот документ основан на текущей реализации кода. Цель состоит в том, чтобы позволить агентам ИИ, сценариям или внешним системам напрямую подключаться к полному API, а не к разрозненным инструкциям, которые видны только людям.

## Обзор стыковки AI

- Базовый адрес: `http(s)://<host>:<port>`
- Все маршруты находятся по адресу `/api/*`.
- Интерфейсы делятся на две категории:
  - Внешний API: `/api/external/*`, используйте ключ API.
  - Полный API управления: для оставшихся `/api/*` сначала войдите в Интернет, а затем используйте Session Cookie.
- Расширение браузера может использовать `POST /api/extension/login` для обмена одноразовым адресом перехода через пароль для входа в Интернет, а затем установить обычный веб-сеанс.
— Операции записи по умолчанию используют тело запроса JSON, `Content-Type: application/json`.
— Большинство интерфейсов возвращают JSON; несколько интерфейсов возвращают загрузки файлов или потоки событий SSE.

Рекомендуемая последовательность стыковки:

1. Войдите в Интернет и сохраните сеансовый файл cookie.
2. Вызовите `GET /api/csrf-token` для получения токена CSRF.
3. Прочтите интерфейс и настройте `GET` напрямую.
4. Интерфейс записи содержит `X-CSRFToken` в заголовке запроса.

### Основы и аутентификация

| Метод | Путь | Аутентификация | Тип возврата | Описание |
| --- | --- | --- | --- | --- |
| ПОСТ | `/login` | Нет | JSON | Используйте пароль для создания веб-сеанса, и вы можете выбрать период действия входа |
| ПОЛУЧИТЬ | `/api/version-status` | Сессия | JSON | Текущая версия и статус версии со склада |
| ПОЛУЧИТЬ | `/api/csrf-token` | Сессия | JSON | Получите токен CSRF, соответствующий текущему сеансу входа в систему |

| ПОЛУЧИТЬ | `/extension-login/<token>` | Одноразовый жетон | Перенаправление | Использовать токен расширенного входа, перейти после установления веб-сеанса |

## Аутентификация

### Внешний API

Внешний API использует аутентификацию ключа API, поддерживая два метода:

- Header: `X-API-Key: your-api-key`
- Query: `?api_key=your-api-key`

Можно настроить в веб-интерфейсе «Настройки -> Внешний ключ API».

Ключ API разделен на два уровня разрешений («Настройки -> Разрешения внешнего ключа API» или чтение и изменение через поле `external_api_key_permission` в `GET/PUT /api/settings`):

— `readonly` (по умолчанию): сохранить все внешние возможности перед обновлением, включая запрос списков учетных записей, запрос электронной почты, загрузку временных учетных записей Outlook и запрос списков проектов и пулов почтовых ящиков проекта.
- `readwrite`: дополнительно разрешает импорт аккаунтов (`POST /api/external/accounts`), удаление (`DELETE /api/external/accounts/email/<email_addr>`), перенос между группами (`POST /api/external/accounts/batch-update-group`), операции с проектами (`start`, `claim-random`, `complete-success`, `complete-failed`, `release`, `reset-failed`, `remove-account`, `restore-account`) и управление их жизненным циклом (`archive`, `restore`, `DELETE /api/external/projects/<project_key>`).

Если разрешение равно `readonly`, вызов конечной точки чтения-записи возвращает `403`, а сообщение об ошибке содержит инструкции переключения; значение разрешения не чувствительно к регистру, и `400` возвращается при записи недопустимых значений.

### Полный API

Полный API требует входа в веб-интерфейс и использования сеансовых файлов cookie.

### Вход в Интернет и период действия сеанса

Позвоните по `POST /login`, чтобы установить сеанс, используя пароль для входа в Интернет. `session_duration_days` — необязательное поле, разрешены только `7`, `30`, `90`, `180` или `permanent`. Если этот параметр опущен, `30` используется по умолчанию:

```json
{
  "password": "web-login-password",
  "session_duration_days": "permanent"
}
```

После успешного входа в систему срок действия сеанса с ограниченным сроком действия истечет в соответствии с выбранным количеством дней с момента успешного входа; последующий доступ не будет продлен. `permanent` не устанавливает абсолютного срока действия, но он все равно истечет после активного выхода из системы, смены версии сеанса из-за изменения пароля для входа, изменения SECRET_KEY или очистки файлов cookie браузера. Возврат `400` при явной отправке других значений не приведет к созданию или перезаписи сеанса входа в систему. Страница веб-входа запоминает последнюю выбранную дату истечения срока действия локально в текущем браузере, но не сохраняет пароли, файлы cookie сеанса или абсолютное время истечения срока действия.

### Пароль для входа в расширение браузера

Расширения браузера не используют внешние ключи API. Расширение сначала вызывает `POST /api/extension/login` и заменяет пароль для входа в Интернет на одноразовый `launch_url`, действительный в течение 60 секунд; затем откройте URL-адрес на вкладке браузера, и сервер напишет обычный веб-сеанс под своим собственным доменным именем и перейдет к веб-консоли.

Тело запроса:

```json
{
  "password": "web-login-password",
  "next": "/#settings"
}
```

Успешный ответ:

```json
{
  "success": true,
  "launch_url": "/extension-login/<token>?next=/%23settings",
  "expires_in": 60
}
```

Описание:

— `next` не является обязательным и должен представлять собой внутрисайтовый путь; недопустимые значения вернутся к `/`
— `launch_url` можно употребить только один раз. Если срок его действия истечет или он будет открыт повторно, он вернется на страницу входа в систему.
- Расширенный вход не обеспечивает выбор периода. Веб-сеанс, установленный билетом потребления, по умолчанию действителен в течение 30 дней и фиксируется с момента установления сеанса.
— После того, как расширение откроет консоль, последующие веб-страницы по-прежнему работают в соответствии с правилами Session + CSRF API полного управления.

### CSRF

Все внутренние операции записи по умолчанию должны содержать заголовок запроса `X-CSRFToken`, а значение берется из `GET /api/csrf-token`.

Типичный заголовок запроса:

```http
Content-Type: application/json
X-CSRFToken: <csrf-token>
Cookie: session=<session-cookie>
```

### Вторая проверка учетной записи и пароля

`GET /api/accounts/<account_id>` возвращает только теги `has_password` и `has_imap_password`, но не возвращает пароль учетной записи или пароль IMAP в виде обычного текста. Если необходимо отобразить пароль, вызовите `POST /api/accounts/<account_id>/secrets` и передайте текущий пароль для входа в Интернет в теле запроса JSON. Необязательное значение `field` — `password` или `imap_password`, которое используется для получения только поля пароля, отображаемого в данный момент; если `field` не передан, возвращаются два поля:

```json
{
  "password": "web-login-password",
  "field": "password"
}
```

Возврат после успешной проверки:

```json
{
  "success": true,
  "secrets": {
    "password": "account-password"
  }
}
```

Если при обновлении учетной записи поле `password` или `imap_password` опущено в теле запроса, бэкэнд сохранит существующее значение; соответствующий пароль будет обновлен только в том случае, если это поле будет передано явно.

### Соглашение об универсальном ответе

Большинство интерфейсов JSON следуют следующим соглашениям:

— `success=true` указывает, что вызов в целом прошел успешно.
— `success=false` указывает, что вызов не удался, и обычно одновременно возвращает `error` или `message`.
— Вернутся некоторые интерфейсы:
  - `partial=true`: Частичный успех
  - `details`: Более подробные причины сбоя.
  - `total`, `count`, `items`: список или статистика
— Неперехваченные исключения возвращаются единообразно:
  - HTTP `500`
  - `{"успех": false, "ошибка": "<информация об исключении>"}`
— При сбое интерфейсов, связанных с почтой, IMAP и Graph, `error` иногда представляет собой не строку, а структурированный объект:

```json
{
  "code": "IMAP_CONNECT_FAILED",
  "reason_code": "MAIL_NETWORK_FAILED",
  «сообщение»: «Ошибка сетевого подключения: невозможно подключиться к почтовой службе, проверьте DNS, брандмауэр, прокси-сервер и адрес службы»,
  "type": "IMAPConnectError",
  "status": 502,
  "details": "",
  "trace_id": "...",
  "category": "network",
  "proxy_configured": false,
  "retryable": true
}
```

Среди них `code` сохраняет исходный код ошибки интерфейса, а `reason_code` предоставляет более подробные причины сбоя прокси-сервера, тайм-аута, TLS или сети. AI-клиент должен сначала определить `success`, а затем быть совместимым с `error`. Это может быть строка или объект.

Пример успешного ответа:

## Описание псевдонима электронной почты

Обычные учетные записи теперь поддерживают настройку нескольких псевдонимов почтовых ящиков.

— И внешний API, и внутренний почтовый интерфейс могут обращаться к одной и той же учетной записи, если они отправлены в основной почтовый ящик или псевдоним почтового ящика.
– Возвращенные результаты могут содержать:
  – `requested_email`: адрес электронной почты, переданный в запросе.
  - `resolved_email`: фактическое попадание в основной почтовый ящик.
  - `matched_alias`: если выбран псевдоним, это соответствующий псевдоним; иначе оно пусто
— псевдоним почтового ящика поддерживает распространенные специальные символы, такие как `+`, `@`, `&`.
  - `@` может передаваться напрямую
  - `+` рекомендуется кодировать как `%2B`.
  - `&` должен быть закодирован как `%26`

Типичное использование:

1. Автоматически пересылать электронные письма из внешнего почтового ящика B в почтовый ящик A, управляемый этим проектом.
2. Установите почтовый ящик B в качестве псевдонима почтового ящика A.
3. Затем напрямую используйте API этого проекта, чтобы получить адрес электронной почты или код подтверждения, используя адрес электронной почты B в качестве параметра `email`.

Получите список рассылки указанного почтового ящика и поддержите совокупный запрос к основному почтовому ящику, псевдониму почтового ящика и почтовому ящику/корзине.

| `from_contains` | строка | Нет | Сохраняйте только электронные письма, отправители которых содержат это ключевое слово |

#### Описание режима агрегации

Когда `folder=all`:

– Серверная часть будет сканировать как `inbox`, так и `junkemail`.

— Например, при `top=1` будет возвращено не более сообщений «Входящие 1 + Спам 1 = 2».
— `skip` — это еще и «сколько букв пропустить для каждой папки»
— `top=0` является юридически безопасным результатом анализа и возвращает пустой список вместо возврата к номеру по умолчанию.
— Результаты сортируются равномерно в обратном порядке по нормализованному времени отправки электронной почты.
— сценарий IMAP будет отдавать приоритет `INTERNALDATE`, возвращаемому сервером; он также совместим с такими форматами времени, как `Tue, 14 Apr 2026 08:20:50 +0000 (UTC)`.
– Каждое электронное письмо будет содержать `folder`.
— Если одна папка выполнена успешно, а другая — нет, она вернет:
  - `success: true`
  - `partial: true`
  - `details` содержит сообщение об ошибке для папки с ошибкой.

#### Резервный суффикс Gmail/Googlemail

Если адрес запроса — `@gmail.com` или `@googlemail.com`, разрешение учетной записи сначала вернется к поиску кандидата на основе исходного адреса и исходного суффикса плюс адрес; после обоих промахов повторите попытку с другим суффиксом. Например, потенциальный заказ для `user+code@gmail.com`:

1. `user+code@gmail.com`
2. `user@gmail.com`
3. `user+code@googlemail.com`
4. `user@googlemail.com`

Если используется резервный кандидат, ответ будет содержать поля `resolved_query_email`, `fallback_used`, `fallback_email` и т. д.

### POST `/api/external/outlook/upload`

Загрузите учетную запись электронной почты и пароль Outlook и сохраните их в независимой временной таблице загрузки `outlook_upload_accounts`. Значение по умолчанию поля «Разрешено или нет» в складской записи не разрешено (`is_authorized = 0`). Поддерживает загрузку заметок сразу или партиями.

> Примечание. Этот интерфейс отвечает только за хранение и не запускает процесс авторизации; загруженный пароль будет зашифрован и сохранен, а ответ интерфейса не будет отражать пароль.

#### Тело запроса

Отдельный элемент:

| Поле | Тип | Требуется | Описание |
| --- | --- | --- | --- |
| `email` | строка | Да | Учетную запись электронной почты, преобразовать в нижний регистр перед входом в базу данных и удалить начальные и конечные пробелы; дубликаты будут пропущены |
| `password` | строка | Да | Пароль электронной почты |
| `remark` | строка | Нет | Примечания |

Пакетный режим (выберите один из двух вышеперечисленных):

| Поле | Тип | Требуется | Описание |
| --- | --- | --- | --- |
| `accounts` | массив | Да | Массив, элементами которого являются `{email, password, remark?}`; если он не пуст, он будет обрабатываться пакетно |

#### Пример запроса

```bash
# Одиночный элемент
curl -X POST -H "X-API-Key: your-api-key" -H "Content-Type: application/json" \
  -d '{"email":"user@outlook.com","пароль":"pwd123","remark":"optional"}' \
  "http://localhost:5000/api/external/outlook/upload"

# Пакет
curl -X POST -H "X-API-Key: your-api-key" -H "Content-Type: application/json" \
  -d '{"accounts":[{"email":"a@outlook.com","password":"p1"},{"email":"b@outlook.com","password":"p2"}]}' \
  "http://localhost:5000/api/external/outlook/upload"
```

#### Пример успешного ответа

```json
{
  "success": true,
  "total": 2,
  "added": 1,
  "duplicate": 1,
  "invalid": 0,
  "results": [
    { "email": "a@outlook.com", "status": "added", "id": 5 },
    { "email": "b@outlook.com", "status": "duplicate" }
  ]
}
```

#### Инструкции по возврату

- `total` / `added` / `duplicate` / `invalid`: общее количество этой обработки и количество каждого статуса.
— значение `results[].status`:
  - `added`: успешно добавлено с помощью `id`.
  - `duplicate`: `email` уже существует и пропускается (исходная запись не будет перезаписана)
  - `invalid`: `email` отсутствует `@` или `password` пуст и не включен в библиотеку
- Пароль для загрузки зашифрован и сохранен, а ответ не отображается `password`
- Входящие записи `is_authorized` всегда `0` (неавторизованные)
— HTTP 400 возвращается, если в теле запроса нет ни `email`, ни `accounts`, что не является пустым.
— HTTP 401/403 возвращается уровнем аутентификации, когда ключ API отсутствует/недействителен.

### POST `/api/external/accounts`

Пакетный импорт **официальных учетных записей электронной почты** (запись в основную таблицу `accounts`) требует ключа API и разрешений на чтение и запись (`readwrite`).

Поддержка того же формата строки учетной записи, что и веб-клиент; учетная запись Outlook — «Электронная почта ---- Пароль ---- Третий абзац ---- Четвертый абзац» (третий абзац по умолчанию — это идентификатор клиента, а четвертый абзац — токен обновления; вы также можете указать обратный порядок через `account_format`, и система автоматически определит и исправит ошибку в соответствии с формой UUID). Учетная запись IMAP поддерживает `электронную почту ----пароль IMAP` (встроенный поставщик) или `электронную почту ----пароль IMAP ----хост IMAP ----порт IMAP` (`provider` — `custom`).

#### Тело запроса

| Поле | Тип | Требуется | Описание |
| --- | --- | --- | --- |
| `accounts` | строка/массив | Да | Многострочная строка (разделенная символом новой строки) или массив строк; одна строка учетной записи в каждой строке, пустые строки игнорируются |
| `account_format` | строка | Нет | `client_id_refresh_token` (по умолчанию) или `refresh_token_client_id` |
| `group_id` | интервал | Нет | Идентификатор целевой группы, по умолчанию `1`; если группа не существует, верните 404 |
| `provider` | строка | Нет | Идентификатор поставщика электронной почты, по умолчанию `outlook`; неизвестные значения выводятся из адреса электронной почты, если они не выводятся, они обрабатываются как `custom` |
| `remark` | строка | Нет | Единые примечания для этой импортированной учетной записи (максимум 500 символов) |
| `tag_ids` | интервал [] | Нет | Список идентификаторов тегов, привязанных к учетным записям, импортированным в этот раз; идентификаторы тегов, которые не существуют, будут игнорироваться |
| `imap_host` | строка | Нет | Пользовательский адрес IMAP-сервера (требуется для `provider=custom`) |
| `imap_port` | интервал | нет | Порт IMAP, по умолчанию `993` |

#### Пример запроса

```bash
curl -X POST -H "X-API-Key: your-api-key" -H "Content-Type: application/json" \
  -d '{"accounts":"a@outlook.com----pwd1----3f2504e0-4f89-11d3-9a0c-0305e82c3301----token1\nb@outlook.com----pwd2----3f2504e0-4f89-11d3-9a0c-0305e82c3302----token2","group_id":2,"tag_ids":[5]}' \
  "http://localhost:5000/api/external/accounts"
```

#### Пример успешного ответа

```json
{
  "success": true,
  «сообщение»: «Успешно импортированы 2 аккаунта»,
  "added_count": 2,
  "skipped_count": 0,
  "invalid_count": 0,
  "tagged_count": 2
}
```

#### Инструкции по возврату

- `added_count` / `skipped_count` / `invalid_count` / `tagged_count`: Количество новых добавлений, повторный пропуск (почтовый ящик уже существует, исходная запись не перезаписывается), неверный формат, успешно привязанные теги
— Если в этот раз новая учетная запись не импортируется, возвращается HTTP 400 (`success: false`), а тело ответа также содержит все счетчики.
— Пароль, токен обновления и пароль IMAP шифруются и сохраняются, а ответ не отображается.
— 403 возвращается, если разрешение равно `readonly`, а сообщение об ошибке включает инструкции по переключению.
— Запишите журнал аудита (`action=import`) для каждого звонка.

### DELETE `/api/external/accounts/email/<email_addr>`

Чтобы удалить **официальную учетную запись электронной почты** по адресу электронной почты, требуется ключ API и разрешения на чтение и запись (`readwrite`).

#### Пример запроса

```bash
curl -X DELETE -H "X-API-Key: your-api-key" \
  "http://localhost:5000/api/external/accounts/email/user%40outlook.com"
```

#### Пример успешного ответа

```json
{
  "success": true,
  "message": "Аккаунт удален user@outlook.com",
  "deleted_email": "user@outlook.com"
}
```

#### Инструкции по возврату

— адрес электронной почты в пути рекомендуется закодировать в формате URL (`@` записывается как `%40`), также можно напрямую написать `@` или `+`.
— Сопоставление адресов электронной почты не чувствительно к регистру; при передаче псевдонима электронной почты основная учетная запись, которой он принадлежит, будет удалена.
— `deleted_email` возвращает канонический адрес электронной почты в библиотеке (может быть смешанный регистр или основной адрес электронной почты, не совсем совпадающий с запрошенным адресом)
— Если учетная запись не существует, будет возвращен HTTP 404.
— Удалите теги и псевдонимы, которые также очистят учетную запись, и пометьте записи, связанные с проектом, как `deleted` (сохранение истории проекта).
— Запишите журнал аудита (`action=delete`) для каждого звонка.

### POST `/api/external/accounts/batch-update-group`

Для пакетного изменения групп официальных учетных записей требуется ключ API и разрешения на чтение и запись (`readwrite`). Со стороны устройства удобно перемещать используемые учетные записи в такие группы, как «Использованные», для визуального различия.

#### Тело запроса

| Поле | Тип | Требуется | Описание |
| --- | --- | --- | --- |
| `account_ids` | интервал [] | Да | Список идентификаторов учетных записей; недопустимые значения (неположительные целые числа) будут автоматически фильтроваться |
| `group_id` | интервал | да | идентификатор целевой группы |

#### Пример запроса

```bash
curl -X POST -H "X-API-Key: your-api-key" -H "Content-Type: application/json" \
  -d '{"account_ids":[12,13],"group_id":3}' \
  "http://localhost:5000/api/external/accounts/batch-update-group"
```

#### Пример успешного ответа

```json
{
  "success": true,
  "message": "2 аккаунта перенесены в группу "Использованные",
  "updated_count": 2
}
```

#### Инструкции по возврату

— `account_ids` пуст или полностью недопустим и возвращает HTTP 400.
— целевая группа не существует и возвращает HTTP 404.
— невозможно перейти в системную группу (например, «временный почтовый ящик»), вернуть HTTP 400.
— `updated_count` — количество фактически сопоставленных и перемещенных учетных записей; если соответствующая учетная запись отсутствует, возвращается HTTP 400.
— Запишите журнал аудита (`action=update`) для каждого звонка.

### API внешнего проекта

Открытые возможности управления проектами для внешних систем: доступ к конечным точкам запросов (список проектов, сведения о проекте, пул почтовых ящиков проекта) можно получить с помощью ключа API с любым разрешением; конечным точкам сбора и возврата требуются разрешения на чтение и запись (`readwrite`).

Внешняя конечная точка проекта и веб-конец `/api/projects/*` используют один и тот же набор внутренней логики, и семантика абсолютно одинакова:

- Такие правила, как конечный автомат проекта (`toClaim` / `claiming` / `done` / `failed` / `removed` / `deleted`), автоматическая перезапуск времени ожидания аренды (по умолчанию 600 секунд, максимум 3600 секунд), независимый статус нескольких проектов в одном почтовом ящике, см. в главе [Управление проектами] (#Project Management).
— также применяются правила создания/завершения, диапазона группировки, объединения псевдонимов почтовых ящиков и компенсации за удаление для `start`.
- Также открыты конечные точки деактивации/восстановления проекта (`active` / `archived`) и удаления. Правила см. в разделе [Жизненный цикл проекта] (#projectlifecycle).
- Структура ответа отражает веб-сторону (упаковка `data`), а запрос списка дополнительно возвращает `total` на верхнем уровне.

#### GET `/api/external/projects`

Получите список проектов (включая количество каждого статуса). Структура ответа такая же, как у `GET /api/projects`, с дополнительным `total` сверху.

```bash
curl -H "X-API-Key: your-api-key" "http://localhost:5000/api/external/projects"
```

#### GET `/api/external/projects/<project_key>`

Получить подробную информацию об одном проекте; если проект не существует, будет возвращен HTTP 404.

#### GET `/api/external/projects/<project_key>/accounts`

Запросите пул почтовых ящиков проекта, структура ответа соответствует `GET /api/projects/<project_key>/accounts` (включая статистику `project` и детали `accounts`), с дополнительным `total` на верхнем уровне.

| Параметры | Тип | Требуется | Описание |
| --- | --- | --- | --- |
| `status` | строка | Нет | Фильтровать по статусу проекта, например `toClaim`, `claiming`, `done`, `failed`, `removed` |
| `group_id` | интервал | Нет | Фильтровать по текущей группе или группе источников проекта; эта группа и все подгруппы будут включены |
| `provider` | строка | Нет | Фильтровать по поставщику электронной почты |
| `keyword` | строка | Нет | Выполняйте нечеткий поиск по адресу электронной почты и заметкам |

```bash
curl -H "X-API-Key: your-api-key" \
  "http://localhost:5000/api/external/projects/gpt/accounts?status=toClaim"
```

Типичное использование: внешняя система использует `status=toClaim` для запроса незарегистрированного пула почтовых ящиков и `status=done` для запроса зарегистрированного пула почтовых ящиков с целью исключения зарегистрированных почтовых ящиков по каналам.

#### POST `/api/external/projects/start`

Чтобы создать проект или завершить работу над проектом, необходимы разрешения на чтение и запись. Тело запроса соответствует `POST /api/projects/start` (`project_key` обязателен, `name`/`description`/`group_ids`/`use_alias_email` необязателен).

```bash
curl -X POST -H "X-API-Key: your-api-key" -H "Content-Type: application/json" \
  -d '{"project_key":"gpt","name":"Регистрация GPT","group_ids":[1,2]}' \
  "http://localhost:5000/api/external/projects/start"
```

#### POST `/api/external/projects/<project_key>/claim-random`

Получите доступный адрес электронной почты от проекта, для которого требуются разрешения на чтение и запись. Тело запроса соответствует веб-стороне:

| Поле | Тип | Требуется | Описание |
| --- | --- | --- | --- |
| `caller_id` | строка | да | идентификатор вызывающего абонента |
| `task_id` | строка | Да | ID текущей задачи |
| `lease_seconds` | интервал | Нет | Секунды аренды, по умолчанию `600`, максимум `3600`; если об этом не сообщается по истечении таймаута, оно будет автоматически переработано в `toClaim` |

```bash
curl -X POST -H "X-API-Key: your-api-key" -H "Content-Type: application/json" \
  -d '{"caller_id":"worker-1","task_id":"task-001","lease_seconds":600}' \
  "http://localhost:5000/api/external/projects/gpt/claim-random"
```

Пример успешного ответа:

```json
{
  "success": true,
  "data": {
    "project_key": "gpt",
    "project_account_id": 101,
    "account_id": 12,
    "email": "user@example.com",
    "primary_email": "user@example.com",
    "group_id": 1,
    "provider": "outlook",
    "account_type": "outlook",
    "remark": "",
    "claim_token": "pclm_xxx",
    "claimed_at": "2026-04-15T10:00:00+00:00",
    "lease_expires_at": "2026-04-15T10:10:00+00:00"
  }
}
```

— Полученный почтовый ящик имеет статус `claiming` и содержит `claim_token`, который должен переноситься в последующих возвратах.
— HTTP 200 + `{"success": false, "error": "Нет электронного письма проекта для сбора"}` возвращается, когда в проекте нет письма для получения.
— Проект не существует и возвращает HTTP 404 (отличается от веб-стороны, что позволяет внешним скриптам отличать ошибки конфигурации от исчерпания пула).
— HTTP 400 возвращается, когда проект находится в деактивированном состоянии (`archived`) и появляется сообщение об ошибке «Проект деактивирован».

#### POST `/api/external/projects/<project_key>/complete-success`

Отметьте адрес электронной почты получателя как успешно зарегистрированный (`claiming` → `done`), для чего требуются разрешения на чтение и запись. Тело запроса соответствует веб-стороне:

| Поле | Тип | Требуется | Описание |
| --- | --- | --- | --- |
| `account_id` | интервал | Да | Получите идентификатор учетной записи в ответе |
| `claim_token` | строка | Да | Токен, возвращенный при получении |
| `caller_id` | строка | нет | идентификатор вызывающего абонента |
| `task_id` | строка | Нет | Идентификатор задачи |
| `detail` | строка | Нет | Описание успеха (максимум 500 символов) |

Адрес электронной почты в статусе `done` больше не будет выделяться этим проектом, то есть «данный адрес электронной почты зарегистрирован в этом канале».

#### POST `/api/external/projects/<project_key>/complete-failed`

Пометить собираемый почтовый ящик как неудавшийся при регистрации (`claiming` → `failed`), для чего требуются разрешения на чтение и запись. Тело запроса соответствует `complete-success`; `failed` больше не будет автоматически участвовать в распределении, и для сброса необходимо вызвать `reset-failed`.

#### POST `/api/external/projects/<project_key>/release`

Активно освободить собираемый почтовый ящик (`claiming` → `toClaim`), что подходит для таких сценариев, как прерывание задачи и активный отказ. Требуются разрешения на чтение и запись. Тело запроса соответствует `complete-success`.

#### POST `/api/external/projects/<project_key>/reset-failed`

Чтобы сбросить почтовый ящик `failed` обратно на `toClaim`, необходимы разрешения на чтение и запись. В теле запроса нужны только `account_id` (обязательно) и `detail` (необязательно).

#### POST `/api/external/projects/<project_key>/remove-account`

Переместите почтовый ящик проекта за пределы проекта (целевое состояние `removed`; будет отклонено в `claiming`), требуются разрешения на чтение и запись. В теле запроса требуется только `account_id` и, опционально, `detail`.

#### POST `/api/external/projects/<project_key>/restore-account`

Чтобы восстановить почтовый ящик проекта `removed` обратно в `toClaim`, необходимы разрешения на чтение и запись. В теле запроса требуется только `account_id` и, опционально, `detail`.

#### POST `/api/external/projects/<project_key>/archive`

Деактивируйте проект (`active` → `archived`), для которого требуются права на чтение и запись. После деактивации:

— `claim-random` возвращает HTTP 400 «Проект деактивирован».
- Конечные точки запроса и отчета проекта (`complete-success` / `complete-failed` / `release` и т. д.) по-прежнему можно использовать в обычном режиме для облегчения выполнения текущих задач.
- Повторный вызов `start` только завершит диапазон и не приведет к повторной активации проекта; восстановление требует явного вызова `restore`

```bash
curl -X POST -H "X-API-Key: your-api-key" \
  "http://localhost:5000/api/external/projects/gpt/archive"
```

#### POST `/api/external/projects/<project_key>/restore`

Восстановить деактивированные проекты (`archived` → `active`), требующие разрешения на чтение и запись. После восстановления `claim-random` доступен сразу, а статус каждого почтового ящика в проекте остаётся неизменным.

```bash
curl -X POST -H "X-API-Key: your-api-key" \
  "http://localhost:5000/api/external/projects/gpt/restore"
```

#### DELETE `/api/external/projects/<project_key>`

Для удаления проекта и ассоциации с его пулом почтовых ящиков требуются разрешения на чтение и запись.

```bash
curl -X DELETE -H "X-API-Key: your-api-key" \
  "http://localhost:5000/api/external/projects/gpt"
```

Удалить правила:

- Удалена связь между самим проектом и «Почтовым ящиком ↔ Проект» (включая историю событий проекта). Учетная запись в основной таблице `accounts` не будет удалена.
- Отказаться от удаления при наличии почтового ящика со статусом `claiming` (получающий), вернуть HTTP 400 и запросить количество; `complete-*` или `release` можно сначала удалить.
— Удаление необратимо; если тот же `project_key` будет использован для повторного использования `start` позже, новый проект будет создан и повторно введен в пул в соответствии с текущим диапазоном.
— Проект не существует, возвращает HTTP 404.
— Запишите журнал аудита (`action=delete`) для каждого звонка.

#### Примеры стыковки и распространенное поведение

Завершите процесс внешней стыковки:

```bash
# 1. Запустить/синхронизировать проект (создается при первом вызове)
curl -X POST -H "X-API-Key: your-api-key" -H "Content-Type: application/json" \
  -d '{"project_key":"gpt"}' "http://localhost:5000/api/external/projects/start"

# 2. Опрос незарегистрированного пула почтовых ящиков
curl -H "X-API-Key: your-api-key" \
  "http://localhost:5000/api/external/projects/gpt/accounts?status=toClaim"

# 3. Получите адрес электронной почты и выполните процесс регистрации.
CLAIM=$(curl -s -X POST -H "X-API-Key: your-api-key" -H "Content-Type: application/json" \
  -d '{"caller_id":"worker-1","task_id":"task-001"}' \
  "http://localhost:5000/api/external/projects/gpt/claim-random")

# 4. Сообщите о результатах после завершения регистрации.
curl -X POST -H "X-API-Key: your-api-key" -H "Content-Type: application/json" \
  -d "{\"account_id\":12,\"claim_token\":\"pclm_xxx\",\"caller_id\":\"worker-1\",\"detail\":\"Регистрация успешна\"}" \
  "http://localhost:5000/api/external/projects/gpt/complete-success"
```

Общее поведение:

— Конечная точка отчета возвращает HTTP 400 («Состояние учетной записи проекта не соответствует»), когда `account_id`/`claim_token` не соответствует текущей записи `claiming`; `account_id` возвращает HTTP 400 («account_id недействителен»), если он нецелочисленный.
— если разрешение `readonly`, вызов конечной точки чтения и записи возвращает HTTP 403, а сообщение об ошибке включает инструкции по переключению.
- Все операции чтения и записи записываются в журнал аудита (`action` — `start`/`claim`/`complete`/`release`/`reset`/`remove`/`restore`, `resource_type=project`). Поток состояния проекта также записывает события проекта для возможности отслеживания в Интернете.

### Управление учетной записью загрузки Outlook

Эти интерфейсы используются терминалом веб-управления для поддержки учетной записи автоматической авторизации Outlook в `outlook_upload_accounts`.

Ограничения безопасности:

— серверная часть сохраняет зашифрованный пароль электронной почты.
- Ответ списка возвращает обычный текст `password` в пакетном режиме, чтобы боковая таблица управления могла переключиться на отображение/скрытие.
— Новые/измененные ответы не возвращают обычный текст `password`.
— Внешний интерфейс использует `has_password`/`password_length`, чтобы определить, сохранен ли пароль, и использует `password` для переключения отображения в таблице.

#### GET `/api/outlook-upload-accounts`

Запросить учетную запись загрузки по страницам.

Параметры запроса:

| Параметры | Тип | Требуется | Описание |
| --- | --- | --- | --- |
| `page` | целое число | Нет | Номер страницы, по умолчанию `1` |
| `page_size` | целое число | Нет | Количество на странице, API по умолчанию `20`, максимум `1000`; терминал управления по умолчанию `20`, обеспечивает шестерни `10`, `20`, `50`, `100` |
| `keyword` | строка | Нет | Нечеткий поиск по электронной почте или заметкам |
| `auth_status` | строка | Нет | Статус авторизации: `all` (по умолчанию), `authorized`, `unauthorized`; неизвестные значения обрабатываются как `all` |

Когда `keyword` и `auth_status` вводятся одновременно, они фильтруются комбинацией И. `total` и `total_pages` в ответе рассчитываются по результатам комбинированной фильтрации.

Имя пользователя, пароль, путь и параметры запроса в URL-адресе будут удалены во время сериализации списка; `tags` взят из официального аккаунта с тем же адресом электронной почты в `account_tags`/`tags`. #### POST `/api/outlook-upload-accounts`

Добавьте одну учетную запись для загрузки. Тело запроса:

| Поле | Тип | Требуется | Описание |
| --- | --- | --- | --- |
| `email` | строка | Да | Адрес электронной почты, преобразуйте его в нижний регистр перед входом в базу данных и удалите начальные и конечные пробелы |

Дубликаты почтовых ящиков возвращают HTTP 400, и в ответе не будет отражен пароль. `password` Пропуск или передача пустой строки означает сохранение исходного пароля. Повторяющиеся электронные письма вернут HTTP 400, а если учетная запись не существует, будет возвращен HTTP 404.

## Управление группой

| Метод | Путь | Параметры | Описание |
| --- | --- | --- | --- |
| ПОЛУЧИТЬ | `/api/groups` | Нет | Получить все группы, вернуть `parent_id`, `level`, `account_count`, `descendant_account_count`, `sort_position` |
| ПОЛУЧИТЬ | `/api/groups/<group_id>` | Параметр пути `group_id` | Получить подробную информацию об одной группе |
| ПОСТ | `/api/groups` | JSON: `name`, `description?`, `color?`, `proxy_url?`, `sort_position?`, `parent_id?` | Создать группу |
| ПУТЬ | `/api/groups/<group_id>` | JSON: `name`, `description?`, `color?`, `proxy_url?`, `sort_position?`, `parent_id?` | Обновить группировку или переместить родительский элемент |
| УДАЛИТЬ | `/api/groups/<group_id>` | Параметр пути `group_id` | Удалить группу; если есть подгруппы, удалите каскадные подгруппы и переместите учетную запись обратно в группу по умолчанию |
| ПУТЬ | `/api/groups/reorder` | JSON: `group_ids: number[]`, `parent_id?` | Изменение порядка общих групп под одним родителем |

Пример запроса на создание или обновление группы:

```json
{
  «имя»: «Группа агентов»,
  «description»: «Отправляйтесь в Гонконг, агент»,
  "color": "#1a1a1a",
  "proxy_url": "http://127.0.0.1:7890",
  "sort_position": 2,
  "parent_id": null
}
```

Группировка поддерживает до трех уровней дерева:

- `parent_id=null` представляет группировку первого уровня; если указать группировку первого уровня в качестве родительской, будет создана группировка второго уровня, а если указать группировку второго уровня в качестве родительской, будет создана группировка третьего уровня.
- Подгруппы нельзя создавать в группах третьего уровня; временные группы почтовых ящиков нельзя использовать в качестве родительских групп или перемещать в другие группы.
- `sort_position` вступает в силу только под тем же `parent_id`, а `PUT /api/groups/reorder` только переупорядочивает `group_ids` того же родителя.
— `account_count` — количество прямых учетных записей текущей группы, а `descendant_account_count` — количество учетных записей текущей группы и всех дочерних групп.
– Удаление родительской группы приведет к удалению всех дочерних групп и перемещению обычных учетных записей электронной почты из удаленной группы в группу по умолчанию.

## Экспорт и вторичная проверка

Интерфейс экспорта сначала проверит пароль для входа один раз, а затем начнет экспорт после получения `verify_token`. `verify_token` в настоящее время является одноразовым токеном, действительным по умолчанию в течение 5 минут. При экспорте по группе будут включены учетные записи группы и всех подгрупп; когда родительско-дочерние группы передаются одновременно, учетные записи будут экспортированы только один раз.

| Метод | Путь | Параметры | Вернуться |
| --- | --- | --- | --- |
| ПОСТ | `/api/export/verify` | JSON: `password` | JSON, вернуть `verify_token` |
| ПОЛУЧИТЬ | `/api/groups/<group_id>/export` | Запрос: `verify_token` | `text/plain` скачать файл |
| ПОЛУЧИТЬ | `/api/accounts/export` | Запрос: `verify_token` | `text/plain` Загрузка файла |
| ПОСТ | `/api/accounts/export-selected` | JSON: `group_ids: number[]` или `account_ids: number[]`, `verify_token` | `text/plain` скачать файл |

Пример запроса двухэтапной проверки:

```json
{
  "password": "your-login-password"
}
```

Пример успешного ответа на второй этап проверки:

```json
{
  "success": true,
  "verify_token": "..."
}
```

| `tag_ids` | массив | Нет | Список идентификаторов тегов, которые будут привязаны к этой новой учетной записи |
| `proxy_url` | строка | Нет | На этот раз основной агент на уровне учетной записи, используемый всеми новыми учетными записями; оставьте это поле пустым, чтобы наследовать агент группы |
| `fallback_proxy_url_1` | строка | Нет | Резервный агент на уровне учетной записи, используемый на этот раз всеми новыми учетными записями 1 |
| `fallback_proxy_url_2` | строка | Нет | На этот раз резервный агент 2 на уровне учетной записи используется всеми вновь добавленными учетными записями |

#### Поля ключей ответа

| Поле | Описание |
| --- | --- |
| `added_count` | Количество новых аккаунтов на этот раз |
| `skipped_count` | Количество аккаунтов, пропущенных из-за дублирования или по другим причинам |
| `invalid_count` | Количество входных строк с неверным форматом |

### POST `/api/accounts/<account_id>/reauthorize`

Повторно авторизуйте существующую учетную запись Outlook OAuth. Этот интерфейс поддерживает только учетные записи Outlook и не поддерживает учетные записи IMAP.

Тело запроса:

| Поле | Тип | Требуется | Описание |
| --- | --- | --- | --- |
| `redirected_url` | строка | Да | Полный URL-адрес обратного вызова в адресной строке браузера после завершения авторизации Microsoft |

Интерфейс будет анализировать код авторизации от `redirected_url`, обменивать его на новый токен обновления от Microsoft, а затем только обновлять `client_id`, зашифрованные `refresh_token`, `refresh_token_updated_at` и обновлять поля статуса целевой учетной записи. Такие поля, как электронная почта, пароль, группа, статус, переадресация, прокси, примечания, псевдоним, метка и т. д. не будут изменены этим интерфейсом.

После успешного сохранения информации об авторизации интерфейс очистит старые ошибки обновления и немедленно запустит проверку обновления токена для одной учетной записи. `success` в ответе указывает, что данные авторизации сохранены; `validation.success` указывает, пройдена ли проверка автоматического обновления.

Пример запроса:

```json
{
  "redirected_url": "http://localhost:8080/?code=..."
}
```

Пример успешного ответа на обновление проверки:

```json
{
  "success": true,
  «сообщение»: «Повторная авторизация прошла успешно, проверка обновления токена пройдена»,
  "authorization_updated": true,
  "validation": {
    "success": true,
    "status": "success",
    "message": "Токен успешно обновлен",
    "authorization_type": "graph"
  }
}
```

Пример ответа на ошибку при обновлении проверки:

```json
{
  "success": true,
  «сообщение»: «Повторная авторизация сохранена, но проверка автоматического обновления не удалась»,
  "authorization_updated": true,
  "validation": {
    "success": false,
    "status": "failed",
    "error": {
      "code": "TOKEN_REFRESH_FAILED",
      «сообщение»: «Ошибка обновления токена»,
      "type": "RefreshTokenError",
      "status": 400
    },
    "error_message": "Не удалось обновить график: ..."
  }
}
```

Распространенные ошибки:

- `ACCOUNT_NOT_FOUND`: учетная запись не существует.
- `ACCOUNT_REAUTH_UNSUPPORTED`: учетная запись IMAP не поддерживает повторную авторизацию.
— `OAUTH_EXCHANGE_FAILED`: URL-адрес обратного вызова недействителен, или Microsoft не удалось обменять токен.
- `ACCOUNT_REAUTH_SAVE_FAILED`: не удалось сохранить новую информацию для авторизации.

### POST `/api/accounts/<account_id>/outlook-auto-auth`

Добавьте существующую официальную учетную запись Outlook в очередь автоматической авторизации Outlook. Этот интерфейс считывает адрес электронной почты и пароль официальной учетной записи с сервера, записывает их во временную таблицу `outlook_upload_accounts` и не возвращает простой текстовый пароль. Поддерживаются только учетные записи Outlook, учетные записи IMAP не поддерживаются.

Этот интерфейс не запускает задачу автоматической авторизации Graph немедленно; пользователю по-прежнему необходимо выполнить авторизацию во всплывающем окне автоматической авторизации Outlook. Временная запись, которая уже существует для того же почтового ящика, перезапишет пароль и вернет его в неавторизованное состояние.

Тело запроса: параметры не требуются.

Пример успешного ответа:

```json
{
  "success": true,
  "message": "Добавлена автоматическая авторизация",
  "upload_account_id": 42,
  "email": "user@outlook.com",
  "status": "added"
}
```

Значение `status`:

- `added`: добавлена временная запись.
- `updated`: перезапись существующих временных записей (перестановка в очередь)

Распространенные ошибки:

- `ACCOUNT_NOT_FOUND` (404): Учетная запись не существует.
- `ACCOUNT_AUTO_AUTH_UNSUPPORTED` (400): учетные записи IMAP не поддерживают присоединение к автоматической авторизации Outlook.
- `ACCOUNT_PASSWORD_MISSING` (400): пароль учетной записи пуст или не может быть расшифрован.
- `ACCOUNT_AUTO_AUTH_INVALID` (400): неверный адрес электронной почты или пароль.

> **Ограничение безопасности**: этот интерфейс не возвращает пароль в ответе. Пароль считывается только из зашифрованных данных, сохраненных на сервере, и записывается в зашифрованную промежуточную таблицу.

При добавлении автоматической авторизации `group_id`, теги и `proxy_url` официального аккаунта будут скопированы одновременно во временную таблицу для удобства использования при создании нового официального аккаунта в дальнейшем.

| `fallback_proxy_url_1` | строка | нет | резервный агент 1 |
| `fallback_proxy_url_2` | строка | нет | запасной агент 2 |

```json
{

```

| Поле | Описание |

## Управление проектами

Интерфейс проекта используется для управления «независимым статусом почтового ящика в рамках определенного проекта» с помощью `project_key`.

— Один и тот же почтовый ящик может существовать в нескольких проектах одновременно.
- Статусы внутри проекта поддерживаются независимо и не влияют друг на друга.
- Текущий статус проекта включает в себя:
  - `toClaim`: Можно собрать.
  - `claiming`: Получение
  — `done`: успешно использовано, больше не выделяется автоматически.
  - `failed`: последнее потребление не удалось, и его необходимо сбросить вручную, прежде чем его можно будет снова распределить.
  - `removed`: Ручной выход за рамки проекта.
  - `deleted`: учетная запись в главной таблице системы была удалена, но история проекта все еще сохраняется.

Информацию об активации/деактивации и удалении самого проекта см. в разделе [Жизненный цикл проекта] (#projectlifecycle).

Интерфейс управления проектами представлен в Интернете: после включения «Настройки → Общие настройки → Портал управления проектами» (по умолчанию отключено) в верхней навигации появляется портал «Управление проектами», который поддерживает создание проектов, просмотр каждого счетчика статусов, деактивацию/восстановление и удаление; возможности интерфейса полностью соответствуют данному разделу.

### Жизненный цикл проекта

В самом проекте есть поле `status` со значением `active` (по умолчанию) или `archived` (отключено):

- После деактивации `claim-random` отказывается получать (HTTP 400 «Проект деактивирован»). Когда пул исчерпан, это все равно HTTP 200. Их можно различить.
— деактивация не повлияет на операции запросов и отчетов. Почтовые ящики `claiming` в пути по-прежнему могут быть `complete-*` или `release`.
- `start` снова не будет повторно активировать деактивированный предмет, а только дополнит диапазон как обычно; для восстановления требуется вызов `restore`
— При удалении проекта будет удален сам проект, ассоциация пула почтовых ящиков (`project_accounts`), диапазон группировки и история событий проекта; учетная запись в основной таблице `accounts` не будет затронута
- При наличии почтового ящика со статусом `claiming` удаление будет отклонено. Сначала завершите его или отпустите и повторите попытку.
- Воссоздание `start` с тем же `project_key` после удаления создаст совершенно новый проект.

### POST `/api/projects/start`

Запустите проект.

Этот интерфейс сочетает в себе две семантики: «создать проект» и «полный объем проекта»:

- Если `project_key` не существует:
  - Создать новый проект
  — Сохранить объем проекта.
  — Добавьте в проект электронные письма в пределах диапазона.
- Если `project_key` уже существует:
  – Рассматривается как повторный запуск того же проекта.
  — использовать исходный диапазон по умолчанию.
  — Если на этот раз `group_ids` будет передан явно, диапазон будет обновлен, а затем заполнен.
  — Добавляйте только новые почтовые ящики, существующий статус проекта не будет сброшен.
  - Не меняет статус проекта `active`/`archived`; деактивированные проекты завершают диапазон, как обычно, но для восстановления требуется явный вызов `restore`.

Удалить правила компенсации:

- При запуске проекта будут проверяться потерянные аккаунты в истории проекта.
- Если учетная запись, соответствующая записи проекта, была удалена из основной таблицы `accounts`, запись проекта будет помечена как `deleted`.
- Если тот же адрес электронной почты позже будет повторно импортирован в систему, старая запись проекта будет повторно использоваться по адресу электронной почты при запуске проекта, а не рассматриваться как новый адрес электронной почты.

Правила псевдонимов почтовых ящиков:

- При `use_alias_email=false` проект заносится в пул по основному адресу электронной почты.
- При `use_alias_email=true` приоритет отдается входу в пул согласно псевдониму аккаунта и адресу электронной почты.
— Если для учетной записи не настроен псевдоним, она все равно будет использовать основной адрес электронной почты `use_alias_email=true`.
— При перезапуске существующего проекта, если `use_alias_email` не передан явно, будет использоваться текущая конфигурация проекта.

#### Тело запроса

| Поле | Тип | Требуется | Описание |
| --- | --- | --- | --- |
| `project_key` | строка | Да | Идентификатор проекта, он будет внутренне преобразован в нижний регистр, а начальные и конечные пробелы будут удалены |

| `description` | строка | Нет | Описание проекта |
| `group_ids` | массив<целое> | Нет | Список группировок по всему проекту; будет включать каждую группу и все учетные записи подгрупп; если не задано, при первом создании по умолчанию будет использован полный диапазон почтовых ящиков |

## Обновление и пересылка операций и обслуживания

### Обновление токена

| Метод | Путь | Параметры | Описание |
| --- | --- | --- | --- |
| ПОСТ | `/api/accounts/<account_id>/refresh` | Параметр пути `account_id` | Обновление одной учетной записи Outlook. Токен |
| ПОСТ | `/api/accounts/refresh-selected` | JSON: `account_ids: number[]` | Обновить выбранную учетную запись Outlook, автоматически пропустить IMAP или несуществующие учетные записи |
| ПОСТ | `/api/accounts/refresh-selected-stream` | JSON: `account_ids: number[]` | Инициализируйте выбранную задачу обновления потоковой передачи учетной записи, верните `task_id` и `stream_url` |
| ПОЛУЧИТЬ | `/api/accounts/refresh-selected-stream/<task_id>` | Параметр пути `task_id` | Подпишитесь на выбранную задачу обновления потоковой передачи учетной записи и верните `text/event-stream` |
| ПОЛУЧИТЬ | `/api/accounts/refresh-all` | Нет | Обновите все учетные записи Outlook и верните `text/event-stream` |
| ПОСТ | `/api/accounts/<account_id>/retry-refresh` | Параметр пути `account_id` | Повторите одно неудачное обновление учетной записи |
| ПОЛУЧИТЬ | `/api/accounts/refresh-failed-stream` | Нет | Потоковая передача повторит попытку текущей неудачной учетной записи и вернет `text/event-stream` |
| ПОСТ | `/api/accounts/refresh-failed` | Нет | Повторите попытку использования последней учетной записи, которую не удалось обновить |
| ПОЛУЧИТЬ | `/api/accounts/trigger-scheduled-refresh` | Запрос: `force=true/false` | Вручную активируйте логику «запланированного обновления» и верните `text/event-stream` |
| ПОСТ | `/api/accounts/stop-full-refresh` | Нет | Запрос на остановку текущей задачи полного обновления |

`token_rotated` и `message` возвращаются при успешном обновлении и повторной попытке отдельного аккаунта: `token_rotated` становится `true` только тогда, когда новый токен обновления отличается от старого значения и успешно записывается в базу данных, при этом копирайтинг имеет вид «Обновление успешно, токен обновлен»; когда новое значение не возвращается или возвращается старое значение, это `false`, а копирайтинг - «Проверка успешна, токен не ротируется, продолжайте использовать исходный токен». Успешное получение нового значения, но неудачное сохранение приведет к ошибке обновления.

`/api/accounts/refresh-all`, `/api/accounts/refresh-failed-stream`, `/api/accounts/refresh-selected-stream/<task_id>` и `/api/accounts/trigger-scheduled-refresh` будут возвращать потоки событий SSE. Общие типы событий включают в себя:

- `start`
- `progress`
- `account_result`: содержит одну учетную запись `status`, `message` и `token_rotated`.
- `delay`
- `complete`

Чтобы выбрать обновление потоковой передачи учетной записи, вам необходимо сначала инициализировать задачу:

```json
{
  "account_ids": [1, 2, 3]
}
```

`POST /api/accounts/refresh-selected-stream` Возврат в случае успеха:

```json
{
  "success": true,
  "task_id": "task-token",
  "stream_url": "/api/accounts/refresh-selected-stream/task-token"
}
```

`EventSource` затем используется для подписки на `stream_url`. В этой задаче используется краткосрочное сохранение состояния в процессе, а при развертывании службы необходимо поддерживать одного работника; если задача не существует или срок ее действия истек, SSE вернет событие `type=error`.

`POST /api/accounts/stop-full-refresh` Возврат в случае успеха:

```json
{
  "success": true,
  «message»: «Запрошено остановить текущую задачу полного обновления»
}
```

Если в данный момент не выполняется задача полного обновления, будет возвращен HTTP `409`:

```json
{
  "success": false,
  «message»: «В настоящее время задача полного обновления не выполняется»
}
```

Пример запроса `POST /api/accounts/refresh-selected`:

```json
{
  "account_ids": [1, 2, 3]
}
```

Этот интерфейс вернет:

- `requested_count`
- `processed_count`
- `success_count`
— `rotated_count`: количество успешных аккаунтов и ротации токена.
— `unrotated_count`: количество успешных аккаунтов, но токен не был ротирован.
- `failed_count`
- `skipped_count`
- `failed_list`
- `skipped_list`

### Обновление журналов и статистики.

| Метод | Путь | Параметры | Описание |
| --- | --- | --- | --- |
| ПОЛУЧИТЬ | `/api/accounts/refresh-logs` | Запрос: `limit`, `offset` | Получить все журналы обновления |
| ПОЛУЧИТЬ | `/api/accounts/<account_id>/refresh-logs` | Запрос: `limit`, `offset` | Получите единый журнал обновления учетной записи |
| ПОЛУЧИТЬ | `/api/accounts/refresh-logs/failed` | Нет | Получить снимок текущего состояния почтового ящика |
| ПОЛУЧИТЬ | `/api/accounts/refresh-stats` | Нет | Получить текущий снимок статистики обновления |
| ПОЛУЧИТЬ | `/api/accounts/refresh-status-list` | Запрос: `q`, `status`, `page`, `page_size` | Получить токен Обновить список адресов электронной почты руководства |

`GET /api/accounts/refresh-logs/failed` возвращает «снимок почтового ящика, который все еще находится в состоянии сбоя» и больше не является списком исторических журналов сбоев.

Глобальные и отдельные журналы обновления учетной записи включают `token_rotated` (`true` / `false` / `null`) и соответствующий `message`. Результат ротации старого журнала — `null`, что означает, что он не записывается и его нельзя считать неротированным. Список управления обновлением возвращает последний результат через `last_refresh_token_rotated` и отображает три независимых времени: `last_refresh_at` представляет самый последний запрос, `last_refresh_success_at` представляет самое последнее успешное обновление (даже если оно не чередуется, оно считается успешным), а `refresh_token_updated_at` представляет самое последнее обновление токена. Сбой не распространяется на время успеха, а отсутствие ротации не распространяется на время обновления токена; неизвестное время возвращает `null`, а интерфейс отображает `-`.

Ответ на обновление одной учетной записи и `account_result` SSE возвращают три времени базы данных одновременно. При первом переносе старой учетной записи подтверждаемое время успеха будет восстановлено из журнала успехов и последнего статуса успеха, а незаписанные значения останутся пустыми.

Параметры запроса `GET /api/accounts/refresh-status-list`:

- `q`
- `status=all|success|failed|never`
- `page`: минимум `1`.
— `page_size`: минимум — `1`, максимум — `10000`.

## Интерфейс электронной почты

### GET `/api/emails/<email_addr>`

Интерфейс внутреннего списка рассылки. Поддерживает основной почтовый ящик или псевдоним почтового ящика; если почтовый ящик содержит `+`, сначала он будет сопоставлен по полному адресу. Если попадания нет, `+suffix` будет удален шаг за шагом справа налево в соответствии с локальной частью. Резервное сопоставление совместимо с основным почтовым ящиком и псевдонимом почтового ящика. Если доменное имя — `gmail.com` или `googlemail.com`, оно будет продолжать использовать другой суффикс после того, как ни один из исходных кандидатов на суффикс не будет сопоставлен.

#### Параметры запроса

| Параметры | Тип | Требуется | Описание |
| --- | --- | --- | --- |
| `folder` | строка | Нет | `inbox`, `junkemail`, `deleteditems`, `all` |
| `skip` | интервал | Нет | Смещение пейджинга, по умолчанию `0`; нецифровые числа используют значение по умолчанию, отрицательные числа обрабатываются как `0` |
| `top` | интервал | Нет | Возвращает количество, по умолчанию — `20`; нецифровые числа используют значение по умолчанию, а отрицательные числа обрабатываются как `0`. Максимальное удаленное чтение — `50`, а локальное чтение сохраняется без дополнительного усечения |
| `source` | строка | Нет | При передаче `local` читайте только локальный список хранения обычного почтового ящика; Требуется `normal_mail_local_retention_enabled=true` |
| `local_only` | бул | нет | `1` / `true` / `yes` / `on` эквивалентны `source=local` |
| `subject_contains` | строка | Нет | Сохраняйте в теме только те электронные письма, которые содержат это ключевое слово, а при чтении используйте символы `+` |
| `from_contains` | строка | Нет | Сохраняйте электронные письма, содержащие это ключевое слово, только у отправителя и сохраняйте символы `+` при чтении |
| `keyword` | строка | Нет | Выполните дальнейшую фильтрацию ключевых слов в теме, предварительном просмотре и тексте и сохраните символы `+` при чтении |

При использовании `folder=all` поведение соответствует внешнему API: захват `inbox` и `junkemail` одновременно, объединение и сортировка по времени.

Успешный ответ дополнительно будет содержать `requested_email`, `resolved_email`; когда почтовый ящик запроса достигает псевдонима, он также будет содержать `matched_alias`. Если вы используете Gmail/Googlemail или резервные обращения с дополнительным адресом, также включаются поля `resolved_query_email`, `fallback_used`, `fallback_email` и т. д.

#### Поле элемента списка

Каждый объект в массиве `emails` содержит как минимум следующие поля:

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | строка | Идентификатор электронной почты |
| `subject` | строка | Тема письма |
| `from` | строка | Адрес отправителя |
| `to` | строка | Адрес получателя, несколько адресов объединены с помощью `, ` |
| `date` | строка | Время получения |
| `is_read` | бул | Было ли это прочитано |
| `has_attachments` | бул | Есть ли вложения |
| `body_preview` | строка | Предварительный просмотр электронной почты |
| `folder` | строка | Папка |
| `id_mode` | строка | Режим идентификатора сообщения: график — `graph`, стандартный IMAP и OAuth IMAP — `uid`; последующие операции должны возвращать исходное |

Идентификаторы сообщений IMAP представляют собой непрозрачные строки. Когда сервер предоставляет UIDVALIDITY, формат `imap:<UIDVALIDITY>:<UID>`, а генерация почтового ящика и UID привязываются одновременно; старый голый UID все еще может использоваться UID. Пожалуйста, всегда возвращайте `id` и `id_mode` в список как есть, не преобразуйте их в числа и не анализируйте их самостоятельно, а затем отбрасывайте UIDVALIDITY. `sequence` используется только для пейджинга внутрисерверного соединения, и старая запись порядкового номера должна быть повторно синхронизирована; изменение его на `uid` может указывать на другой адрес электронной почты.

### POST `/api/emails/delete`

Удалять электронные письма пакетами (безвозвратное удаление).

#### Тело запроса

```json
{
  "email": "user@outlook.com",
  "method": "graph",
  "folder": "inbox",
  "items": [
    {
      "id": "AAMk...",
      "folder": "inbox",
      "id_mode": "graph"
    }
  ]
}
```

Совместимо со старыми форматами:

```json
{
  "email": "user@outlook.com",
  "ids": ["AAMk...", "AAMk..."]
}
```

Описание:

- Рекомендуется передавать `items` (включая `id`/`folder`/`id_mode`) и `method`, в соответствии с `/api/emails/mark-read`.
— Учетные записи Outlook разделены по `id_mode`/`method`: `graph` использует Graph API, `uid` использует OAuth IMAP; старая операция `sequence` будет отклонена и список необходимо будет получить заново
— Стандартная учетная запись IMAP навсегда удалена через IMAP `STORE \\Deleted` + `EXPUNGE`.
— Старые клиенты, прошедшие только проверку `ids`, по-прежнему принимаются; в настоящее время по умолчанию используется обработка графов.

### Управление каналами Cloudflare

Cloudflare Temp Email поддерживает многоканальную конфигурацию. Каждый канал содержит `name`, `worker_domain`, `email_domains`, `admin_password`, `enabled`, `is_default`. `email_domains` является необязательным. Если оставить это поле пустым, канал все равно можно сохранить, но имя домена не может быть выбрано автоматически при создании электронного письма; пароль администратора передается только при сохранении; в ответе списка возвращается только `admin_password_configured`.

Создание каналов:

```http
POST /api/cloudflare/channels
```

```json
{
  "name": "cfmail-us",
  "worker_domain": "cfmail-us.example.workers.dev",
  "email_domains": "mail-us.example.com, alt-us.example.com",
  "admin_password": "ADMIN_PASSWORD",
  "enabled": true,
  "is_default": true
}
```

При обновлении существующих каналов `admin_password` можно оставить пустым, что указывает на сохранение исходного пароля; `email_domains` также можно оставить пустым, и интерфейс запроса доменного имени вернет успешный ответ и пустой список. Перед удалением канала система проверит, существует ли еще временный почтовый ящик Cloudflare, ссылающийся на канал; указанный канал нельзя удалить, и его можно сначала деактивировать.

### GET `/api/cloudflare/messages`

Просмотреть все электронные письма указанного работника канала Cloudflare; используйте канал Cloudflare по умолчанию, если `channel_id` не передается. Этот интерфейс требует сеанса входа в Интернет и не использует внешний ключ API; он отличается от `folder=all` обычной учетной записи электронной почты, которая объединяет только входящие сообщения и спам обычной учетной записи электронной почты. Этот интерфейс не предоставляет агрегированные представления по каналам Cloudflare.

### GET `/api/skins`

Получите список скинов внешнего вида на уровне системы, текущие значения конфигурации и действующие на данный момент скины. Этот интерфейс требует, чтобы вы вошли в систему.

Пример успешного ответа:

```json
{
  "success": true,
  "configured_skin_id": "midnight-sample",
  "active_skin_id": "midnight-sample",
  "asset_hash": "a1b2c3d4e5f6a7b8",
  "active_skin": {
    "id": "midnight-sample",
    "name": "Midnight Sample",
    "version": "1.0.0",
    "source_type": "upload",
    "builtin": false,
    "active": true,
    "status": "ok",
    "asset_hash": "a1b2c3d4e5f6a7b8",
    "last_error": ""
  },
  "skins": []
}
```

Описание поля:

| Поле | Описание |
| --- | --- |
| `configured_skin_id` | Идентификатор скина сохранен в таблице `settings` |
| `active_skin_id` | Действующий на данный момент идентификатор скина; когда конфигурация недоступна, она возвращается к `classic` |
| `asset_hash` | Текущая версия CSS скина, может использоваться как параметр `/assets/active-skin.css?v=...` |
| `skins` | Список установленных скинов, всегда содержит встроенный `classic` |

Общие поля объектов скина:

| Поле | Описание |
| --- | --- |
| `id` | Идентификатор скина |
| `name` | Отображаемое имя |
| `version` | Версия |
| `description` | Описание |
| `source_type` | `builtin`, `upload` или `git` |
| `builtin` | Есть ли встроенный скин |
| `active` | Действует ли он в настоящее время |
| `status` | `ok` или `invalid` |
| `last_error` | Последняя ошибка проверки или чтения |
| `git_url` | Адрес источника Git, возвращается только исходный скин Git |
| `git_ref` | Git ref, возвращается только исходный скин Git |

### POST `/api/skins/<skin_id>/activate`

Включить указанный скин. Этот параметр является параметром системного уровня. После сохранения все устройства, вошедшие в систему, будут использовать один и тот же текущий скин.

Пример успешного ответа:

```json
{
  "success": true,
  «сообщение»: «Скин включен»,
  "active_skin": {
    "id": "classic",
    "source_type": "builtin",
    "active": false,
    "status": "ok"
  },
  "asset_hash": "classic"
}
```

Распространенные ошибки при сбое:

- `Неверный идентификатор скина`
- `Скин не существует`
- `Скин недоступен`

Вы также можете отправить `active_skin_id` через `PUT /api/settings`, чтобы добиться того же эффекта.

### POST `/api/skins/upload`

Загрузите zip-архив скина. Имя поля формы поддерживает `skin` или `file`.

Пример запроса:

```bash
curl -X POST \
  -H "X-CSRFToken: <csrf-token>" \
  -b "session=<session-cookie>" \
  -F "skin=@skin.zip" \
  "http://localhost:5000/api/skins/upload"
```

Пример успешного ответа:

```json
{
  "success": true,
  «сообщение»: «Скин установлен»,
  "skin": {
    "id": "midnight-sample",
    "name": "Midnight Sample",
    "version": "1.0.0",
    "source_type": "upload",
    "status": "ok"
  }
}
```

Требования к формату см. в [`docs/skins.md`](skins.md). Невозможность загрузки не приведет к изменению текущего активированного скина.

### POST `/api/skins/git/install`

Установите скин из репозитория Git. Корневой каталог хранилища должен содержать файлы записей `skin.json` и CSS.

Пример запроса:

```json
{
  "git_url": "https://github.com/user/outlook-skin.git",
  "git_ref": "main"
}
```

Описание:

- Требуется `git_url`.
- `git_ref` Необязательно, может быть ветвью, тегом или другой разрешимой ссылкой `git clone --branch`.
- `git` должен быть установлен в операционной среде.
- Специального входа для управления частным складом не существует. Не рекомендуется записывать учетные данные непосредственно в URL-адрес, видимый многим людям.

Успешный ответ соответствует интерфейсу загрузки. Если установка не будет выполнена, текущий активированный скин не изменится.

### POST `/api/skins/<skin_id>/git/update`

Обновите установленный исходный скин Git. Сервер будет использовать `git_url` и `git_ref`, сохраненные в скине, чтобы снова получить его, и потребует, чтобы обновленный `skin.json.id` соответствовал исходному идентификатору скина.

Пример успешного ответа:

```json
{
  "success": true,
  «message»: «Скин Git обновлен»,
  "skin": {
    "id": "midnight-sample",
    "source_type": "git",
    "status": "ok"
  }
}
```

Существующие файлы скинов не будут перезаписаны при сбое обновления.

### DELETE `/api/skins/<skin_id>`

Удалить неактивные пользовательские скины. Встроенный `classic` не может быть удален, как и текущий активный скин не может быть удален напрямую; сначала вам нужно переключиться на другие скины или `classic`.

Пример успешного ответа:

```json
{
  "success": true,
  «сообщение»: «Скин был удален»
}
```

### GET `/assets/active-skin.css`

Возвращает CSS действующего в данный момент скина. Этот ресурс используется для загрузки страниц и не требует сеанса; возвращает пустой классический резервный CSS, если конфигурация недоступна или не удается прочитать CSS.

Клиент может использовать `asset_hash`/`active_skin_asset_hash`, возвращаемые `GET /api/skins` или `GET /api/settings`, в качестве параметров запроса для обновления кеша:

```txt
/assets/active-skin.css?v=<asset_hash>
```

### GET `/api/settings/normal-mail-retention/status`

Получите локальную статистику хранения и состояние задач очистки обычных почтовых ящиков.

#### Пример успешного ответа

```json
{
  "success": true,
  "status": {
    "enabled": true,
    "saved_message_count": 128,
    "cached_body_count": 42,
    "estimated_retained_bytes": 1048576,
    "db_file_bytes": 5242880,
    "clear_status": {
      "state": "idle",
      "message": ""
    }
  }
}
```

`clear_status.state` может быть `idle`, `running`, `succeeded` или `failed`. Для отображения интерфейса и принятия решений по очистке используются статистические значения, а не точные квоты.

### POST `/api/settings/normal-mail-retention/clear`

Запустите задачу фоновой очистки, чтобы удалить локальные сохраненные данные обычного почтового ящика в `retained_normal_mail_messages`. Этот интерфейс не будет автоматически отключать `normal_mail_local_retention_enabled`; Выключение осуществляется независимо `PUT /api/settings`.

Задачи очистки находятся в состоянии «в процессе»: повторные запросы не запускают второй поток удаления, а вместо этого возвращают текущее состояние `running` с помощью `already_running=true`. Когда фоновое удаление сталкивается с кратковременным SQLite `database is locked`, оно повторяется ограниченным образом; окончательный результат опрашивается через интерфейс состояния.

#### Пример успешного ответа

```json
{
  "success": true,
  "already_running": false,
  "status": {
    "state": "running",
    «message»: «Очистка локального кэша хранения обычных почтовых ящиков»
  }
}
```

## Описание

### Использование прокси

API, связанный с почтовым ящиком учетной записи, в настоящее время отдает приоритет конфигурации прокси-сервера на уровне учетной записи; только если учетные записи `proxy_url`, `fallback_proxy_url_1` и `fallback_proxy_url_2` пусты, конфигурация прокси-сервера группы, к которой принадлежит учетная запись, будет унаследована. Если в текущей группе не настроен прокси-сервер, она продолжит поиск прокси-сервера родительской группы вверх, пока не найдет группу-предка с конфигурацией прокси-сервера или не достигнет группы первого уровня:

— Получение токена графа
- Список рассылки Graph
– Подробная информация о графике по электронной почте.
— Получение токена Outlook OAuth IMAP.
– Список OAuth IMAP Outlook/Подробности/Удалить
- Список паролей IMAP/Сведения/Удалить
— Прямой опрос для сбора сообщений/деталей.

### Правила конфликта псевдонимов

Псевдоним будет проверен при сохранении:

– не может совпадать с основным адресом электронной почты этой учетной записи.
– Не может совпадать с основным адресом электронной почты других учетных записей.
– Невозможно дублировать другие псевдонимы учетной записи.
- Не может конфликтовать с временным адресом электронной почты.

### Специальный тип ответа

Следующие интерфейсы не являются обычными интерфейсами данных JSON:

- `GET /api/accounts/refresh-all`: `text/event-stream`
- `GET /api/accounts/refresh-failed-stream`: `text/event-stream`
- `GET /api/accounts/trigger-scheduled-refresh`: `text/event-stream`
- `GET /api/groups/<group_id>/export`: загрузка файла `text/plain`
- `GET /api/accounts/export`: загрузка файла `text/plain`
- `POST /api/accounts/export-selected`: загрузка файла `text/plain`
