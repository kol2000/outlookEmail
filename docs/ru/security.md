# 🔐 Конфигурация безопасности

## 1. Измените пароль по умолчанию.

** Способ 1: передать переменные среды (только инициализация) ** во время первого развертывания.

В `docker-compose.yml`:
```yaml
environment:
  - LOGIN_PASSWORD=your_secure_password_here
  - SECRET_KEY=your-random-secret-key-here
```

`LOGIN_PASSWORD` задаёт начальный хеш пароля, только если в базе **ещё нет** `settings.login_password`. После инициализации изменение этой переменной окружения **не меняет** текущий пароль входа.

**Метод 2: Изменение через веб-интерфейс (необходимо знать текущий пароль) **

После входа в систему нажмите кнопку «⚙️ Настройки», чтобы изменить пароль для входа онлайн. Текущий пароль должен быть введен при изменении; после успеха текущий сеанс останется в системе, а другие вошедшие в систему устройства/сеансы должны будут войти в систему снова.

**Метод 3: сброс через официальный интерфейс командной строки, если вы забудете свой пароль (старый пароль не требуется) **

Если у вас есть доступ к хосту или каталогу данных, вы можете запустить:

```bash
python scripts/reset_login_password.py
# Docker: docker exec -it <container> python scripts/reset_login_password.py
```

- Поддерживается только интерактивный ввод новых паролей через терминал (без `--password`/конвейерной передачи)
- Запись хешей bcrypt и ротация версий сеансов входа в систему, аннулирование существующих сеансов.
- Относится к операциям эксплуатации и обслуживания на границе доверия **host **, которая дополняет операцию «Выполнен вход в систему, чтобы изменить пароль, и текущий пароль должен быть проверен».
- Подробные инструкции см. в разделе [troubleshooting.md](troubleshooting.md) «Забыли пароль для входа в Интернет».

### Срок действия сеанса входа в систему

На веб-странице входа предусмотрены фиксированные варианты срока действия входа: 7 дней, 30 дней, 90 дней, 180 дней и навсегда, значение по умолчанию — 30 дней. Ограниченный период фиксирован и рассчитывается с момента успешного входа в систему и не продлевается при последующих посещениях страниц или вызовах API; он действителен постоянно и не истекает автоматически из-за времени входа в систему. Срок действия всех сеансов по-прежнему истекает после активного выхода из системы, смены версии сеанса из-за изменения пароля для входа, изменения SECRET_KEY или очистки файлов cookie браузера.

Страница входа запоминает только последний выбранный период локально в текущем браузере и не сохраняет пароли, файлы cookie сеанса или абсолютное время истечения срока действия. Сервер по-прежнему будет проверять опцию истечения срока действия, и прямой вызов интерфейса входа в систему не может обойти фиксированную опцию; для входа в расширение браузера нет срока действия, и по умолчанию устанавливается 30-дневный сеанс.

## 2. Включить защиту CSRF (рекомендуется)

Защита CSRF включена по умолчанию. Если flask-wtf не установлен, система будет плавно деградировать:

```bash
pip install flask-wtf>=1.2.0
```

Характеристики защиты **CSRF: **
- Автоматически добавлять токен CSRF для всех операций изменения статуса.
- Предотвращение атак с подделкой межсайтовых запросов.
- Полностью прозрачно для пользователей, ручные операции не требуются.
- Автоматическое понижение версии, если она не установлена, что не влияет на использование функций.

## 3. Ограничение скорости входа в систему

В системе имеется встроенное ограничение скорости входа в систему для предотвращения взлома методом грубой силы:

- Предел сбоев ** **: блокируется после 5 сбоев.
- Продолжительность блокировки ** **: 15 минут.
- ** на основе IP**: каждый IP считается независимо.
- ** автоматически разблокируется. **: автоматически разблокируется по истечении времени блокировки.

## 4. Шифрование конфиденциальных данных

Все конфиденциальные данные хранятся в зашифрованном виде:

Зашифрованный контент **: **.
- Токен обновления (симметричное шифрование Fernet)
- Пароль для входа (хеш bcrypt)
- Пароль электронной почты (симметричное шифрование Fernet)
- Пароль электронной почты во внешней временной таблице загрузки (симметричное шифрование Fernet; интерфейс списка и внешний интерфейс не возвращают и не отображают простой текст)
- Внешний ключ API (симметричное шифрование Fernet)

Ключ шифрования **: **
- Получение ключей шифрования на основе SECRET_KEY.
- Использование функции получения ключа PBKDF2HMAC.
- 100 000 итераций, алгоритм SHA256.

** ВАЖНОЕ ПРИМЕЧАНИЕ: **
- SECRET_KEY должен оставаться неизменным.
- SECRET_KEY будет автоматически сгенерирован и сохранен при первом запуске Windows `exe`.
- Docker, среда выполнения Python и производственная среда должны явно устанавливать фиксированный SECRET_KEY.
- Изменение SECRET_KEY приводит к невозможности расшифровки сохраненных данных.
- Если вам нужно внести изменения, сначала экспортируйте учетную запись, а затем повторно импортируйте ее после внесения изменений.

## 5. Вторичная проверка функции экспорта

Функция экспорта требует подтверждения пароля для предотвращения несанкционированного экспорта:

Механизм защиты **: **
- Перед экспортом необходимо ввести пароль для входа.
- Токен одноразового подтверждения, срок его действия истекает сразу после использования.
- Все экспортные операции записываются в журналы аудита.
- Запись времени работы, IP-адреса и деталей экспорта.

Журнал аудита **: **
```sql
SELECT * FROM audit_logs WHERE action = 'export' ORDER BY created_at DESC;
```

## 5.1 Вторая проверка отображения учетной записи и пароля

Интерфейс сведений об учетной записи по умолчанию не возвращает открытый текст пароля учетной записи и пароля IMAP, а только возвращает флаг, указывающий, был ли сохранен пароль. При нажатии «Отображение проверки» в веб-интерфейсе вам необходимо еще раз ввести текущий пароль для входа; пароль учетной записи будет получен и отображен только после прохождения проверки.

Механизм защиты **: **
- Перед просмотром пароля учетной записи необходимо ввести пароль для входа.
- Сохранение учетной записи без проверки не приведет к удалению сохраненных паролей.
- Успешная проверка пароля учетной записи приведет к записи журнала аудита.
- В журнале аудита записывается только информация об учетной записи и операциях, но не содержимое пароля.

## 6. Защита от XSS

Многоуровневый механизм защиты от XSS:

** Внешняя защита: **
- Автоматическое экранирование пользовательского ввода (escapeHtml).
- Содержимое электронной почты очищается с помощью DOMPurify.
- изоляция песочницы iframe (sandbox="allow-same-origin")

** внутренняя защита: **
- Функция очистки ввода (sanitize_input)
- Экранирование специальных символов HTML
- Ограничение длины и фильтрация управляющих символов

Конфигурация **DOMPurify: **
```javascript
DOMPurify.sanitize(content, {
    ALLOWED_TAGS: ['a', 'b', 'i', 'u', 'strong', 'em', 'p', 'br', 'div', ...],
    FORBID_TAGS: ['script', 'style', 'iframe', 'object', 'embed', ...],
    FORBID_ATTR: ['onerror', 'onload', 'onclick', ...]
});
```

## 6.1 Пользовательская граница безопасности кожи

Внешний вид скина загружает только CSS и не выполняет сценарии или команды установки в пакете скина. При загрузке пакета обложки zip сервер отклоняет обход пути, символические ссылки, файлы сценариев, файлы HTML и исполняемые файлы; Установка исходного кода Git также будет проверена на соответствие тому же набору форматов скинов.

Все равно необходимо обработать в соответствии с функцией доверенного администратора:

- CSS может изменить внешний вид интерфейса, скрыть элементы или загрузить удаленные ресурсы.
- Источник Git позволит серверу активно получать доступ к адресу склада, указанному пользователем.
- Не рекомендуется открывать возможность загрузки скинов или установки Git обычным пользователям.
- При развертывании несколькими пользователями рекомендуется ограничить доступ к источникам через брандмауэр, обратный прокси-сервер или страницу настроек доверенной сети.

## 7. Настройте брандмауэр

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 5000/tcp
sudo ufw enable
```

## 8. Ограничить источники доступа (Nginx)

```nginx
location / {
    allow 192.168.1.0/24;
    deny all;
    proxy_pass http://localhost:5000;
}
```

## 9. Используйте надежные пароли

- Пароль для входа должен содержать не менее 8 символов, включая прописные и строчные буквы, цифры и специальные символы.
- **SECRET_KEY должен использовать случайно сгенерированную длинную строку (не менее 32 байтов) **.
- Метод генерации: `python -c 'import secrets; print(secrets.token_hex(32))'`
- Регулярно меняйте пароль.

## 10. Резервное копирование данных

```bash
# Резервная база данных
cp data/outlook_accounts.db data/outlook_accounts.db.backup

# Регулярное резервное копирование (crontab)
0 2 * * * cp /path/to/data/outlook_accounts.db /path/to/backup/outlook_accounts.db.$(date +\%Y\%m\%d)
```

## Лучшие практики обеспечения безопасности

1. ** исправлено SECRET_KEY**: развертывание сервера должно быть задано явно, версия для настольных компьютеров должна сохранять автоматически сгенерированный файл ключа.
2. ** включает HTTPS**: производственная среда использует шифрование SSL/TLS.
3. ** регулярно обновляет **: своевременно обновляется до последней версии.
4. Журнал мониторинга ** **: регулярно проверяйте журналы аудита и журналы приложений.
5. ** ограничивает доступ к **: используйте брандмауэр и Nginx, чтобы ограничить источники доступа.
6. ** резервное копирование данных **: регулярно создавайте резервные копии файлов базы данных.
7. ** Политика надежных паролей **: используйте сложные пароли и регулярно меняйте их.
8. Установка ** CSRF-защита **: `pip install flask-wtf`
