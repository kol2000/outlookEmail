# Руководство по обновлению

Этот документ предназначен для пользователей, которые уже используют этот проект, и объясняет шаги обновления, предложения по резервному копированию и идеи отката после выпуска новой версии.

## Рекомендации перед обновлением

Перед обновлением рекомендуется выполнить следующие операции:

1. Создайте резервную копию каталога `data/`, по крайней мере, сохраните файлы базы данных.
2. Запишите используемые в данный момент теги образа, методы развертывания и ключевые переменные среды.
3. Подтвердите, что текущий `SECRET_KEY` будет по-прежнему сохраняться и не будет заменен во время обновления.
4. При использовании обратного прокси-сервера или автоматического сценария убедитесь, что порт, имя домена и путь не изменились после обновления.

## Ключевые данные, которые необходимо сохранить

Самое важное, что следует учитывать при обновлении, — это сохранить следующее:

- База данных SQLite: `data/outlook_accounts.db`.
- Исправлено `SECRET_KEY`.
- Пользовательские переменные среды

Если `SECRET_KEY` изменен, сохраненные конфиденциальные данные, такие как токен обновления, ключ API и пароль электронной почты, не смогут быть расшифрованы.

## Обновление докера

### Обновление до последней стабильной сборки ветки.

```bash
docker pull ghcr.io/assast/outlookemail:latest
docker compose down
docker compose up -d
```

### Обновление до указанной официальной версии.

В официальной среде рекомендуется отдавать приоритет использованию четких номеров версий:

```bash
docker pull ghcr.io/assast/outlookemail:v2.0.15
docker compose down
docker compose up -d
```

Если вы используете `docker-compose.yml`, вы также можете напрямую изменить изображение на указанную версию:

```yaml
services:
  outlook-mail-reader:
    image: ghcr.io/assast/outlookemail:v2.0.15
```

Выполнить после завершения:

```bash
docker compose up -d
```

## Обновление Windows `exe`

1. Загрузите новую версию `OutlookEmail-windows-x64-*.zip` с GitHub Releases.
2. Разархивируйте в новый каталог или перезапишите файлы программы в старом каталоге.
3. Сохраните исходный каталог данных `%APPDATA%\\OutlookEmail`.
4. Начать новый `OutlookEmail.exe`

Описание:

- Данные по умолчанию находятся не в каталоге программы, а в `%APPDATA%\\OutlookEmail`
- Не удаляйте базу данных или файлы ключей в этом каталоге по своему желанию.

## Прямое обновление Python

```bash
git pull origin main
pip install -r requirements.txt
python web_outlook_app.py
```

Если вы используете виртуальную среду, активируйте соответствующую среду перед выполнением.

## Проверка после обновления

После обновления рекомендуется подтвердить как минимум следующее:

1. Страницу входа можно открыть в обычном режиме.
2. Исходные учетные записи, группы, ярлыки и настройки все еще существуют.
3. Исходная плоская группа по-прежнему отображается как группа первого уровня; создание новой подгруппы и выбор родительской группы для просмотра учетной записи подгруппы — это нормально.
4. Случайно проверьте хотя бы одну учетную запись Outlook и одну учетную запись IMAP, чтобы обеспечить нормальный доступ.
5. Если внешний API включен, проверьте `/api/external/emails` один раз.
6. Если включена автоматическая пересылка или запланированное обновление, проверьте, нормально ли выполняется задача.

## Рекомендуемая стратегия обновления

### Производственная среда

- Отдайте приоритет использованию тегов чистой версии `vX.Y.Z`.
- Сначала проверьте в тестовой среде, а затем обновите до официальной среды.
- Создайте резервную копию базы данных перед обновлением.

### Тестовая или личная среда

- Вы можете использовать `latest` напрямую.
- Если вы хотите отслеживать версию разработки, вы можете использовать `dev`.

## Идеи отката

Если после обновления обнаружены проблемы, вы можете выполнить откат в соответствии с исходным методом развертывания:

### Откат Docker

```bash
docker pull ghcr.io/assast/outlookemail:v2.0.13
docker compose down
docker compose up -d
```

### Откат Windows

- Вернитесь к старой версии `exe`.
- Сохраните исходный каталог данных без изменений.

### Откат Python

```bash
git checkout <соответствующая фиксация или тег старой версии>
pip install -r requirements.txt
python web_outlook_app.py
```

Если структура базы данных изменится в процессе обновления, перед откатом необходимо сначала подтвердить, совместима ли старая версия с текущей базой данных.

## Часто задаваемые вопросы

### Ошибка входа в систему или нарушение конфиденциальных данных после обновления.

Установите приоритет проверки того, был ли изменен `SECRET_KEY`. Это самая распространенная причина.

### `latest` и версия выпуска несовместимы после обновления.

Это нормально:

- `latest` обычно соответствует последней соответствующей сборке ветки по умолчанию.
- `vX.Y.Z` соответствует образу версии, созданному при выпуске официальной версии.

Для официальной среды рекомендуется указать четкий номер версии.
