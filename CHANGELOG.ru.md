The format is based on Keep a Changelog, and this project follows Semantic Versioning (`MAJOR.MINOR.PATCH`).

### Security
— Включите DOMPurify 3.4.17 в локальные статические ресурсы и используйте его для основного интерфейса и страницы общего доступа к электронной почте, чтобы не полагаться на CDN для сценариев очистки тела электронной почты (# 108).

## [3.0.30] - 2026-11-06

### Fixed
— исправлено несоответствие темы списка и деталей после удаления электронных писем IMAP, а также проблема, заключающаяся в том, что старые серийные номера могут случайно удалить другие электронные письма (#105); список возвращает UID единообразно и связывается вместе, когда сервер предоставляет UIDVALIDITY. Подробности, исходные электронные письма, вложения, операции чтения и удаления больше не откатывают один и тот же номер между UID и серийным номером.
— запрос старого серийного номера требует повторной синхронизации; старый тег кэша IMAP будет признан недействительным и перестроен за один раз во время первого запуска, а исходная текстовая запись кэша будет сохранена, чтобы избежать дальнейшего отображения несовпадающих деталей.
— исправлена ​​проблема, из-за которой почтовые ящики, такие как Gmail и Outlook IMAP, которые не поддерживают сортировку IMAP, не могут получить доступ к общим ресурсам «Latest N Only» (#107); вернуться к пакетному чтению метаданных UID и INTERNALDATE, сортировке по фактическому времени отправки электронной почты, гарантируя, что старые импортированные или скопированные электронные письма не попадут в неправильный диапазон авторизации из-за больших UID.

### Important
— идентификатор сообщения IMAP равен `imap:<UIDVALIDITY>:<UID>`, когда сервер предоставляет UIDVALIDITY. Клиент API должен повторно получить список и вернуть идентификатор в том виде, в каком он есть, и не может изменить старый серийный номер на UID; номер счета, информация для авторизации и удаленный адрес электронной почты не будут затронуты.
— Серверам, не поддерживающим SORT, требуются дополнительные метаданные времени сканирования, а проверка ограниченного общего доступа к большим почтовым ящикам может выполняться медленнее; При сканировании с откатом используется текущий бюджет тайм-аута IMAP, и в доступе будет по-прежнему отказано, если данные неполны, ответ превышает лимит или истекает тайм-аут, и не будет автоматически изменен на неограниченный.

## [3.0.29] - 2026-11-06

### Added
— учетные записи Outlook/Hotmail поддерживают независимый выбор области токена графа и могут использовать автоматическую, `.default`, только для чтения, полные разрешения или пользовательскую конфигурацию; автоматический режим запомнит самую последнюю успешную область в процессе, чтобы уменьшить количество повторных неудачных запросов (# 103).

### Changed
— Ограниченный общий доступ к электронной почте загружается лениво в соответствии с текущей открытой папкой. Во входящих и спам-сообщениях отображаются последние N писем соответственно, что уменьшает количество дополнительных запросов при открытии страницы общего доступа (#104).

### Fixed
— Очистите старый кэш успехов сразу после изменения области действия учетной записи или восстановления автоматического режима, чтобы избежать дальнейшего использования предыдущей конфигурации, доступной только для чтения.
— Фоновая переадресация также будет применять область, сохраненную учетной записью во время холодного запуска, без предварительного открытия страницы учетной записи.
— выберите область в соответствии с необходимыми разрешениями на отправку, удаление и пометку как прочитанные, чтобы избежать повторного использования несовместимого кэша только для чтения; сохраните `.default`, пользовательскую область и резервную исходную авторизованную область и отправьте сообщение только один раз.
— Ограничьте попытки входа в Gmail IMAP и список ожиданий очистки соединений, чтобы уменьшить задержки при получении писем в аномальных сетях.

### Important
- **К старым ссылкам с ограниченным доступом также будут применяться новые правила**: исходное «всего N сообщений для обеих папок» заменено на «N сообщений для каждой папки», и можно будет получить доступ максимум к 2N сообщениям. Если вы не согласны с новым диапазоном видимости, отзовите соответствующие ссылки перед обновлением.
— Поле объема учетной записи автоматически заполняется при запуске, что устраняет необходимость миграции вручную; ненастроенные учетные записи продолжают использовать автоматический режим, а автоматическая память успешных областей будет восстановлена ​​после перезапуска процесса.

## [3.0.28] - 2026-10-31

### Added
— Правила пересылки поддерживают независимую настройку ключевых слов электронной почты и условий отправителя и могут использоваться как для обычных почтовых ящиков, так и для источников Cloudflare; в предварительном просмотре и списке правил будут отображаться фактически действующие условия.
– Правила пересылки поддерживают однократное и пакетное редактирование одного и того же исходного диапазона. Вы можете изменить метод уведомления, канал, ключевые слова или отправителя соответственно и оставить поля неотмеченными.

### Changed
— Условия фильтрации электронной почты перенесены из глобальных настроек работы в исходные правила. Ключевые слова и условия отправителя должны быть заданы одновременно, если они заполнены одновременно; электронные письма, не соответствующие условиям, не будут доставлены, но процесс сканирования будет продолжаться в обычном режиме.
— Существующие правила можно редактировать через идентификатор стабильного правила. Изменение цели уведомления или условий фильтрации не приведет к изменению личности источника; При сбое пакетного редактирования все правило будет отменено, а историческая доставка не будет автоматически повторно отправляться из-за изменений в условиях правила.

### Important
— при обновлении автоматически заполняются поля условий правил для существующей базы данных и переносятся старые глобальные ключевые слова в обычные правила для почтовых ящиков, которые действовали до обновления; На Cloudflare по-прежнему не будут влиять старые глобальные ключевые слова. Миграция и тегирование выполняются в одной транзакции. В случае неудачи будет произведен откат всей системы. Ручная миграция не требуется. Однако перед обновлением рекомендуется создать резервную копию каталога `data/`.

## [3.0.27] - 2026-10-31

### Added
— Настройки пересылки электронной почты реструктурированы в независимые рабочие области управления: поддерживается создание нескольких каналов уведомлений SMTP, Telegram, Enterprise WeChat и Feishu, а также связываются правила по обычному адресу электронной почты, группе, Cloudflare Worker, имени домена или полному адресу получателя.
— добавлен предварительный просмотр правила пересылки, история доставки, статус доставки, не зависящий от канала, неудачная повторная попытка, а также пакетная фильтрация и удаление; в одном и том же электронном письме результаты регистрируются отдельно для разных каналов уведомлений.

### Changed
— Обычные уведомления почтового ящика наследуются в соответствии с «конкретным почтовым ящиком → группой → общей конфигурацией по умолчанию», а электронные письма Cloudflare анализируются в соответствии с «конкретным адресом → именем домена → конфигурацией рабочего по умолчанию»; текущие настройки и правила канала сохраняются отдельно.
— Сохранение состояния пересылки доставки и сканирования источников для поддержки продолжения обработки после перезапуска службы, а также для правильной блокировки или отмены ожидающих доставок при изменении пунктов назначения уведомлений, деактивации источников или деактивации каналов.

### Important
— Обновление автоматически и идемпотентно перенесет старые настройки SMTP, Telegram, Enterprise WeChat и Feishu на совместимые каналы; существующие учетные записи, в которых изначально была включена переадресация, будут перенесены на определенные правила электронной почты, а учетные записи, которые изначально были закрыты, останутся без уведомления, а существующие ручные правила будут сохранены. Ручная миграция не требуется, но перед обновлением рекомендуется создать резервную копию каталога `data/`.

## [3.0.26] - 2026-10-29

### Added
— В список рассылки IMAP добавлен новый журнал запросов, занимающий много времени, который может отслеживать фазы подключения, аутентификации, выбора папки, поиска, извлечения, анализа и отключения по запросу.

### Changed
— Список рассылки IMAP считывает заголовки сообщений, статус чтения, время прибытия и структуру вложений пакетами на каждой странице; тело и вложения читаются только при открытии сообщения. Когда сервер отклоняет пакетный запрос, он автоматически возвращается к чтению заголовков электронной почты один за другим.
— больше не выполняется предварительная загрузка текста после принятия новых писем, синхронизированных в фоновом режиме; Обновление списка сохраняет существующий локальный предварительный просмотр текста.

### Important
— Ручная миграция не требуется. Сообщения в списке IMAP, которые еще не были кэшированы для предварительного просмотра, отображают пустой предварительный просмотр, а текст читается после открытия сообщения.

## [3.0.25] - 2026-10-27

### Added
- Управление iCloud (#101): поддерживает настройку основной учетной записи Apple, ручной вход в систему и код двухфакторной проверки, синхронизацию/создание/деактивацию/удаление скрытых адресов электронной почты, дополнительный автоматический повторный вход и сопоставление адресов с соответствующими учетными записями получателей.
– Обычные почтовые ящики поддерживают iCloud IMAP и пароли для приложений; добавлены новые независимые инструкции iCloud, охватывающие настройку, резервное копирование и переход на более раннюю версию.

### Security
- Пароль для входа в Apple, сеанс управления и конфигурация автоматического повторного входа шифруются и сохраняются; код подтверждения используется только для текущего процесса проверки и не сохраняется.

### Important
— Ручная миграция не требуется. Частное соглашение Apple и долгосрочное продление еще не прошли реальную акцептацию; следуйте инструкциям, чтобы подтвердить свой логин, управление адресом и получение почты.

## [3.0.24] - 2026-10-24

### Added
— Новый канал робота Feishuqun для пересылки электронной почты (#99): поддерживает Webhook, дополнительный ключ подписи и отправку тестовых сообщений. Его можно включить одновременно с SMTP, Telegram и Enterprise WeChat. В push-уведомлении указывается номер счета, отправитель, получатель/копия, тема, время и текстовая сводка.
— Feishu повторно использует существующий переключатель переадресации учетных записей, фильтрацию ключевых слов, временное окно и дедупликацию по каналам; поддерживает общее ограничение скорости, ограничение тока, охлаждение и безопасные подсказки об ошибках. В случае сбоя он будет повторять попытки только тех каналов, которые не увенчались успехом.
- Тестовое сообщение использует текущую форму и не сохраняется автоматически; как тестовые, так и официальные уведомления включают «пересылку по электронной почте», чтобы облегчить настройку ключевых слов безопасности робота.

### Security
— Feishu Webhook и ключи подписи шифруются и сохраняются без повторного отображения. Оставьте их пустыми, чтобы сохранить существующую конфигурацию. Удаление подписи требует явной операции. Успешная доставка регистрируется только в том случае, если успешны как HTTP, так и бизнес-код Feishu.

### Important
— Обновление без миграции вручную. Перед использованием настройте и включите Feishu в «Настройки -> Настройки пересылки электронной почты» и включите переадресацию на уровне учетной записи для адресов электронной почты, которые необходимо уведомить. Результат отправки может быть неопределенным после тайм-аута сети, а последующие повторные попытки могут привести к повторным уведомлениям.

## [3.0.23] - 2026-10-23

### Fixed
— Исправлена ​​проблема фоновой пересылки электронной почты, продолжающая удерживать блокировки записи SQLite во время последующих сетевых запросов: не удалось получить сведения о папке или электронной почте, своевременная отправка после отправки каждого канала, уменьшение количества ошибок блокировки базы данных, возникающих из-за блокировки записи в локальный кэш при обновлении и просмотре электронных писем на переднем плане (# 100).
— Каждый канал пересылки отправляет записи дедупликации независимо. Последующие исключения обработки электронной почты больше не будут отменять записи успешных каналов, что сокращает количество повторных пересылок во время повторных попыток.

## [3.0.22] - 2026-10-23

### Added
- Совместное использование электронной почты поддерживает пользовательские коды доступа в стиле сетевого диска (#92): при создании можно установить от 4 до 32 английских букв или цифр, с учетом регистра; после успешного создания вы можете скопировать ссылку для общего доступа и код доступа, и управление общим доступом укажет, требуется ли код доступа.
- Посетители могут просматривать информацию об электронной почте, списках рассылки и подробную информацию только после ввода правильного кода доступа; один и тот же сеанс браузера запоминает 20 последних проверенных общих ссылок и по-прежнему будет соответствовать сроку действия, статусу отзыва и ограничению количества электронных писем после проверки.

### Security
— Код доступа хранится с использованием хеша bcrypt, а простой текст отображается только в результате создания; успешная проверка предоставляет только разрешение на чтение соответствующего общего ресурса, но не предоставляет разрешение на управление или запись.
- После неправильного ввода одного и того же IP для одной и той же шары 5 раз подряд проверка приостанавливается на 5 минут; страницу общего доступа и интерфейс анонимного чтения запрещено кэшировать, а адрес электронной почты или содержимое электронной почты не будут возвращены до проверки.

### Important
— Поля базы данных заполняются автоматически при запуске, что исключает необходимость ручной миграции; Доступ к существующим ссылкам и новым ссылкам без установленного кода доступа сохраняется.
- Сохраните код доступа, отображаемый при его создании; если вы забыли код доступа, отмените старую общую папку и создайте ее заново.

## [3.0.21] - 2026-10-21

### Added
— В результатах обновления токена различаются «обновление успешно, токен обновлен» и «проверка успешна, токен не был ротирован, продолжайте использовать исходный токен», одновременно отображаются запросы для отдельных учетных записей, пакетные журналы и списки обновлений, а результаты ротации каждого обновления сохраняются.
— Управление обновлением токенов добавляет время «Последнего успешного обновления» и «Последней ротации», которые отображаются отдельно от «Последнего обновления»; если запрос не ротируется, но запрос успешен, время успеха также будет обновлено. Если последующий сбой завершится неудачей, время последнего успеха будет сохранено. Если он не вращается, время последнего вращения будет сохранено.
— Запрос на завершение пакетного обновления увеличивает количество учетных записей с обновленными и неротированными токенами.

### Fixed
— Обновление токена Outlook Graph изменено, чтобы установить приоритет запроса `.default`. Если успешно, но не возвращен действительный токен обновления, продолжайте пробовать исходную область авторизации; когда повторный выпуск не удается или новое значение не возвращается, существующие успешные результаты и старый токен сохраняются, чтобы не пропустить доступные возможности ротации. Запросы на включение сохраняют исходный порядок области действия.
— Если новый токен обновления не удается сохранить, это записывается как сбой обновления, чтобы избежать ложных сообщений о том, что токен был обновлен; журнал обновления дополнен сортировкой за ту же секунду, чтобы гарантировать, что самые последние результаты отображаются первыми.

### Important
- Автоматически заполнять поля базы данных при запуске и восстанавливать самое последнее подтверждаемое время успеха из существующих журналов успеха и состояния учетной записи; результат ротации старых журналов отображается как «Незаписано», а неизвестное время остается пустым, без ручной миграции.

## [3.0.20] - 2026-10-18

## [3.0.0] - 2026-07-27

### Added
— URL-адрес прокси-сервера группы/аккаунта поддерживает заполнитель `{mail}`: расширяется в соответствии с локальной частью адреса электронной почты (сохраняются только буквенно-цифровые и строчные буквы) при исходящих сообщениях, настраивается исходный инвентарь, API/эхо редактирования и не расширяется; может быть подключен к пулам липких прокси, таким как [Resin](https://github.com/Resinat/Resin).
— Автоматическая авторизация учетных записей загрузки: приоритет отдается использованию самой записи загрузки `proxy_url`, в противном случае наследуется шаблон группового прокси, а основной прокси-сервер фиксируется на протяжении всего процесса OAuth (переключение при отказе в середине процесса не происходит).
— переменная среды `LOG_LEVEL` (`DEBUG`/`INFO`/`WARNING`/`ERROR`/`CRITICAL`, по умолчанию `INFO`) управляет глобальным уровнем журнала; INFO по умолчанию выводит исходящие данные `[Агента]` (кодирование пароля, включая платформу/учетную запись Resin).
— Журнал использования исходящего прокси-сервера охватывает такие пути, как отправка сообщений, обновление токена, сокет IMAP и автоматическая авторизация Outlook.

### Fixed
— исправлена ​​проблема, из-за которой обновление токена не учитывало переопределение агента на уровне учетной записи и считывало только агент группы; теперь это соответствует получению электронной почты: переопределение учетной записи → наследование группы → расширение `{mail}`; `db` правильно передается, когда нет контекста Flask для запланированного обновления.
— Исправлена ​​проблема, из-за которой PySocks переходил в состояние NO AUTH и Resin не получал Platform.Account, когда прокси-сервер SOCKS «имеет имя пользователя и пароль пуст»: транспортный уровень заполняет заполнитель пароля, чтобы принудительно использовать UserPass.
— Исправлена ​​проблема, из-за которой редактирование группы по умолчанию (внешнее представление `parent_id=null` и родительский элемент без изменений) ошибочно воспринималось как «неподвижное».
— Запросы, связанные с токеном/пакетным обновлением, для дополнения столбца учетной записи `proxy_url`/резервного, чтобы избежать переопределения учетной записи из-за разрешенной потери конфигурации.

### Changed
— `get_account_proxy_url`/`get_account_proxy_failover_urls` вместо этого возвращают исходящий прокси, расширенный во время выполнения; хранилище и отображение по-прежнему используют нерасширенный путь конфигурации.
— Автоматическая авторизация графа: `trust_env=False`, когда прокси-сервер приложения настроен так, чтобы избежать дублирования с прокси-сервером среды.
- В интерфейсе и документации приоритет отдается `socks5h://`, и объясняются `{mail}`, примеры смолы и шумоподавление `LOG_LEVEL=WARNING`.

### Important
— **Изменения в поведении:** Для почтового ящика, настроенного с помощью агента на уровне учетной записи, обновление токена теперь также будет использовать агент (ранее оно все еще могло использовать группировку или прямое соединение).
— **Изменения в поведении:** URL-адреса SOCKS в форме `user:@host` / `user@host` будут отправлять UserPass (используйте заполнитель для пустого пароля); Прокси-серверы без Resin, использующие «имя пользователя, но НЕТ АУТИЗАЦИИ», могут быть несовместимы.
— Пакетное извлечение/обновление содержит больше журналов под `LOG_LEVEL=INFO` по умолчанию; производство может настроить `LOG_LEVEL=WARNING` для отключения `[Агента]` и другого вывода INFO.
- разные префиксы `{mail}` могут конфликтовать после очистки (например, `a.b` и `ab`); чистая небуквенно-цифровая локальная часть может расшириться до пустого сегмента учетной записи.

### Added

- Добавлены настройки локального хранения, статистика хранения, статус очистки и операции очистки кэша для обычных почтовых ящиков.
— Добавлены интерфейсы `/api/emails/retain-bodies`, `/api/settings/normal-mail-retention/status` и `/api/settings/normal-mail-retention/clear`.
— Добавлен `docs/local-mail-retention.md` для объяснения локального диапазона хранения, поведения синхронизации, подробного хранения текста, стратегии очистки и ограничений по этапам для обычных почтовых ящиков.

### Changed
— Обычный список почтовых ящиков, сведения, операции пометки чтения и удаления будут синхронно поддерживать статус локального хранения, а данные хранения по умолчанию контролируются переключателем `normal_mail_local_retention_enabled=false`.
— Резервные сведения IMAP для Outlook/Hotmail OAuth и поддержка загрузки вложений `id_mode=uid|sequence`, который по умолчанию считывается по UID, чтобы избежать смешивания UID и серийных номеров.
- Обычная фильтрация по ключевым словам почтового ящика отдает приоритет проверке кэшированного текста и компенсирует удаленное чтение только тогда, когда необходимы удаленные данные.
— Обычные параметры подкачки почтовых ящиков изменены на безопасный анализ, нечисловые значения используют значения по умолчанию, отрицательные числа обрабатываются как `0`, а максимальный удаленный список `top` — `50`.
— на странице настроек отображается количество сохраненных сообщений, кэшированный текст, предполагаемый размер хранения и размер базы данных SQLite, сохраняемой локально в обычных почтовых ящиках, а также запрос на подтверждение очистки, когда переключатель хранения выключен.
— README, инструкции по локальному хранению и документация по API дополняют общее локальное хранение почтовых ящиков, завершение текста, статус очистки, `id_mode` и поведение загрузки вложений.

### Fixed
— Исправлена ​​проблема, из-за которой параметры подкачки интерфейса, такие как журналы обновления и журналы пересылки, не защищены границами, могут сообщаться об ошибках из-за недопустимого ввода или чрезмерных запросов подкачки.
— Исправлена ​​проблема, из-за которой внешнее сравнение ключей API не выполняло стабильную нормализацию строк и сравнение с постоянным временем.
— Исправлена ​​проблема, связанная с тем, что локальное хранение повторяющихся сообщений в обычных почтовых ящиках под разными почтовыми ящиками `id_mode` может повлиять на дедупликацию списков, обратное заполнение подробностей и запрос на обновление.
— исправлена ​​проблема, из-за которой при очистке локального кэша хранения общего почтового ящика при кратковременной блокировке SQLite отсутствуют ограниченные повторные попытки, а повторные запросы на очистку могут запускать несколько задач очистки.
— Исправлена ​​проблема, из-за которой фильтрация по теме, отправителю и ключевым словам применялась только после разбивки локального зарезервированного списка обычных почтовых ящиков, в результате чего первый экран отсутствовал, а `count` и `has_more` были неточными, когда соответствующие электронные письма находились на последующих страницах.
— исправлена ​​проблема, из-за которой большее количество электронных писем могло дублироваться или пропускаться из-за смещения смещения во время фоновой синхронизации, вставляя новые электронные письма во время отображения локального списка хранения и продолжая загружать больше электронных писем.
— исправлена ​​проблема, из-за которой кэш внешней памяти мог продолжать отображать очищенный локальный список рассылки после очистки или отключения локального хранения обычных почтовых ящиков.

— Добавлен контроллер панели задач Windows для упакованного настольного приложения с действиями «Открыть интерфейс ` and ` выхода».

### Changed
— Управление обновлением токена удаляет карту текущего прогресса и изменяет ее для постоянного отображения журнала задач во всплывающем окне.
- Switched the packaged Windows desktop runtime to a controllable background server so the tray can exit the app cleanly.

### Fixed
— исправлена ​​проблема «сбоя повторной попытки», при которой по-прежнему принимаются синхронные запросы, изменен потоковый вывод журнала, повторно использован интервал обновления и прекращено управление задачами.
- Fixed the Windows packaged app having no visible way to quit after launching the browser UI.

## [1.0.0] - 2026-04-07

### Added
- Stable initial release baseline for the Outlook mail management tool.
- Web UI for mailbox group management, mailbox import, and mail browsing.
- Outlook access via Microsoft Graph API, new IMAP, and legacy IMAP fallback.
- Temporary mailbox integration for GPTMail, DuckMail, and Cloudflare Temp Email.
- External API access using API Key authentication.
- Docker and Docker Compose deployment support.
