#Инструменты управления электронной почтой с несколькими почтовыми ящиками

Инструмент управления электронной почтой для сценариев с несколькими учетными записями электронной почты. Он поддерживает унифицированное чтение, управление и пересылку электронной почты через Outlook/Hotmail OAuth, API Microsoft Graph и стандартный IMAP. Он также предоставляет веб-интерфейс и расширение браузера Chrome/Edge для управления группами, управления учетными записями, просмотра электронной почты и вызовов внешних API. В настоящее время поддерживает Outlook/Hotmail, Gmail, QQ, 163, 126, Yahoo, почтовый ящик Alibaba и пользовательские почтовые ящики IMAP, а также интегрирует возможности временных почтовых ящиков GPTMail, DuckMail, Cloudflare Temp Email с несколькими поставщиками.

Примечание. Изменение пароля приведет к тому, что аутентификация станет недействительной и потребуется повторная авторизация.

### Режим работы

Службе необходимо поддерживать работу одного рабочего процесса. Официальный образ Docker исправлен на однопоточный + многопоточный режим Gunicorn; если вы настраиваете развертывание, не увеличивайте количество рабочих. Если требуется параллелизм, отдайте приоритет регулированию количества потоков. Задачи потоковой передачи, управляемые обновлением токена, будут использовать краткосрочное состояние внутри процесса, а несколько рабочих процессов приведут к тому, что инициализация задач и подписка SSE попадут в разные процессы.

#### Необязательно: включите онлайн-обновление интерфейса Docker + используйте собственный идентификатор клиента и URL-адрес обратного вызова.

Онлайн-обновление Docker в интерфейсе требует доступа к сокету хоста Docker. `/var/run/docker.sock` имеет права управления Docker на хосте, и его рекомендуется включать только в доверенной среде.

Эта функция доступна только для контейнеров, использующих переменные теги изображений, такие как `latest`, `main` и `dev`. Если текущий контейнер имеет метку версии, например `v2.0.39`, интерфейс откажется от онлайн-обновления, поскольку Watchtower не будет автоматически переключать фиксированную метку на метку новой версии.
По умолчанию приложение автоматически повторяет попытку в соответствии с этой версией, когда демон явно возвращает «минимальную поддерживаемую версию API»; Если ваша среда Docker или агент сокета предъявляют особые требования к совместимости, вы также можете явно установить `DOCKER_UPDATE_API_VERSION`, и его значение можно будет ссылаться на выходные данные `docker version --format '{{.Server.APIVersion}}'`.
Необязательная переменная среды `DOCKER_UPDATE_STATUS_TIMEOUT` используется для независимого управления временем ожидания (в секундах) запроса статуса и проверки контейнера и не влияет на `DOCKER_UPDATE_TIMEOUT` фактической задачи обновления.
Если для текущего тега `latest` / `main` / `dev` нет нового изображения, интерфейс отобразит, что на этот раз обновление не было применено, вместо ложного сообщения о том, что обновление не удалось.

Если вы хотите, чтобы функция «Получить токен» в интерфейсе использовала ваше собственное приложение Azure, установите `OAUTH_CLIENT_ID` и `OAUTH_REDIRECT_URI` одновременно. Эти два значения будут использоваться для генерации ссылок авторизации Microsoft и обмена на Refresh Token; после успешного обмена идентификатор клиента, возвращаемый интерфейсом, необходимо импортировать в учетную запись вместе с токеном обновления. Если этот параметр не установлен, будет использоваться встроенный идентификатор клиента по умолчанию проекта и адрес обратного вызова по умолчанию `http://localhost:8080`.

```yaml
version: '3.8'
services:
  outlook-mail-reader:
    image: ghcr.io/assast/outlookemail:latest
    container_name: outlook-mail-reader
    ports:
      - "5000:5000"
```

### Способ 5. Создайте и запустите локальный исходный код (docker-compose.build.yml).

Его удобно запускать после того, как локальный компьютер создаст образ на основе исходного кода (вместо загрузки предварительно созданного образа на `ghcr.io`), что облегчает немедленную проверку после локальных изменений.

Корневой каталог хранилища предоставил `docker-compose.build.yml`, который будет использовать `Dockerfile` в корневом каталоге для создания образа из исходного кода и запуска контейнера.

#### Шаг 1. Подготовьте файл переменных среды `.env.local`.

`docker-compose.build.yml` внедряет переменные среды через `env_file: .env.local`. Если файл** не существует, Compose напрямую сообщит об ошибке и откажется запускаться**. Сначала вам необходимо скопировать и изменить его из шаблона:

```bash
cp .env.example .env.local
```

Измените хотя бы два из следующих пунктов:

```bash
# Генерируем случайную строку и заполняем SECRET_KEY из .env.local
python -c 'import secrets; print(secrets.token_hex(32))'
```

- `SECRET_KEY`: заполните случайную строку, сгенерированную выше (обязательно измените ее, не используйте значения-заполнители; начальные и конечные пробелы будут игнорироваться)
- `LOGIN_PASSWORD`: пароль для входа во время первой инициализации, по умолчанию — `admin123`, рекомендуется изменить его на надежный пароль; изменение этой переменной после ее записи в базу данных не приведет к перезаписи текущего пароля. Если вы забыли свой пароль, используйте `scripts/reset_login_password.py` (см. [Устранение неполадок](docs/troubleshooting.md) / [Конфигурация безопасности](docs/security.md))

Необязательно: если вам нужно настроить количество потоков/таймаута Gunicorn, добавьте `GUNICORN_THREADS` и `GUNICORN_TIMEOUT` к `.env.local` (если оставить пустым, используйте значение по умолчанию 4/300).

Необязательно: общее время ожидания чтения списков почты в обычных почтовых ящиках Outlook/IMAP по умолчанию составляет 120 секунд, которое можно настроить в «Системные настройки -> Общие настройки -> Таймаут получения почты» (30-300 секунд); вы также можете установить начальное значение через `MAIL_FETCH_OVERALL_TIMEOUT` `.env.local` перед первым запуском. Это значение должно быть меньше `GUNICORN_TIMEOUT` (по умолчанию 300 секунд).

#### Шаг 2. Сборка и запуск

```bash
docker compose -f docker-compose.build.yml up -d --build
```

— `--build` заставляет образ пересобираться из исходного кода (метка образа — `outlookemail:local`)
— Имя контейнера — `outlook-mail`, а отображаемый порт — `5000:5000`.
— Сохранение данных осуществляется на хост-машине `./data`; `./static` и `./templates` монтируются в режиме только для чтения, что облегчает локальное редактирование шаблонов/статических ресурсов, чтобы они вступили в силу в реальном времени.

После запуска войдите в `http://localhost:5000` и войдите в систему с помощью `LOGIN_PASSWORD` в `.env.local`.

#### Шаг 3: Общие команды эксплуатации и обслуживания

```bash
# Посмотреть журнал
docker compose -f docker-compose.build.yml logs -f

# Просмотр проверки работоспособности и статуса
docker compose -f docker-compose.build.yml ps

# Пересобрать и перезапустить после изменения исходного кода.
```

## ✨ Особенности

### Метод чтения электронной почты

В настоящее время этот инструмент содержит три типа ссылок для чтения:

1. **Outlook/Hotmail OAuth + Graph API** — метод приоритета, подходит для учетных записей Outlook/Hotmail/Live.
2. **Outlook/Hotmail OAuth + резервный вариант IMAP** — `outlook.live.com` / `outlook.office365.com`
3. **Стандартный IMAP** — применимо к Gmail, QQ, 163, 126, Yahoo, Alibaba Mailbox и пользовательскому IMAP.

#### Обычное поведение и ограничения локального хранения почтовых ящиков

Обычный переключатель локального хранения почтового ящика `normal_mail_local_retention_enabled` по умолчанию отключен. Пользователям необходимо явно включить его в настройках системы, прежде чем обычные почтовые ящики Outlook/Hotmail и стандартные IMAP смогут сохранять метаданные списка и часть просмотренного и заполненного текста в локальном SQLite.

Если эта функция включена, сначала будет загружен обычный список почтовых ящиков из локальных сохраненных данных, а последний сохраненный список адресов электронной почты будет отображаться сразу же при нажатии; если вы продолжите прокручивать вниз, чтобы загрузить больше в режиме локального приоритета, также будет использоваться локальная сохраненная пейджинговая система, поэтому, когда удаленный доступ недоступен, вы все равно сможете просматривать сохраненные электронные письма за пределами первого экрана. Страница также продолжит инициировать удаленную синхронизацию с Graph API или IMAP в фоновом режиме. После успешной удаленной синхронизации новые метаданные списка будут записаны обратно в локальную библиотеку хранения; в случае сбоя синхронизации текущая страница сохранит локальный список и отобразит сообщение об ошибке фоновой синхронизации без очистки списка.

Когда фоновая синхронизация обнаруживает новые электронные письма, которые еще не отображались локально, на странице отображается непрерывное сообщение «Синхронизировано N новых электронных писем». Новые письма не будут добавлены в текущий список сразу после успешной синхронизации; новые электронные письма будут объединены в текущий список только после того, как пользователь нажмет на приглашение, а фоновое завершение выделения, обновление кэша списка и сохранение тела нового электронного письма будут выполнены, чтобы предотвратить внезапную замену прочитанных или выбранных электронных писем.

В деталях электронной почты приоритет будет отдаваться зарезервированному основному содержимому; Если локальная строка не имеет основного содержимого, основное содержимое будет заполнено сохраненными данными после успешного чтения удаленных сведений для последующего просмотра при обновлении страницы, перезапуске приложения или возникновении временного сбоя в сети. Если удаленные сведения не работают, но локальный текст уже существует, на странице сведений будет отображаться локальный сохраненный текст в качестве резервного варианта. Фильтрация ключевых слов также сначала проверяет кешированный текст, и только если кеш отсутствует, удаленные данные будут прочитаны.

Стандартные списки IMAP и Outlook/Hotmail OAuth IMAP одинаково возвращают `id_mode=uid`. Когда сервер возвращает UIDVALIDITY, идентификатор электронной почты — `imap:<UIDVALIDITY>:<UID>`; при звонке реквизиты, исходное письмо, вложение, интерфейсы чтения и удаления возвращайте как есть, не конвертируя в число. Серийный номер используется только для пейджинга в рамках текущего соединения и больше не используется в качестве идентификатора электронной почты для перекрестных запросов; старый запрос `id_mode=sequence` предложит обновить список, и тот же номер не будет использоваться для возврата к чтению других писем, если UID не существует.

После обновления старый серийный номер и кэш IMAP, не привязанный к UIDVALIDITY, будут единовременно помечены как недействительные и восстановлены посредством удаленной синхронизации; исходная текстовая запись кэша будет сохранена в базе данных для восстановления, а кэш графа, номер учетной записи и удаленная почта не будут затронуты. Старые клиенты API должны повторно получить список, а не просто менять `id_mode` старой записи с `sequence` на `uid`.

На этом этапе сохраняются только метаданные общего списка почтовых ящиков и текст сведений о прочтении, а загрузка или сохранение двоичного файла вложения и исходного содержимого MIME не включается; загрузка вложения по-прежнему зависит от текущей ссылки удаленного провайдера. На странице настроек отображается количество сохраненных сообщений, количество кэшированных тел, предполагаемый размер хранения и текущий размер базы данных SQLite, а также предусмотрено отдельное действие «очистить кеш». Когда переключатель локального удержания выключен, интерфейс сначала запросит подтверждение; после подтверждения локальные данные хранения обычного почтового ящика будут удалены с помощью задачи фоновой очистки, и будет отображен статус очистки. Задачи очистки отклоняют повторные запуски, ограничивают повторные попытки эфемерных блокировок SQLite, а опрос состояния внешнего интерфейса использует интервалы отсрочки для снижения нагрузки при выполнении длительных задач. См. [`docs/local-mail-retention.md`](docs/local-mail-retention.md) для более полного описания области действия.

### Функции веб-приложения

#### Основные функции
- 🔐 **Подтверждение входа** - Веб-интерфейс, защищенный паролем, поддерживает онлайн-изменение пароля; если вы забыли свой пароль, вы можете использовать официальный скрипт `scripts/reset_login_password.py` для его сброса (см. [Устранение неполадок](docs/troubleshooting.md))
— 📁 **Управление группами** — поддерживает до трёх уровней древовидной группировки почтовых ящиков, создание, редактирование, свертывание и расширение, сортировку на одном уровне, перетаскивание между уровнями и каскадное удаление.
— 🌐 **Прокси-сервер учетной записи/группы** — Каждую группу можно настроить с помощью прокси-сервера HTTP/SOCKS5, а подгруппы могут наследовать родительский прокси-сервер. Одна учетная запись также может установить прокси и сначала переопределить групповой прокси; URL-адрес прокси-сервера поддерживает заполнитель `{mail}` (связанный с пулами липких прокси, такими как [Resin](https://github.com/Resinat/Resin))
- 📧 **Управление несколькими электронными письмами** - Пакетный импорт и управление учетными записями электронной почты Outlook/Hotmail OAuth/IMAP
— 🪪 **Управление псевдонимами** — поддержка настройки нескольких псевдонимов почтовых ящиков для одного почтового ящика. И основной почтовый ящик, и псевдонимы можно использовать для получения электронных писем и вызова внешних API.
- 🔀 **Расширенное использование псевдонимов** - Вы можете автоматически перенаправить внешний почтовый ящик в почтовый ящик A, управляемый этим проектом, а затем настроить внешний почтовый ящик как псевдоним A, чтобы письма можно было читать одинаково в этом проекте.
- 📬 **Просмотр почты** — веб-интерфейс поддерживает просмотр входящих сообщений и спама; API поддерживает `inbox`, `junkemail`, `deleteditems`, `all`.
— 🔗 **Ссылка для общего доступа к электронной почте** — вы можете создать временную или постоянную ссылку для общего доступа только для чтения, а также выбрать отображение только последних писем «1–50» в вашем почтовом ящике и спаме соответственно.
- ✉️ **Основы написания электронной почты** - Учетные записи Outlook/Hotmail, прошедшие авторизацию Graph, могут отправлять электронные письма в виде простого текста в Интернете.
— 📎 **Загрузка вложений** — данные электронной почты поддерживают загрузку одного вложения, а также поддерживают упаковку всех вложений в виде загрузок ZIP.
— 🔍 **Полноэкранный режим** — поддержка просмотра электронной почты в полноэкранном режиме.
- 📤 **Функция экспорта** - Поддержка экспорта информации об учетной записи электронной почты по дереву групп, выбранной учетной записи или всем
— 🧩 **Резервное копирование WebDAV** — поддерживает запланированную загрузку файлов «Экспорт всех групп» в WebDAV с помощью Cron или загрузку вручную.
- 🎨 **Современный пользовательский интерфейс** - Четыре столбца с четкими разделами для списка учетных записей, списка рассылки и сведений о почте.
- 🎭 **Скин внешнего вида на уровне системы** - Поддерживает встроенный классический пакет скинов zip и исходный код хранилища Git; все устройства входа будут согласованы после переключения
- ⚡ **Оптимизация производительности** - Кэширование списка почты и списка учетных записей, переключение групп и переключение учетных записей выполняются быстрее.
— 📄 **Загрузка страницы** — прокрутите страницу вниз, чтобы автоматически загрузить следующую страницу (20 букв на странице).
— 🔥 **Временная электронная почта** — Интегрируйте GPTMail + DuckMail + Temporary Email Cloudflare, несколько провайдеров могут создавать, импортировать, читать и просматривать детали; Cloudflare поддерживает многоканальную конфигурацию, каждый пул паролей/почты рабочего/администратора управляется независимо, а все электронные письма можно просматривать по каналам.
- ⚙️ **Настройки системы** - Изменить пароль, ключ API, время ожидания получения электронной почты и т. д. онлайн.
- 🔄 **Ассистент OAuth2** — Встроенный процесс авторизации для быстрого получения токена обновления.
- 💾 **Кеширование почты** - Интеллектуальное кэширование списков рассылки, переключение для мгновенного отображения; локальное хранение обычных почтовых ящиков по умолчанию отключено, его можно включить, просмотреть статистику и очистить кэш локального хранения на странице настроек.
- 🏷️ **Управление метками** - Поддержка маркировки почтовых ящиков, пакетных операций и фильтрации по меткам.
- 🧮 **Управление проектом** - Получение/возврат почтовых ящиков (независимых конечных автоматов) в соответствии с размерами проекта. По умолчанию вход скрыт. Вы можете создавать проекты на веб-странице, просматривать количество статусов, деактивировать/восстанавливать и удалять после открытия «Настройки → Общие настройки».
— 📦 **Пакетное перемещение групп** — Пакетный выбор почтовых ящиков для перемещения на любой общий уровень группы.
- ✅ **Пакетный выбор** - Списки адресов электронной почты и списки рассылки поддерживают выбор всего текущего списка и отмену выбора.
- 🗑️ **Удаление электронной почты** - единоразовое/пакетное окончательное удаление; поддерживается как Graph, так и IMAP (включая стандартную учетную запись IMAP, резервный вариант OAuth IMAP)
- 🔄 **Резервный приоритет API** - Outlook OAuth API Graph по умолчанию → IMAP (новый) → IMAP (старый); предпочитаемый канал может быть записан по учетной записи, и он автоматически вернется в исходное состояние после сбоя и запомнит фактический успешный канал.
— 🔑 **Внешний API** — Получайте электронные письма напрямую через API-ключ без входа в систему. Поддерживает псевдонимы почтовых ящиков, агрегированные папки и фильтрацию по множеству условий. Дополнительные адреса электронной почты со знаком + автоматически распознаются и автоматически возвращаются к запросу основного почтового ящика/псевдонима почтового ящика; если требуемая функция относительно завершена, рекомендуется напрямую подключиться к полному API. Форма документа изменена и придана форма, подходящая для чтения ИИ. Напрямую передайте его ИИ и позвольте ИИ использовать пароль для входа вместо ключа API в соответствии с полным API.

#### Управление обновлением токена
- 🔁 **Полное обновление** - Обновите все токены учетной записи OAuth Outlook/Hotmail одним щелчком мыши.
— 🔄 **Результат ротации** — различайте токены, успешно обновленные и проверенные, но не ротированные, обновите журнал, чтобы постоянно записывать результаты ротации, и отобразите два типа количеств в подсказке о завершении пакета.
— 🕒 **Время обновления** — отображает последнее обновление, последнее успешное обновление и последнюю ротацию соответственно; отсутствие ротации также можно рассматривать как успешное обновление, и сбой не приведет к перезаписи последнего успешного обновления.
- ✅ **Выполнение пакетных операций** - Вы можете напрямую пакетно обновлять, копировать, экспортировать, пересылать, прокси, помечать, перемещать группы и удалять учетные записи в списке управления обновлением токенов.
- 📄 **Просмотр страниц** - Список управления обновлением токенов поддерживает переход по номеру страницы и переключение количества страниц, что подходит для сценариев с большим количеством учетных записей.
— ⏰ **Обновление по расписанию** — поддерживает настройку по дням или выражениям Cron и автоматически вступает в силу при запуске Docker/Docker Compose.

## 📖 Инструкция по применению

### 1. Получите учетные данные OAuth2 (этот шаг не является обязательным. Если приобретенная учетная запись имеет токен, вы можете пропустить этот шаг; сам проект также имеет встроенный идентификатор клиента по умолчанию. Если вы проигнорируете этот шаг, будет использоваться идентификатор клиента по умолчанию, и вы можете начать непосредственно с шага 5 этого раздела)

Чтобы использовать этот инструмент, вам необходимо получить следующие учетные данные OAuth2:

1. **Идентификатор клиента** – идентификатор клиента, зарегистрированный приложением Microsoft Azure.
2. **Токен обновления** – токен обновления OAuth2.

Помощник OAuth2 в интерфейсе считывает `OAUTH_CLIENT_ID` и `OAUTH_REDIRECT_URI` при запуске службы. Если вы настроите собственные значения в Docker/Docker Compose, эти значения будут использоваться для ссылок авторизации и обмена токенами; если они не настроены, будут использоваться встроенные значения проекта по умолчанию. При импорте учетных записей идентификатор клиента должен использоваться вместе с токеном обновления, замененным для той же авторизации.

#### Шаг 4. Настройте разрешения API. Этот шаг следует пропустить. Текущий встроенный идентификатор клиента можно использовать в обычном режиме без настройки этого шага.

Ручной помощник OAuth по умолчанию использует разрешения для одного ресурса GraphAPI, чтобы избежать смешивания ресурсов Graph и Outlook в рамках одной авторизации Microsoft OAuth v2. Времена `AADSTS70011`:
- `offline_access` - Получить токен обновления
- `Mail.Read`/`Mail.ReadWrite`/`Mail.Send`/`User.Read` - График чтения писем, управление электронной почтой, отправка писем как с текущей учетной записью, так и с основной информацией о пользователе.

`Mail.Send` — это полномочия делегирования, необходимые для написания основных электронных писем на стороне Интернета. Токен обновления истории не может автоматически увеличить это разрешение; Если при написании электронного письма вам будет предложено недостаточно прав, пожалуйста, повторите авторизацию `GraphAPI` для учетной записи. Повторная авторизация не повлияет на существующие конфигурации электронной почты.

При добавлении или редактировании учетной записи Outlook/Hotmail вы можете выбрать автоматические разрешения, `.default`, только для чтения, полные разрешения или пользовательские разрешения с помощью «Области токена». В автоматическом режиме запоминается самая последняя успешная область действия в процессе, и старый кеш будет очищен при изменении конфигурации или восстановлении автоматического режима; конфигурация учетной записи также применяется к фоновой переадресации. Область — это предпочтение параметра в обмен на токен. Для отправки сообщений, удаления и пометки как прочитанных будут выбраны кандидаты с необходимыми разрешениями. Фактические разрешения по-прежнему определяются авторизацией Microsoft.

Если вам нужен доступ к IMAP, выберите «Авторизация IMAP» на панели «Авторизация электронной почты Outlook» (по умолчанию для автоматической авторизации используется GraphAPI). Не помещайте его в ту же ссылку для ручной авторизации, что и разрешения Graph. Авторизация IMAP не включает `Mail.Send` и не поддерживает базовое написание электронных писем через Интернет.

#### Шаг 5. Получите токен обновления

Используйте встроенный помощник OAuth2 этого инструмента для получения токена обновления:

[Upstream screenshot: Обмен на токен](https://raw.githubusercontent.com/assast/outlookEmail/v3.0.32/img/%E6%8D%A2%E5%8F%96token.png)

1. Нажмите кнопку «Получить токен» в веб-интерфейсе.
2. Нажмите «Создать ссылку для авторизации».
3. Скопируйте ссылку и откройте ее в браузере для завершения авторизации.
4. Скопируйте полный URL-адрес после авторизации (по соображениям безопасности я не создавал сервис обратного вызова авторизации унифицированным образом. Все авторизации выполняются внутри сервисов, развернутых мной, и не будут утечек, поэтому URI перенаправления — http://localhost:8080. Эта ссылка точно не будет открыта, поэтому вам нужно скопировать ее и обменять на Refresh Token во второй половине развернутого сервиса)
5. Вставьте в поле ввода «Авторизованный URL».
6. Нажмите кнопку «Погасить токен».
7. Скопируйте полученный токен обновления.

### 2. Импортировать учетную запись электронной почты

После нажатия «Импортировать почтовый ящик» в веб-интерфейсе вы можете выбрать соответствующий формат импорта в соответствии с типом почтового ящика.

#### Outlook/Hotmail OAuth

Поддерживаются два формата:

```txt
Электронная почта ---- Пароль ---- client_id ----refresh_token
Электронная почта ----Пароль ----refresh_token ----client_id
```

Пример:

```txt
user@outlook.com----password123----24d9a0ed-8787-4584-883c-2fd79308940a----0.AXEA...
```

#### Стандартный почтовый ящик IMAP

iCloud поддерживает `imap.mail.me.com:993` и пароли для конкретных приложений, а также обеспечивает независимую основную учетную запись Apple, управление скрытыми адресами электронной почты и дополнительный автоматический повторный вход в систему. См. Инструкции по использованию iCloud (docs/icloud.md) для получения информации о настройке, карантине электронной почты, резервном копировании и переходе на более раннюю версию. Частные соглашения Apple и долгосрочные продления по-прежнему требуют принятия реальной учетной записи.

Применимо к Gmail, QQ, 163, 126, Yahoo, почтовому ящику Alibaba и т. д.:

```txt
Электронная почта ----код авторизации IMAP/пароль приложения.
```

Пример:

```txt
user@gmail.com----app-password
user@qq.com----imap-auth-code
```

#### Настройка IMAP

Поддерживаются два формата:

```txt
Электронная почта ---- пароль IMAP.
Электронная почта ---- пароль IMAP ---- imap_host ---- imap_port
```

Пример:

```txt
user@example.com----app-password
user@example.com----app-password----imap.example.com----993
```

Поддерживает пакетный импорт, по одной учетной записи в строке. Формат импортируемого файла остается неизменным; всплывающее окно импорта может единообразно устанавливать примечания, метки и статус для новой учетной записи, а также уведомлять о действующих правилах группы, в которой она автоматически используется. Временные группы почтовых ящиков невозможно выбрать при импорте обычных почтовых ящиков.

Группировка поддерживает до трех уровней иерархии. Если выбрана родительская группа, в списке учетных записей электронной почты одновременно будут отображаться учетные записи этой группы и всех подгрупп; если в подгруппе не настроен агент, она унаследует агент родительской группы вверх. Удаление группы, содержащей подгруппы, приведет к каскадному удалению подгрупп и перемещению связанных учетных записей обратно в группу по умолчанию.

#### Агент и шаблон смолы `{mail}`

URL-адрес прокси-сервера группы или учетной записи может содержать литерал `{mail}`. Исходящие запросы (извлечение писем, обновление токена, автоматическая авторизация Outlook и т. д.) будут заменены адресом электронной почты `@` во время выполнения. Локальная часть: удалить небуквенно-цифровые символы и преобразовать их в нижний регистр. Настройте библиотеку как есть, и эхо редактирования не будет расширено.

Рекомендуемый пример (порт Resin по умолчанию 2260, липкий идентификатор V1 `Platform.Account:TOKEN`):

```text
socks5h://outlook.{mail}:yourToken@127.0.0.1:2260
```

Если токен пуст, доступны следующие два варианта:

```text
socks5h://outlook.{mail}:@127.0.0.1:2260
socks5h://outlook.{mail}@127.0.0.1:2260
```

Описание:

- Рекомендуется отдать приоритет `socks5h://`/`socks5://`; обычный HTTP-прокси может быть недоступен для запросов токенов IMAP
— После очистки разные префиксы электронной почты могут конфликтовать (например, `a.b` и `ab`), этот проект допускает такое поведение.
- Автоматическая авторизация учетной записи загрузки: установите приоритет загрузки для записи собственного `proxy_url`, в противном случае наследуйте шаблон группового агента.
— По умолчанию `LOG_LEVEL=INFO` будет печатать данные `[Агента]` (кодирование пароля) при получении сообщений/обновлении токена/автоматической авторизации. Если имеется много журналов пакетных сцен, установите `LOG_LEVEL=WARNING`, чтобы уменьшить шум и закрыть этот тип INFO.
- Дружественный проект: [Смола](https://github.com/Resinat/Resin)

### 3. Проверьте электронную почту.

1. Выберите группу слева.
2. Выберите учетную запись электронной почты.
3. Нажмите кнопку «Получить электронную почту».
4. Переключитесь на «Входящие» и «Спам» в веб-интерфейсе, чтобы просмотреть электронные письма.
5. Прокрутите список рассылки вниз, чтобы автоматически загрузить следующую страницу (20 сообщений на странице).
6. Нажмите на электронное письмо, чтобы просмотреть подробную информацию, поддерживается рендеринг HTML и полноэкранный просмотр.
7. Когда вам необходимо просмотреть результаты агрегации `deleteditems` или `all`, рекомендуется использовать внешний API или внутренний API.

#### Базовое написание электронных писем на веб-сайте

После выбора включенной основной учетной записи Outlook/Hotmail, авторизованной `GraphAPI`, в верхней части списка почты будет отображаться надпись «Написать письмо». Эта функция поддерживает отправку электронных писем в виде обычного текста только одному или нескольким получателям в качестве самой текущей учетной записи:

— Если для исторической учетной записи будет предложено повторно авторизоваться, пожалуйста, завершите авторизацию `GraphAPI` еще раз, как указано выше, чтобы получить `Mail.Send`.
— Когда Microsoft Graph возвращает `202 Accepted`, в интерфейсе отображается «Почта отправлена ​​на отправку»; это означает, что сервис принял запрос, но это не означает, что получателю доставлено.
- Когда запрос на отправку сталкивается с тайм-аутом сети или прерыванием соединения, система не будет автоматически отправлять его повторно, чтобы избежать повторной доставки; пожалуйста, подтвердите результат, прежде чем решить, отправлять ли его вручную.
- В настоящее время отправка вручную по IMAP/SMTP, отправка временного почтового ящика, псевдонима или общего почтового ящика, вложения, HTML/форматированный текст, черновик, ответ/пересылка, список отправленных, портал расширений браузера, внешний API, пакетная, запланированная или автоматическая отправка писем не поддерживаются.

#### Ссылка для обмена электронными письмами

Отзывную ссылку только для чтения можно создать при совместном использовании учетной записи электронной почты. При создании можно выбрать «Безлимитно» или «Только последние N сообщений»; для последнего можно установить значение «1-50», а в папке «Входящие» и «спам» будут отображаться только последние N сообщений (какая бы папка ни была открыта).

— Серверы, не поддерживающие СОРТИРОВКУ, такие как Gmail и Outlook IMAP, будут считывать метаданные UID и INTERNALDATE в пакетном режиме и проверять «последний N» на основе фактического времени отправки электронной почты; импорт старых писем не расширит диапазон видимости из-за больших UID. Проверка больших почтовых ящиков может происходить медленнее, а неполные данные или тайм-ауты могут по-прежнему отказывать в доступе.
- Начиная с версии 3.0.29, старые ограниченные ссылки также вступают в силу в соответствии с «N печатей на папку», и можно получить доступ максимум к 2N печатям; Если вы не согласны с новым диапазоном видимости, отзовите соответствующие ссылки перед обновлением.
- Код доступа к дополнительным настройкам: `4–32` английские буквы или цифры, с учетом регистра; оставьте это поле пустым, иначе к существующим ссылкам без кодов доступа все равно можно будет получить прямой доступ. После настройки посетители должны пройти аутентификацию для просмотра информации об электронной почте, списков рассылки и подробностей.
— Вы можете скопировать ссылку и код доступа после успешного создания. Код доступа отображается только при его создании, сохраните его самостоятельно; управление общим доступом показывает только, установлен ли код доступа. Если вы ее забыли, отмените старую ссылку и создайте ее заново.
– В одном и том же сеансе браузера запоминаются 20 последних проверенных общих ссылок; после неправильного ввода кода доступа 5 раз подряд ИП приостановит проверку по этой ссылке на 5 минут. После проверки на вас по-прежнему распространяется период действия, статус отзыва и ограничение на количество электронных писем.
— «Только последние N» — это динамическое окно: после поступления новых сообщений старые сообщения могут перестать быть видимыми по ссылке.
— Ограниченная ссылка, срок действия которой не истекает, будет продолжать отображать последние N электронных писем в будущем; пожалуйста, отмените ссылку в управлении общим доступом, когда она вам больше не понадобится.
– Ограничение ограничивает только количество доступных электронных писем и не снижает чувствительности тела электронного письма, метаданных вложений и т. д., которые разрешено просматривать.

### 4. Выбор партии и работа с партиями

#### Список учетных записей электронной почты

В левой части списка учетных записей электронной почты есть поле выбора, которое подходит для обновления токенов, копирования адресов электронной почты, изменения статуса пересылки, маркировки, перемещения групп или одновременного удаления нескольких учетных записей.

Общие методы выбора:

1. **Отдельный выбор/отмена одного выбора**: щелкните поле выбора в левой части учетной записи.
2. **Войдите в режим пакетного выбора**: нажмите кнопку «☑» в верхней части панели почтового ящика. После того, как кнопка выделена, вы можете щелкнуть строку учетной записи, чтобы переключить выбранное состояние, не нажимая на поле выбора.
3. **Выбор непрерывного диапазона**: сначала выберите учетную запись, затем, удерживая `Shift`, щелкните другую учетную запись или поле выбора, и будет выбран непрерывный диапазон между ними.
4. **Перетаскивание**: после входа в режим пакетного выбора удерживайте мышь/трекпад на строке учетной записи или в поле выбора и перетаскивайте ее вверх или вниз, чтобы непрерывно выбирать проходящие учетные записи; если стартовая учетная запись была выбрана, это перетаскивание приведет к групповой отмене выбора проходящих учетных записей.
5. **Выбрать весь текущий список**: нажмите «Выбрать все» или «Выбрать все загруженные» в пакетном меню. Когда список учетных записей загружается на страницах, эта кнопка работает только для учетных записей, загруженных в данный момент на страницу; продолжив прокрутку вниз, чтобы загрузить больше, вы можете нажать еще раз, чтобы выбрать все загруженные.
6. **Очистить выбор**: нажмите «Очистить выбор», чтобы отменить все выборы в текущем списке.

После выбора хотя бы одной учетной записи появится пакетное меню:

— ПК: меню перемещается справа от первой выбранной учетной записи и перемещается по мере прокрутки списка учетных записей.
- Мобильный телефон: меню отображается внизу для удобного сенсорного управления.

Пакетные операции, поддерживаемые обычными учетными записями электронной почты:

— **Токен обновления**: доступен только для учетных записей OAuth Outlook/Hotmail; Учетные записи IMAP не могут быть обновлены, и кнопка предложит вам номер, который можно обновить.
- **Копировать адрес электронной почты+псевдоним**: скопируйте основной адрес электронной почты и настроенный псевдоним выбранной учетной записи.
- **Экспорт**: экспортируйте выбранную учетную запись после второй проверки. Целесообразно сначала отфильтровать по ярлыку или выполнить поиск, а затем экспортировать только выбранную в данный момент учетную запись.
- **Конфигурация уведомлений**: выберите несколько почтовых ящиков, групп или рабочих в разделе «Дополнительные функции -> Пересылка электронной почты -> Правила пересылки» вверху, чтобы единообразно указать каналы уведомлений или отключить уведомления; мобильный портал находится в меню «Операция».
– **Тег+/Тег-**: пакетное добавление или удаление тега для выбранной учетной записи.
- **Переместить**: переместить выбранную учетную запись в указанную группу.
— **Включить/деактивировать учетную запись**: пакетное изменение статуса учетной записи, сохранение паролей, токенов и записей проекта. Деактивированные учетные записи больше не будут участвовать в сборе новых проектов, обновлении токенов и автоматической пересылке; когда вам нужно использовать их повторно, вы можете выбрать их на главной странице и включить их в пакетном режиме.
- **Удалить**: окончательное удаление выбранной учетной записи и повторное подтверждение перед операцией.

Временные группы почтовых ящиков также используют один и тот же набор методов выбора, но в пакетном меню отображаются только операции, применимые к временным почтовым ящикам, такие как копирование почтовых ящиков, добавление/удаление меток и удаление; обычные операции, специфичные для учетной записи, такие как обновление токенов и перемещение групп, будут скрыты.

При экспорте по группам будут включены учетные записи выбранной группы и всех ее подгрупп; если выбраны и родительская группа, и подгруппа, экспортируемый контент будет автоматически дедуплицирован.

#### Список управления обновлением токена

Список адресов электронной почты в «Управлении обновлением токенов» также поддерживает тот же метод пакетного выбора:

1. Нажмите «☑» в начале списка, чтобы войти в режим выбора партии.
2. Установите флажок, щелкните строку учетной записи, выберите непрерывный диапазон `Shift` или перетащите ее.
3. Нажмите «Выбрать весь текущий список», чтобы выбрать только те учетные записи, которые были отображены после текущей фильтрации.
4. При поиске по ключевым словам или переключении фильтрации статуса выбранные учетные записи будут очищены, чтобы избежать случайной фильтрации других учетных записей.

После выбора учетной записи вы можете напрямую выполнять следующие пакетные действия:

– **Обновить токен**: продолжайте использовать токен для обновления журнала задач управляемой потоковой передачи и просмотра прогресса и результатов на уровне учетной записи.
- **Копировать адрес электронной почты+псевдоним/экспорт**: повторно используйте процесс экспорта копирования и вторичной проверки обычного списка адресов электронной почты.
– **Деактивация учетной записи**: вы можете сначала отфильтровать учетные записи, которые не удалось обновить, а затем выбрать учетные записи, которые необходимо деактивировать для пакетных операций. После деактивации он будет удален из списка управления обновлением токена, и его по-прежнему можно будет найти на главной странице и включить в пакетном режиме.
- **Агент/Тег+/Тег-/Переместить/Удалить**: повторное использование обычного пакетного интерфейса учетной записи электронной почты. После завершения токен будет обновлен синхронно, чтобы обновить список управления, основной список адресов электронной почты и количество групп.

#### Список рассылки

В левой части списка рассылки обычных почтовых ящиков также имеется поле выбора, которое подходит для пакетной обработки писем в текущем почтовом ящике:

1. Нажмите на поле выбора слева от электронного письма, чтобы выбрать или снять флажок с одного электронного письма.
2. Нажмите «Выбрать все», чтобы выбрать загруженный в данный момент список рассылки.
3. Нажмите «Очистить выбор», чтобы отменить выбранные электронные письма.
4. Нажмите «Установить как прочитанные», чтобы пометить выбранные непрочитанные электронные письма как прочитанные; если все выбранные электронные письма будут прочитаны, эта кнопка будет неактивна.
5. Нажмите «Удалить», чтобы навсегда удалить выбранные электронные письма в пакетном режиме. Перед началом работы вам будет предложено подтвердить еще раз.

Выбор пакета электронной почты применяется только к электронным письмам, которые были загружены в текущую папку/представление агрегирования текущего почтового ящика; при переключении почтовых ящиков, обновлении списка адресов электронной почты или при пустом списке выбранные электронные письма будут удалены.

### 5. Управление псевдонимами

1. Откройте «Редактировать учетную запись» учетной записи электронной почты.
2. Заполните несколько псевдонимов по строкам в «Почтовом ящике псевдонимов».
3. После сохранения основной адрес электронной почты и псевдоним будут указывать на одну и ту же учетную запись.

Подходит для следующих сценариев:

– В одной учетной записи зарегистрировано несколько имен электронной почты.
- Некоторые сайты используют `user+tag@example.com`.
- После того как внешний почтовый ящик будет автоматически перенаправлен в почтовый ящик управления проектом, я надеюсь и дальше использовать исходное имя почтового ящика для получения почты.

### 6. Переадресация электронной почты

Откройте «Переадресация почты» в разделе «Управление проектами» в раскрывающемся меню «Дополнительные функции» вверху (меню «Операция» на мобильном телефоне) или напрямую получите доступ к `/forwarding`. Управление переадресацией не зависит от настроек системы. Правила, каналы и история доставки отображаются в таблицах; параметры опроса сохраняются отдельно в «Настройках запуска», а условия фильтрации электронной почты настраиваются в каждом правиле и не будут перезаписаны при сохранении системных настроек. Сначала настройте **канал уведомлений**, затем добавьте **правило пересылки** и, наконец, подтвердите назначение уведомления посредством предварительного просмотра:

1. **Канал уведомлений**: создайте именованную цель SMTP, Telegram, Business WeChat или Feishu. Можно создать несколько целей одного типа, выбрать несколько каналов из одного источника или один канал может использоваться несколькими источниками. Учетные данные шифруются и сохраняются. В новой форме канала отображаются только настроенные теги, и они остаются пустыми, чтобы сохранить исходные значения. Текущий черновик используется для тестирования и не сохраняется автоматически.
2. **Общий источник почтового ящика**: нажмите «Конкретная учетная запись → Непосредственная и родительская группа → Общая конфигурация по умолчанию», чтобы выбрать самую последнюю чистую конфигурацию. Почтовые ящики и подгруппы, которые не настроены отдельно, автоматически используют конфигурацию верхнего уровня, и нет необходимости наследовать или включать дополнительную переадресацию; метод уведомления может указать канал или отключить уведомление. «Удалить правила переадресации» в списке правил удаляет независимые правила этого источника и восстанавливает использование конфигурации верхнего уровня; после удаления правил по умолчанию уведомления по умолчанию выдаваться не будут. Учетная запись должна быть еще активной; перемещенная группа сохраняет свою собственную явную конфигурацию, и если она не будет перезаписана, она будет следовать за новой группой.
3. **Источник CF**: выберите Worker, затем настройте полное доменное имя или полный адрес получения и выполните разрешение «Конкретный адрес → Полное имя домена → Конфигурация Worker по умолчанию». Поддерживает адреса, которые не были импортированы локально; просто укажите канал для адреса, чтобы уведомить адрес, не открывая все доменное имя. Worker изначально закрыт по умолчанию и не наследует обычную конфигурацию почтового ящика. `example.com` не включает автоматически имена субдоменов; полный адрес сохраняет суффикс и точку `+` и не объединяет псевдонимы.
4. **Множественный выбор и предварительный просмотр**: Почтовые ящики, группы и рабочие используют раскрывающиеся флажки с возможностью поиска, и вы можете вводить адреса электронной почты или имена для фильтрации и проверки элементов один за другим. Измените условия фильтра, чтобы сохранить выбранные источники: «Выбрать все результаты фильтра», чтобы выбрать только текущие соответствующие элементы, и «Очистить все», чтобы отменить все выборы. Правила поддерживают новое добавление, однократное и пакетное редактирование одного и того же исходного диапазона; новые дополнения не будут перезаписывать существующие правила. Если какой-либо из выбранных источников уже имеет независимые правила, они будут отклонены группами. Для редактирования вы можете напрямую использовать значок карандаша списка. В предварительном просмотре вы можете выбрать конкретный почтовый ящик или Worker из выбранного источника, чтобы просмотреть путь автоматического наследования и фактическую цель; историю можно запросить по источнику, полному адресу, каналу и статусу.
5. **Фильтрация правил и пакетная обработка**. Таблицу правил можно фильтровать, комбинируя ключевые слова, диапазон источников, каналы уведомлений и методы уведомлений. Условия будут сохранены после обновления. Проверяйте текущие результаты фильтра по одному или выбирайте их все и удаляйте их пакетно после подтверждения; изменение условий фильтра приведет к снятию флажка, чтобы избежать случайного удаления скрытых правил. Один и тот же исходный диапазон (например, оба являются конкретными обычными почтовыми ящиками или оба являются полными доменными именами CF) поддерживает пакетное редактирование; проверьте метод уведомления, канал, ключевое слово или отправителя, которые будут изменены в форме, неотмеченные поля сохранят свои исходные значения и оставьте пустыми после проверки, чтобы очистить условия. Отредактируйте фиксированный идентификатор источника; различные типы источников по-прежнему можно смешивать и удалять. Если какое-либо правило недействительно, весь пакет будет отклонен. Если запись не удалась, весь пакет будет отменен. Невыбранные правила останутся неизменными. Значок списка мусора с приглашением на удаление и сохранением подтверждения.

Каждое правило переадресации можно настроить независимо с помощью **ключевых слов электронной почты** и **отправителя**, применимых как к обычным почтовым ящикам, так и к CF. Ключевые слова должны быть по одному в строке. Тема или весь видимый текст может содержать любой из них. Он не чувствителен к регистру. Отправитель имеет полный адрес электронной почты в каждой строке, игнорируя регистр и точно совпадая с любым адресом электронной почты отправителя, и не соответствует отображаемому имени или аналогичному суффиксу. Когда оба типа условий заполнены, они должны выполняться одновременно. Если один пункт оставлен пустым, ограничений нет; если оба элемента пусты, все будут перенаправлены. При наследовании используется весь набор целей и условий фильтрации последнего заданного правила и не пересекается с условиями верхнего уровня; и в предварительном просмотре, и в таблице правил отображаются действующие условия. Адрес отправки SMTP и целевые получатели по-прежнему настраиваются единообразно для канала уведомлений.

Интервал опроса, временные окна последовательного/параллельного и обычного почтового ящика, а также параметры мусорной корзины по-прежнему сохраняются независимо в «Настройках запуска»; CF не применяет обычные папки почтового ящика и временные окна. Почта, не соответствующая условиям правила, не будет доставлена, но процесс сканирования будет продолжаться в обычном режиме; корректировка условия не будет автоматически повторно доставлять обработанную почту, а также не будет повторно проверять установленные неудачные доставки.

- Для одного и того же письма + одного и того же конкретного канала уведомлений создается только одна доставка в одном почтовом ящике; множественные ассоциации, повторные сканирования и повторные чтения импортированных адресов CF не будут генерировать второе уведомление. Различные новые электронные письма уведомляются отдельно, а разные каналы одного и того же типа записывают результаты отдельно.
— Повторяются только неудачные цели, если одна цель успешна, а другая неудачна; Отсрочка повторной попытки увеличена вдвое с 30 секунд до максимум 1 часа с учетом более позднего восстановления в исходном направлении. Деактивированные цели не будут перенаправлены на другие каналы и не могут быть удалены, если на них все еще ссылаются источники или они не завершили доставку.
— по умолчанию новая ассоциация будет обрабатывать новые электронные письма только после вступления в силу и не будет автоматически перевыпускать историю; Обычные учетные записи могут явно откатить курсор через существующую запись журнала пересылки и повторно сканировать необработанные исторические электронные письма. Успешные цели по-прежнему будут дедуплицироваться, а новые цели не будут добавляться к существующим событиям.
— Фон CF считывает фактический адрес получателя со страницы Worker и продолжает работать, даже если веб-страница закрыта. Он не создает автоматически локальный почтовый ящик и не записывает во временный почтовый кэш. Ход сканирования и неудачная доставка сохраняются; при перезапуске службы будут продолжать получать письма в течение периода хранения восходящего потока. Активное отключение Worker приостановит сканирование и отправку, а повторное включение не приведет к повторной отправке электронных писем в течение периода активной приостановки по умолчанию.
— Изменение фактического места назначения отменит отставание старой версии места назначения, и вы сможете продолжить попытку еще раз, обновив информацию аутентификации для того же места назначения. Удаление переопределения на уровне почтового ящика восстанавливает наследование, а его закрытие останавливает уведомления из этого источника.
— унифицированные проверки можно запускать вручную, а ошибки сканирования CF, результаты конкретных каналов и причины блокировки можно просматривать в истории.
— В сводках пересылки Telegram, WeChat Business, Feishu и SMTP будет указан фактический получатель; адрес CC также будет отображаться, если электронное письмо имеет адрес CC, а «Не указано» будет отображаться, если информация о получателе отсутствует.

Обновление идемпотентно перенесет старую конфигурацию на совместимые каналы и определенные правила для почтовых ящиков и не будет автоматически генерировать правила «общего почтового ящика по умолчанию». Для существующих учетных записей, которые изначально включали пересылку, каждая установила правило «конкретного обычного почтового ящика» и обозначила исходный канал активации; старые закрытые аккаунты останутся без уведомления. `auto` использует исходные доступные каналы, `none` остается без уведомления и явно решает продолжать использовать старый вход для анализа псевдонимов, таких как `email/tg/qywx` и пробелы. Обычные правила по умолчанию, которые были автоматически перенесены, будут разделены на учетные записи и удалены, в то время как время действия канала, курсор и запись об успехе будут сохранены; Добавленные или измененные вручную правила не будут затронуты. Также существует однократное обновление условий правил: старые глобальные ключевые слова копируются в обычные правила почтовых ящиков, действовавшие до обновления. CF сохраняет исходное поведение, не ограниченное обычными глобальными ключевыми словами; по умолчанию фильтрация новых отправителей не ограничена, а старый адрес отправки SMTP, целевые получатели, учетные данные и исторические доставки сохраняют свои исходные значения. База данных, завершившая миграцию старой версии, также будет обновлена. Метка миграции и данные будут отправлены в одной транзакции. В случае неудачи будет выполнен откат всей базы данных; перезапуск не повлияет на последующие изменения пользователя. Старый интерфейс ключевых слов совместим только с перенесенными учетными записями и не изменяет правила, введенные вручную. Миграция выполняется только один раз, и плановая проверка не восстанавливает ассоциацию; вновь импортированные почтовые ящики по-прежнему могут автоматически использовать правила группировки. CF не включается автоматически. Старый интерфейс настроек настраивает только совместимые каналы для миграции учетных записей и не меняет вручную учетные записи, группы или правила CF; обычные конфигурации по умолчанию по-прежнему могут создаваться пользователями вручную. Старый интерфейс обновления `PUT` совместим и сохранен, новые страницы используют `POST`, а пакетное редактирование одного или того же диапазона использует `PATCH` в соответствии со стабильным идентификатором.

Если вам нужно откатить версию, сначала остановите новое расписание и создайте резервную копию базы данных и ключей. Новая запись об успехе совместимого экземпляра синхронизируется со старой транзакцией `forward_logs` и может использоваться для дедупликации старой версии; сначала подтвердите старое зеркало настроек и выбор совместимого канала, прежде чем запускать старое расписание. Старые версии не могут обрабатывать новые экземпляры и уведомления CF; восстановление резервной копии перед миграцией приведет к потере конфигурации и записей после резервного копирования, а процедуру только отката не следует рассматривать как откат данных без потерь.

#### Робот Фейшукун

1. Добавьте собственного робота в «Настройки -> Роботы» целевой группы Feishu и скопируйте его адрес веб-перехватчика `https://open.feishu.cn/open-apis/bot/v2/hook/...`.
2. В этом проекте создайте новый канал Feishu в «Дополнительные функции -> Пересылка электронной почты -> Каналы уведомлений» и заполните вебхук; Если на роботе включена проверка подписи, одновременно введите ключ подписи.
3. Если робот использует проверку безопасности ключевых слов, вы можете настроить ключевое слово «пересылка электронной почты», и это слово будет содержаться как в тестовом сообщении, так и в официальной сводке электронной почты; при использовании белого списка IP-адресов необходимо разрешить экспорт IP-адресов этой службы.
4. Нажмите «Отправить тестовое сообщение», чтобы проверить конфигурацию, затем сохраните канал и выберите его в «Ассоциации источника»; тест использует текущую форму и не будет сохранен автоматически. Активные обычные адреса электронной почты и адреса CF автоматически уведомляются в соответствии с действующими правилами источника.

Вебхук и ключ подписи зашифрованы и сохранены. Настройки не будут отображаться при повторном открытии. Оставьте пустым, чтобы сохранить существующее значение. После установки флажка «Явно очистить существующие ключи подписи» тест будет отправлен немедленно как конфигурация без подписи. После сохранения подпись больше не будет использоваться для формальной пересылки; это не изменит настройки безопасности на стороне робота Feishu.

Когда Feishu отправляет сводку по электронной почте в виде простого текста, размер тела запроса ограничен 20 КБ в байтах UTF-8, а слишком длинный контент будет обрезан. Официальная пересылка и тестирование разделяют ограничение скорости одного и того же вебхука (до 5 раз в секунду, до 100 раз в минуту); Feishu зафиксирует сбой и будет соблюдать действительный `Retry-After` при возврате ограничения скорости.

История пересылки показывает бизнес-ошибки Feishu, такие как ошибка подписи или несоответствие ключевых слов; HTTP 200 не означает успешную передачу. Неудачные каналы будут повторены при последующих проверках пересылки, а другие успешные каналы не будут отправляться повторно. После сбоя в сети или тайм-аута может оказаться невозможным подтвердить, получил ли Feishu уведомление. Последующие повторные попытки могут по-прежнему приводить к повторным уведомлениям. Сначала вы можете проверить групповое сообщение.

### 7. Резервное копирование WebDAV

Настройте в «Настройки -> Резервное копирование WebDAV»:

1. Введите URL-адрес каталога WebDAV, например `https://dav.example.com/backups`.
2. Введите имя пользователя и пароль WebDAV/пароль приложения по мере необходимости.
3. Заполните 5 выражений Cron, например `0 3 * * *`.
4. Нажмите «Рассчитать время следующего выполнения», чтобы подтвердить предварительный просмотр Cron. Время будет использовать часовой пояс приложения в общих настройках.
5. Нажмите «Проверить WebDAV», чтобы убедиться, что каталог доступен для записи; тест загружает только временные тестовые файлы и не требует пароля для входа.
6. При изменении настроек резервного копирования введите пароль для входа в поле «Подтверждение конфиденциальной операции» и сохраните его.

Дополнительное объяснение:

— При запланированном резервном копировании будет загружен текстовый файл, соответствующий параметру «Экспортировать все группы», с именем файла в виде `all_groups_backup_YYYYMMDD_HHMMSS.txt`.
— Nut Cloud необходимо сначала создать выделенный каталог, а затем заполнить URL-адрес каталога, например `https://dav.jianguoyun.com/dav/mailBackup`; не заполняйте просто `https://dav.jianguoyun.com/dav`
- «Ручная загрузка» немедленно загрузит реальный файл резервной копии, и вам необходимо ввести пароль для входа.
— Резервное копирование WebDAV включает конфиденциальные данные, такие как учетные записи, токены, временные учетные данные электронной почты и т. д. Рекомендуется использовать выделенный каталог WebDAV и контролировать права доступа.

### 8. Расширение для браузера (парольная версия)

Расширение Chrome/Edge Manifest V3 встроено в хранилище, а каталог — `browser-extension/`. Расширение использует пароль для входа в Интернет и не требует внешнего ключа API.

Способ установки:

1. Откройте страницу управления расширениями браузера, например `chrome://extensions/` или `edge://extensions/`.
2. Включите режим разработчика.
3. Выберите «Загрузить распакованное расширение».
4. Выберите каталог `browser-extension` этого склада.

Как использовать:

1. Нажмите значок расширения.
2. Введите адрес службы OutlookEmail и пароль для входа в Интернет.
3. Нажмите «Сохранить конфигурацию» или непосредственно нажмите на вход в функцию на боковой панели.

Расширение предоставит встроенную панель управления на боковой панели браузера, и текущая вкладка веб-страницы не будет обрезана. Такие функции, как «Почтовый ящик», «Импорт», «Обновление», «Токен», «Экспорт», «Ярлыки» и «Настройки» теперь доступны напрямую. Полные инструкции по установке, настройке, функциональности и устранению неполадок доступны в [инструкциях по использованию расширения браузера](browser-extension/README.md).

### 9. Внешний API

Получайте электронные письма напрямую через API-ключ без входа в веб-интерфейс.

Текущая дополнительная поддержка:

– Используйте основной почтовый ящик или псевдоним почтового ящика для получения почты.
- `folder=all` агрегирует входящие и спам одновременно и сортирует их в обратном хронологическом порядке после нормализации, `top` рассчитывает их отдельно для каждой папки
— Поддержка фильтрации списка по теме, отправителю и ключевым словам.
— Поддержка псевдонимов специальных символов, таких как `user+alias@example.com`.
— При запросе адреса `@gmail.com`/`@googlemail.com`, если исходный суффикс не выбран, он автоматически возвращается к другому суффиксу.
— по умолчанию `top=1`
- `skip` / `top` будет выполнять безопасный анализ: нецифровые значения используют значения по умолчанию, отрицательные числа обрабатываются как `0`; `top` — самый крупный `50`.

**Этапы настройки:**
1. Нажмите «⚙️ Настройки» → нажмите «🔑 Генерировать случайным образом» в разделе «Внешний ключ API» → Сохранить.

**Пример вызова:**
```bash
curl -H "X-API-Key: your-api-key" \
  "http://localhost:5000/api/external/emails?email=user@outlook.com&folder=inbox"

curl -H "X-API-Key: your-api-key" \
  "http://localhost:5000/api/external/emails?email=alias@example.com&folder=all&top=10"

curl -H "X-API-Key: your-api-key" \
  "http://localhost:5000/api/external/emails?email=alias@example.com&folder=all&top=10&subject_contains=verify&from_contains=github&keyword=reset"

curl -H "X-API-Key: your-api-key" \
  "http://localhost:5000/api/external/emails?email=user%2Balias%40example.com"
```

Если адрес электронной почты или псевдоним содержит специальные символы:

- `@` может передаваться напрямую
- `+` рекомендуется кодировать как `%2B`.
- `&` должен быть закодирован как `%26`

Если вы автоматически перенаправляете внешний почтовый ящик B в почтовый ящик A, управляемый этим проектом, а затем сопоставляете B как псевдоним A, то вы можете напрямую использовать B в качестве параметра `email` для вызова внешнего API.

Подробную документацию см. в [Документация API](docs/api.md).

## 🏗️ Техническая архитектура

### Стек серверных технологий
— **Flask 3.0+** — Веб-фреймворк
- **SQLite 3** - База данных
— **Запросы/запросы[socks]** — поддержка HTTP-клиента и прокси-сервера.
— **IMAP4_SSL** — поддержка протокола IMAP.
— **Microsoft Graph API** — API электронной почты Outlook/Hotmail.
— **APScheduler + croniter** — запланированное обновление и перенаправление опроса.
- **bcrypt + криптография** - Хеширование паролей и шифрование конфиденциальных полей.

### Стек интерфейсных технологий
– **Встроенный JavaScript** – Нет зависимостей от фреймворка
- **CSS3** — современный стиль
– **Fetch API** – Асинхронный запрос
- **DOMPurify 3.0.8** - Очистка HTML

### Системные требования
- Python 3.9+
- SQLite 3
— Докер (необязательно)
- 2 ГБ+ ОЗУ

## Часто задаваемые вопросы
### Как получить пароль приложения для Gmail
Включите 2fa и создайте пароль приложения здесь.

https://support.google.com/mail/answer/185833?hl=zh-Hans


### Как получить идентификатор группы и идентификатор пользователя tg
#### Получить личный идентификатор (ID пользователя)
Найдите @userinfobot или @getmyid_bot в окне поиска Telegram.

Нажмите «Пуск».

Бот немедленно ответит вашим идентификатором пользователя (строкой цифр).

Если вы хотите узнать чужой идентификатор: просто перешлите отправленное вам сообщение боту, и он отобразит идентификатор этого пользователя.


#### Получить идентификатор группы (ID группы)
Добавьте указанных выше ботов (например, @getmyid_bot) в свою группу.

Введите /myid (или команду, указанную роботом) в группе.

Бот возвращает идентификатор группы.

Примечание. Идентификаторы обычных групп обычно начинаются с цифры, тогда как идентификаторы супергруппы или канала обычно начинаются с -100.
