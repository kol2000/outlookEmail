# Инструмент управления электронной почтой с несколькими почтовыми ящиками

Инструмент управления электронной почтой для сценариев с несколькими учетными записями электронной почты. Он поддерживает унифицированное чтение, управление и пересылку электронной почты через Outlook/Hotmail OAuth, API Microsoft Graph и стандартный IMAP. Он также предоставляет веб-интерфейс и расширение браузера Chrome/Edge для управления группами, управления учетными записями, просмотра электронной почты и вызовов внешних API. В настоящее время поддерживает Outlook/Hotmail, Gmail, QQ, 163, 126, Yahoo, почтовый ящик Alibaba и пользовательские почтовые ящики IMAP, а также интегрирует возможности временных почтовых ящиков GPTMail, DuckMail, Cloudflare Temp Email с несколькими поставщиками.

Примечание. Изменение пароля приведет к тому, что аутентификация станет недействительной и потребуется повторная авторизация.

### Режим работы

Службе необходимо поддерживать работу одного рабочего процесса. Официальный образ Docker исправлен на однопоточный + многопоточный режим Gunicorn; если вы настраиваете развертывание, не увеличивайте количество рабочих. Если требуется параллелизм, отдайте приоритет регулированию количества потоков. Задачи потоковой передачи, управляемые обновлением токена, будут использовать краткосрочное состояние внутри процесса, а несколько рабочих процессов приведут к тому, что инициализация задач и подписка SSE попадут в разные процессы.

#### Необязательно: включите онлайн-обновление интерфейса Docker + используйте собственный идентификатор клиента и URL-адрес обратного вызова.

Онлайн-обновление Docker в интерфейсе требует доступа к сокету хоста Docker. `/var/run/docker.sock` имеет права управления Docker на хосте, и его рекомендуется включать только в доверенной среде.

Эта функция доступна только для контейнеров, использующих переменные теги изображений, такие как `latest`, `main` и `dev`. Если текущий контейнер имеет метку версии, например `v2.0.39`, интерфейс откажется от онлайн-обновления, поскольку Watchtower не будет автоматически переключать фиксированную метку на метку новой версии.
По умолчанию приложение автоматически повторяет попытку в соответствии с «минимальной поддерживаемой версией API», когда демон явно возвращает «минимальную поддерживаемую версию API»; Если ваша среда Docker или агент сокета предъявляют особые требования к совместимости, вы также можете явно установить `DOCKER_UPDATE_API_VERSION`, и его значение может ссылаться на выходные данные `docker version --format '{{.Server.APIVersion}}'`.
Необязательная переменная среды `DOCKER_UPDATE_STATUS_TIMEOUT` используется для независимого управления временем ожидания (в секундах) запроса статуса и проверки контейнера и не влияет на `DOCKER_UPDATE_TIMEOUT` фактической задачи обновления.
Если для текущего тега `latest` / `main` / `dev` нет нового изображения, интерфейс отобразит, что на этот раз обновление не было применено, вместо ложного сообщения о том, что обновление не удалось.

Если вы хотите, чтобы функция «Получить токен» в интерфейсе использовала ваше собственное приложение Azure, установите `OAUTH_CLIENT_ID` и `OAUTH_REDIRECT_URI` одновременно. Эти два значения будут использоваться для генерации ссылок авторизации Microsoft и обмена на Refresh Token; после успешного обмена идентификатор клиента, возвращаемый интерфейсом, необходимо импортировать в учетную запись вместе с токеном обновления. Если этот параметр не установлен, будет использоваться встроенный идентификатор клиента по умолчанию проекта и адрес обратного вызова по умолчанию `http://localhost:8080`.

```yaml
version: '3.8'
services:
  outlook-mail-reader:
    image: ghcr.io/assast/outlookemail:latest
    container_name: outlook-mail-reader
    ports:
      - "5000:5000"
    volumes:
      - ./data:/app/data
      - /var/run/docker.sock:/var/run/docker.sock
    environment:
      - LOGIN_PASSWORD=admin123
      - SECRET_KEY=your-secret-key-here
      - FLASK_ENV=production
      - DOCKER_UPDATE_ENABLED=true
      - DOCKER_UPDATE_CONTAINER=outlook-mail-reader
      # Необязательно: явно укажите версию API в новых средах демона/сокет-прокси Docker.
      # - DOCKER_UPDATE_API_VERSION=1.52
      # Необязательно: разрешите помощнику интерфейса OAuth использовать ваше собственное приложение Azure.
      # - OAUTH_CLIENT_ID=your-azure-application-client-id
      # - OAUTH_REDIRECT_URI=http://localhost:8080
    restart: unless-stopped
```

### Способ 5. Создайте и запустите локальный исходный код (docker-compose.build.yml).

Подходит для запуска после того, как локальный компьютер создаст образ на основе исходного кода (вместо загрузки предварительно созданного образа на `ghcr.io`), что облегчает немедленную проверку после локальных изменений.

Корневой каталог хранилища предоставил `docker-compose.build.yml`, который будет использовать `Dockerfile` в корневом каталоге для создания образа из исходного кода и запуска контейнера.

#### Шаг 1. Подготовьте файл переменных среды `.env.local`.

`docker-compose.build.yml` внедряет переменные среды через `env_file: .env.local`. Если файл ** не существует, Compose напрямую сообщит об ошибке и откажется запускать **. Сначала вам необходимо скопировать и изменить его из шаблона:

```bash
cp .env.example .env.local
```

Измените хотя бы два из следующих пунктов:

```bash
# Создайте случайную строку и введите SECRET_KEY из .env.local.
python -c 'import secrets; print(secrets.token_hex(32))'
```

- `SECRET_KEY`: заполните случайную строку, сгенерированную выше (обязательно измените ее, не используйте значения-заполнители; начальные и конечные пробелы будут игнорироваться)
- `LOGIN_PASSWORD`: пароль для входа во время первой инициализации, по умолчанию — `admin123`, рекомендуется изменить его на надежный пароль; Изменение этой переменной ** после записи ** в базу данных не приведет к перезаписи текущего пароля. Если вы забыли свой пароль, используйте `scripts/reset_login_password.py` (см. [Устранение неполадок](docs/ru/troubleshooting.md) / [Конфигурация безопасности](docs/ru/security.md))

Необязательно: если вам нужно настроить количество потоков/таймаута Gunicorn, добавьте `GUNICORN_THREADS` и `GUNICORN_TIMEOUT` к `.env.local` (если оставить пустым, используйте значение по умолчанию 4/300).

Необязательно: общее время ожидания чтения списков почты в обычных почтовых ящиках Outlook/IMAP по умолчанию составляет 120 секунд, которое можно настроить в «Системные настройки -> Общие настройки -> Таймаут получения почты» (30-300 секунд); вы также можете установить начальное значение через `MAIL_FETCH_OVERALL_TIMEOUT` `.env.local` перед первым запуском. Это значение должно быть меньше `GUNICORN_TIMEOUT` (по умолчанию 300 секунд).

#### Шаг 2. Сборка и запуск

```bash
docker compose -f docker-compose.build.yml up -d --build
```

- `--build` заставляет образ пересобираться из исходного кода (метка образа — `outlookemail:local`)
- Имя контейнера — `outlook-mail`, а отображаемый порт — `5000:5000`.
- Сохранение данных осуществляется на хост-машине `./data`; `./static` и `./templates` монтируются в режиме только для чтения, что облегчает локальное редактирование шаблонов/статических ресурсов, чтобы они вступили в силу в реальном времени.

После запуска посетите `http://localhost:5000` и войдите в систему с помощью `LOGIN_PASSWORD` в `.env.local`.

#### Шаг 3. Общие команды эксплуатации и технического обслуживания.

```bash
# Посмотреть журнал
docker compose -f docker-compose.build.yml logs -f

# Просмотр проверок состояния и статуса
docker compose -f docker-compose.build.yml ps

# Пересобрать и перезапустить после изменения исходного кода.
docker compose -f docker-compose.build.yml up -d --build

# Остановить и удалить контейнер (данные остаются в ./data)
docker compose -f docker-compose.build.yml down
```

> Совет: `docker-compose.build.yml` по умолчанию не монтирует сокет Docker хоста, поэтому «Интернет-обновление Docker» в интерфейсе недоступно. Для сценариев локальной сборки используйте для обновления указанную выше пересборку `up -d --build`.

## ✨ Особенности

### Как читать электронные письма

В настоящее время этот инструмент содержит три типа ссылок для чтения:

1. **Outlook/Hotmail OAuth + Graph API** — метод приоритета, подходит для учетных записей Outlook/Hotmail/Live.
2. **Outlook/Hotmail Резервный вариант OAuth + IMAP ** — `outlook.live.com` / `outlook.office365.com`
3. ** стандартный IMAP** — подходит для Gmail, QQ, 163, 126, Yahoo, почтового ящика Alibaba и пользовательского IMAP.

#### Обычное поведение и ограничения локального хранения почтовых ящиков.

Обычный переключатель локального хранения почтового ящика `normal_mail_local_retention_enabled` по умолчанию отключен. Пользователям необходимо явно включить его в настройках системы, прежде чем обычные почтовые ящики Outlook/Hotmail и стандартные IMAP смогут сохранять метаданные списка и часть просмотренного и заполненного текста в локальном SQLite.

Если эта функция включена, сначала будет загружен обычный список почтовых ящиков из локальных сохраненных данных, а последний сохраненный список адресов электронной почты будет отображаться сразу же при нажатии; если вы продолжите прокручивать вниз, чтобы загрузить больше в режиме локального приоритета, также будет использоваться локальная сохраненная пейджинговая система, поэтому, когда удаленный доступ недоступен, вы все равно сможете просматривать сохраненные электронные письма за пределами первого экрана. Страница также продолжит инициировать удаленную синхронизацию с Graph API или IMAP в фоновом режиме. После успешной удаленной синхронизации новые метаданные списка будут записаны обратно в локальную библиотеку хранения; в случае сбоя синхронизации текущая страница сохранит локальный список и отобразит сообщение об ошибке фоновой синхронизации без очистки списка.

Когда фоновая синхронизация обнаруживает новые электронные письма, которые еще не отображались локально, на странице отображается непрерывное сообщение «Синхронизировано N новых электронных писем». Новые письма не будут добавлены в текущий список сразу после успешной синхронизации; новые электронные письма будут объединены в текущий список только после того, как пользователь нажмет на приглашение, а фоновое завершение выделения, обновление кэша списка и сохранение тела нового электронного письма будут выполнены, чтобы предотвратить внезапную замену прочитанных или выбранных электронных писем.

В деталях электронной почты приоритет будет отдаваться зарезервированному основному содержимому; Если локальная строка не имеет основного содержимого, основное содержимое будет заполнено сохраненными данными после успешного чтения удаленных сведений для последующего просмотра при обновлении страницы, перезапуске приложения или возникновении временного сбоя в сети. Если удаленные сведения не работают, но локальный текст уже существует, на странице сведений будет отображаться локальный сохраненный текст в качестве резервного варианта. Фильтрация ключевых слов также сначала проверяет кешированный текст, и только если кеш отсутствует, удаленные данные будут прочитаны.

Резервная ссылка IMAP в Outlook/Hotmail OAuth по умолчанию считывает сведения и вложения по UID; Элементы списка, подробные запросы и загрузки вложений могут содержать `id_mode=uid|sequence`, чтобы избежать смешивания UID и серийных номеров, что может привести к неправильному получению электронной почты. Стандартные учетные записи IMAP продолжают использовать существующую логику чтения идентификаторов сообщений.

На этом этапе сохраняются только метаданные общего списка почтовых ящиков и текст сведений о прочтении, а загрузка или сохранение двоичного файла вложения и исходного содержимого MIME не включается; загрузка вложения по-прежнему зависит от текущей ссылки удаленного провайдера. На странице настроек отображается количество сохраненных сообщений, количество кэшированных тел, предполагаемый размер хранения и текущий размер базы данных SQLite, а также предусмотрено отдельное действие «очистить кеш». Когда переключатель локального удержания выключен, интерфейс сначала запросит подтверждение; после подтверждения локальные данные хранения обычного почтового ящика будут удалены с помощью задачи фоновой очистки, и будет отображен статус очистки. Задачи очистки отклоняют повторные запуски, ограничивают повторные попытки эфемерных блокировок SQLite, а опрос состояния внешнего интерфейса использует интервалы отсрочки для снижения нагрузки при выполнении длительных задач. См. [`docs/local-mail-retention.md`](docs/ru/local-mail-retention.md) для более полного описания области действия.

### Функция веб-приложения

#### Основные функции
- 🔐 ** Проверка входа в систему ** — веб-интерфейс, защищенный паролем, поддерживает онлайн-изменение пароля; если вы забыли свой пароль, вы можете использовать официальный скрипт `scripts/reset_login_password.py` для его сброса (см. [Устранение неполадок](docs/ru/troubleshooting.md))
- 📁 ** Управление группами ** — поддерживает до трех уровней древовидной группировки почтовых ящиков, создание, редактирование, свертывание и расширение, сортировку одноуровневых элементов, перетаскивание между уровнями и каскадное удаление.
- 🌐 ** прокси-сервер учетной записи/группы ** — каждая группа может быть настроена с использованием прокси-сервера HTTP/SOCKS5, а подгруппы могут наследовать родительский прокси-сервер. Одна учетная запись также может установить прокси и сначала переопределить групповой прокси; URL-адрес прокси-сервера поддерживает заполнитель `{mail}` (связанный с пулами липких прокси, такими как [Resin](https://github.com/Resinat/Resin))

### 2. Импортируйте учетную запись электронной почты.

После нажатия «Импортировать почтовый ящик» в веб-интерфейсе вы можете выбрать соответствующий формат импорта в соответствии с типом почтового ящика.

#### Outlook/Hotmail OAuth

Поддерживаются два формата:

```txt
Электронная почта ---- Пароль ---- client_id ----refresh_token
Электронная почта ----Пароль ----refresh_token ----client_id
```

Пример:

```txt
user@outlook.com----password123----24d9a0ed-8787-4584-883c-2fd79308940a----0.AXEA...
```

#### Стандартный почтовый ящик IMAP.

Применимо к Gmail, QQ, 163, 126, Yahoo, почтовому ящику Alibaba и т. д.:

```txt
Электронная почта ----код авторизации IMAP/пароль приложения.
```

Пример:

```txt
user@gmail.com----app-password
user@qq.com----imap-auth-code
```

#### Пользовательский IMAP

Поддерживаются два формата:

```txt
Электронная почта ---- пароль IMAP.
Электронная почта ---- пароль IMAP ---- imap_host ---- imap_port
```

Пример:

```txt
user@example.com----app-password
user@example.com----app-password----imap.example.com----993
```

Поддержка пакетного импорта, по одной учетной записи в строке. Формат импортируемого файла остается неизменным; всплывающее окно импорта может единообразно устанавливать заметки, метки и статус для этой новой учетной записи, и вы можете выбрать, включать ли пересылку электронной почты немедленно. Временные группы почтовых ящиков невозможно выбрать при импорте обычных почтовых ящиков.

Группировка поддерживает до трех уровней иерархии. Если выбрана родительская группа, в списке учетных записей электронной почты одновременно будут отображаться учетные записи этой группы и всех подгрупп; если в подгруппе не настроен агент, она унаследует агент родительской группы вверх. Удаление группы, содержащей подгруппы, приведет к каскадному удалению подгрупп и перемещению связанных учетных записей обратно в группу по умолчанию.

#### Шаблон Proxy и Resin `{mail}`

URL-адреса прокси-серверов группы или учетной записи могут содержать буквальный символ `{mail}`. Исходящие запросы (извлечение писем, обновление токена, автоматическая авторизация Outlook и т. д.) будут заменены адресом электронной почты `@` во время выполнения. Локальная часть: удалить небуквенно-цифровые символы и преобразовать их в нижний регистр. Настройте библиотеку как есть, и эхо редактирования не будет расширено.

Рекомендуемый пример (порт Resin по умолчанию 2260, липкий идентификатор V1 `Platform.Account:TOKEN`):

```text
socks5h://outlook.{mail}:yourToken@127.0.0.1:2260
```

Если токен пуст, доступны следующие два варианта:

```text
socks5h://outlook.{mail}:@127.0.0.1:2260
socks5h://outlook.{mail}@127.0.0.1:2260
```

Описание:

- Рекомендуется отдавать приоритет `socks5h://`/`socks5://`; обычный HTTP-прокси может быть недоступен для запросов токенов IMAP
- После очистки разные префиксы электронной почты могут конфликтовать (например, `a.b` и `ab`). Такое поведение принято этим проектом
- Автоматическая авторизация учетной записи загрузки: установите приоритет загрузки для записи собственного `proxy_url`, в противном случае наследуйте шаблон группового прокси.
- По умолчанию `LOG_LEVEL=INFO` будет печатать детали `[Агент]` (кодирование пароля) при получении сообщения/обновлении токена/автоматической авторизации. Если имеется много журналов пакетных сцен, установите `LOG_LEVEL=WARNING`, чтобы уменьшить шум и закрыть этот тип INFO.
- Дружественный проект: [Resin](https://github.com/Resinat/Resin)

### 3. Проверьте электронную почту.

1. Выберите группу слева
2. Выберите учетную запись электронной почты.
3. Нажмите кнопку «Получить письмо».
4. Переключитесь на «Входящие» и «Спам» в веб-интерфейсе, чтобы просмотреть электронные письма.
5. Прокрутите список рассылки до конца, чтобы автоматически загрузить следующую страницу (20 сообщений на странице).
6. Нажмите на электронное письмо, чтобы просмотреть подробную информацию, поддерживается рендеринг HTML и полноэкранный просмотр.
7. Если вам необходимо просмотреть результаты агрегации `deleteditems` или `all`, рекомендуется использовать внешний API или внутренний API.

#### Базовое написание электронных писем на веб-сайте.

После выбора включенной основной учетной записи Outlook/Hotmail, авторизованной `GraphAPI`, в верхней части списка почты будет отображаться надпись «Написать письмо». Эта функция поддерживает отправку электронных писем в виде обычного текста только одному или нескольким получателям в качестве самой текущей учетной записи:

- Если для исторической учетной записи будет предложено повторно авторизоваться, пожалуйста, завершите авторизацию `GraphAPI` еще раз в соответствии с вышеизложенным, чтобы получить `Mail.Send`.
- Когда Microsoft Graph возвращает `202 Accepted`, в интерфейсе отображается «Почта отправлена ​​на отправку»; это означает, что сервис принял запрос, но это не означает, что получателю доставлено.
- Когда запрос на отправку сталкивается с тайм-аутом сети или прерыванием соединения, система не будет автоматически отправлять его повторно, чтобы избежать повторной доставки; пожалуйста, подтвердите результат, прежде чем решить, отправлять ли его повторно вручную.
- В настоящее время отправка вручную по IMAP/SMTP, отправка временного почтового ящика, псевдонима или общего почтового ящика, вложения, HTML/форматированный текст, черновик, ответ/пересылка, список отправленных, портал расширений браузера, внешний API, пакетная, запланированная или автоматическая отправка писем не поддерживаются.

### 4. Выбор партии и работа с партиями.

#### Список учетных записей электронной почты

В левой части списка учетных записей электронной почты есть поле выбора, которое подходит для обновления токенов, копирования адресов электронной почты, изменения статуса пересылки, маркировки, перемещения групп или одновременного удаления нескольких учетных записей.

Общие методы выбора:

1. Выбор радио **/отмена выбора радио **: щелкните поле выбора в левой части учетной записи.
2. ** Войдите в режим пакетного выбора. **: нажмите кнопку «☑» в верхней части панели почтового ящика. После того, как кнопка выделена, вы можете щелкнуть строку учетной записи, чтобы переключить выбранное состояние, не нажимая на поле выбора.
3. ** непрерывный выбор диапазона **: сначала выберите учетную запись, затем, удерживая `Shift`, щелкните другую учетную запись или поле выбора, и будет выбран непрерывный диапазон между ними.
4. ** перетащите, чтобы выбрать **: после входа в режим пакетного выбора нажмите и удерживайте мышь/трекпад на строке учетной записи или поле выбора и перетащите вверх или вниз, чтобы непрерывно выбирать проходящие учетные записи; если стартовая учетная запись была выбрана, это перетаскивание приведет к групповой отмене выбора проходящих учетных записей.
5. ** Выбрать весь текущий список **: Нажмите «Выбрать все» или «Выбрать все загруженные» в пакетном меню. Когда список учетных записей загружается на страницах, эта кнопка работает только для учетных записей, загруженных в данный момент на страницу; продолжив прокрутку вниз, чтобы загрузить больше, вы можете нажать еще раз, чтобы выбрать все загруженные.
6. ** Очистить выбор **: Нажмите «Очистить выбор», чтобы отменить все выборы в текущем списке.

После выбора хотя бы одной учетной записи появится пакетное меню:

- ПК: меню перемещается справа от первой выбранной учетной записи и перемещается по мере прокрутки списка учетных записей.
- Мобильное устройство: меню отображается внизу для удобного сенсорного управления.

Пакетные операции, поддерживаемые обычными учетными записями электронной почты:

- ** Токен обновления **: доступен только для учетных записей Outlook/Hotmail OAuth; Учетные записи IMAP не могут быть обновлены, и кнопка покажет количество обновлений.
- ** Копировать адрес электронной почты + псевдоним **: Скопируйте основной адрес электронной почты и настроенный псевдоним выбранной учетной записи.
- Экспорт ** **: экспорт выбранных учетных записей после вторичной проверки. Целесообразно сначала фильтровать по тегу или выполнять поиск, а затем экспортировать только выбранные в данный момент учетные записи.
- ** Включить переадресацию/Отменить переадресацию **: Пакетное изменение переключателя переадресации на уровне учетной записи. Глобальный канал пересылки по-прежнему необходимо настроить в «Настройки -> Настройки пересылки электронной почты».
- ** tag + / tag - **: пакетное добавление или удаление тега для выбранной учетной записи.
- ** переместить **: переместить выбранную учетную запись в указанную группу.
- ** удалить **: окончательно удалить выбранную учетную запись, вам потребуется еще раз подтвердить операцию перед операцией.

Временные группы почтовых ящиков также используют один и тот же набор методов выбора, но в пакетном меню отображаются только операции, применимые к временным почтовым ящикам, такие как копирование почтовых ящиков, добавление/удаление меток и удаление; обычные операции, связанные с учетной записью, такие как обновление токенов, переадресация и перемещение групп, будут скрыты.

При экспорте по группам будут включены учетные записи выбранной группы и всех ее подгрупп; если выбраны и родительская группа, и подгруппа, экспортируемый контент будет автоматически дедуплицирован.

#### Список управления обновлением токенов

Список адресов электронной почты в «Управлении обновлением токенов» также поддерживает тот же метод пакетного выбора:

1. Нажмите «☑» в начале списка, чтобы войти в режим выбора партии.
2. Выбирайте учетные записи с помощью флажков, щелчков строк учетной записи, непрерывного выбора диапазона `Shift` или перетаскивания.
3. Нажмите «Выбрать весь текущий список», чтобы выбрать только те учетные записи, которые были отображены после текущей фильтрации.
4. При поиске по ключевым словам или переключении фильтрации статуса выбранные учетные записи будут очищены, чтобы избежать ошибочной фильтрации других учетных записей.

После выбора учетной записи вы можете напрямую выполнять следующие пакетные действия:

- ** Обновить токен**: продолжайте использовать токен для обновления журнала задач управляемой потоковой передачи, и вы сможете просматривать прогресс и результаты на уровне учетной записи.
- ** копировать почтовый ящик + псевдоним / экспорт **: повторное использование копии и процесса экспорта вторичной проверки обычного списка почтовых ящиков.
- ** включает пересылку/отмену пересылки/агент/метку+/метку-/перемещение/удаление **: повторное использование обычного пакетного интерфейса учетной записи электронной почты. После завершения токен будет обновлен синхронно, чтобы обновить список управления, список основных почтовых ящиков и количество групп.

#### Список рассылки

В левой части списка рассылки обычных почтовых ящиков также имеется поле выбора, которое подходит для пакетной обработки писем в текущем почтовом ящике:

1. Нажмите на поле выбора слева от электронного письма, чтобы выбрать или снять флажок с одного электронного письма.
2. Нажмите «Выбрать все», чтобы выбрать загруженный в данный момент список рассылки.
3. Нажмите «Очистить выбор», чтобы отменить выбранные электронные письма.
4. Нажмите «Установить как прочитанные», чтобы пометить выбранные непрочитанные электронные письма как прочитанные; если все выбранные электронные письма будут прочитаны, эта кнопка будет неактивна.
5. Нажмите «Удалить», чтобы навсегда удалить выбранные электронные письма в пакетном режиме. Перед началом работы вам будет предложено подтвердить еще раз.

Выбор пакета электронной почты применяется только к электронным письмам, которые были загружены в текущую папку/представление агрегирования текущего почтового ящика; при переключении почтовых ящиков, обновлении списка адресов электронной почты или при пустом списке выбранные электронные письма будут удалены.

### 5. Управление псевдонимами

1. Откройте «Редактировать учетную запись» учетной записи электронной почты.
2. Введите несколько псевдонимов по строкам в «Почтовый ящик псевдонимов».
3. После сохранения основной адрес электронной почты и псевдоним будут указывать на одну и ту же учетную запись.

Подходит для следующих сценариев:

- В одной и той же учетной записи зарегистрировано несколько имен электронной почты.
- Некоторые сайты используют `user+tag@example.com`.
- После того как внешний почтовый ящик будет автоматически перенаправлен в почтовый ящик управления проектом, я надеюсь и дальше использовать исходное имя почтового ящика для получения почты.

### 6. Переадресация электронной почты

Пересылка электронной почты разделена на два уровня контроля:

1. ** Переключатель уровня учетной записи **
   При импорте учетной записи или редактировании учетной записи выберите, следует ли включить переадресацию для учетной записи.
2. ** глобальные настройки переадресации **
   Настройте в «Настройки -> Настройки пересылки электронной почты»:
   - Интервал опроса
   - Диапазон времени пересылки электронной почты
   - Пересылать ли спам-сообщения
   - Канал пересылки (SMTP/Telegram)
   - Специфические параметры SMTP/Telegram

Дополнительное объяснение:

- Опрос пересылки обрабатывает только почтовые ящики с «включенной пересылкой в учетной записи».
- Проверку переадресации можно запустить вручную.
- Вы можете просмотреть недавнюю историю переадресации и записи об ошибках.

### 7. Резервное копирование через WebDAV.

Настройте в «Настройки -> Резервное копирование WebDAV»:

1. Введите URL-адрес каталога WebDAV, например `https://dav.example.com/backups`.
2. Введите имя пользователя и пароль WebDAV/пароль приложения по мере необходимости.
3. Заполните 5 выражений Cron, например `0 3 * * *`.
4. Нажмите «Рассчитать время следующего выполнения», чтобы подтвердить предварительный просмотр Cron. Время будет использовать часовой пояс приложения в общих настройках.
5. Нажмите «Проверить WebDAV», чтобы убедиться, что каталог доступен для записи; тест загружает только временные тестовые файлы и не требует пароля для входа.
6. При изменении настроек резервного копирования введите пароль для входа в поле «Подтверждение конфиденциальной операции» и сохраните его.

Дополнительное объяснение:

- При запланированном резервном копировании будет загружен текстовый файл, соответствующий параметру «Экспортировать все группы», с именем файла в виде `all_groups_backup_YYYYMMDD_HHMMSS.txt`.
- Nut Cloud необходимо сначала создать выделенный каталог, а затем ввести URL-адрес каталога, например `https://dav.jianguoyun.com/dav/mailBackup`; не заполняйте просто `https://dav.jianguoyun.com/dav`
- «Ручная загрузка» немедленно загрузит реальный файл резервной копии, и вам необходимо ввести пароль для входа.
- Резервное копирование WebDAV включает конфиденциальные данные, такие как учетные записи, токены, временные учетные данные электронной почты и т. д. Рекомендуется использовать выделенный каталог WebDAV и контролировать права доступа.

### 8. Расширение для браузера (парольная версия)

Расширение Chrome/Edge Manifest V3 встроено в хранилище, а каталог — `browser-extension/`. Расширение использует пароль для входа в Интернет и не требует внешнего ключа API.

Способ установки:

1. Откройте страницу управления расширениями браузера, например `chrome://extensions/` или `edge://extensions/`.
2. Включите режим разработчика
3. Выберите «Загрузить распакованное расширение».
4. Выберите каталог `browser-extension` этого склада.

Как использовать:

1. Нажмите на значок расширения.
2. Введите адрес службы OutlookEmail и пароль для входа в Интернет.
3. Нажмите «Сохранить конфигурацию» или непосредственно нажмите на вход в функцию на боковой панели.

Расширение предоставит встроенную панель управления на боковой панели браузера, и текущая вкладка веб-страницы не будет обрезана. Такие функции, как «Почтовый ящик», «Импорт», «Обновление», «Токен», «Экспорт», «Ярлыки» и «Настройки» теперь доступны напрямую. См. [Инструкции по использованию расширения для браузера](browser-extension/README.ru.md) для получения полных инструкций по установке, настройке, функциональности и устранению неполадок.

### 9. Внешний API

Получайте электронные письма напрямую через API-ключ без входа в веб-интерфейс.

Текущая дополнительная поддержка:

- Используйте свой основной почтовый ящик или псевдоним для получения почты.
- `folder=all` объединяет входящие и спам-сообщения одновременно и сортирует их в порядке, обратном нормализованному времени электронной почты, `top` рассчитывается отдельно для каждой папки.
- Поддержка фильтрации списка по теме, отправителю и ключевым словам.
- Поддержка псевдонимов специальных символов, таких как `user+alias@example.com`.
- При запросе адреса `@gmail.com` / `@googlemail.com`, если исходный суффикс не выбран, он автоматически вернется к другому суффиксу.
- По умолчанию `top=1`
- `skip` / `top` будет выполнять безопасный анализ: нецифровые значения используют значения по умолчанию, отрицательные числа обрабатываются как `0`; `top` — самый крупный `50`.

Шаги настройки **: **
1. Нажмите «⚙️ Настройки» → нажмите «🔑 Сгенерировать случайным образом» в разделе «Внешний ключ API» → Сохранить.

Пример вызова **: **
```bash
curl -H "X-API-Key: your-api-key" \
  "http://localhost:5000/api/external/emails?email=user@outlook.com&folder=inbox"

curl -H "X-API-Key: your-api-key" \
  "http://localhost:5000/api/external/emails?email=alias@example.com&folder=all&top=10"

curl -H "X-API-Key: your-api-key" \
  "http://localhost:5000/api/external/emails?email=alias@example.com&folder=all&top=10&subject_contains=verify&from_contains=github&keyword=reset"

curl -H "X-API-Key: your-api-key" \
  "http://localhost:5000/api/external/emails?email=user%2Balias%40example.com"
```

Если адрес электронной почты или псевдоним содержит специальные символы:

- Символ `@` можно передавать без кодирования.
- `+` рекомендуется кодировать как `%2B`.
- `&` должен быть закодирован как `%26`.

Если вы автоматически перенаправляете внешний почтовый ящик B в почтовый ящик A, управляемый этим проектом, а затем сопоставляете B как псевдоним A, то вы можете напрямую использовать B в качестве параметра `email` для вызова внешнего API.

Подробную документацию см. в [Документация по API](docs/ru/api.md).

## 🏗️Техническая архитектура

### Стек серверных технологий
- **Flask 3.0+** — веб-фреймворк
- **SQLite 3** — База данных
- **Requests/requests[socks]** — поддержка HTTP-клиента и прокси
- **IMAP4_SSL** — поддержка протокола IMAP.
- **Microsoft Graph API** — API почты Outlook/Hotmail
- **APScheduler + croniter** — запланированное обновление и пересылка опроса
- **bcrypt + криптография** — хеширование паролей и шифрование конфиденциальных полей.

### Стек интерфейсных технологий
- Собственный JavaScript **** – нет зависимостей от фреймворка
- **CSS3** — современный стиль.
- **Fetch API** — асинхронный запрос
- **DOMPurify 3.0.8** — очистка HTML

### Системные требования
- Python 3.9+
- SQLite 3
- Докер (необязательно)
- Память более 2 ГБ

## Часто задаваемые вопросы
### Как получить пароль приложения для Gmail
Включите 2fa и создайте пароль приложения здесь.

https://support.google.com/mail/answer/185833?hl=zh-Hans


### Как получить идентификатор группы и идентификатор пользователя tg
#### Получить личный идентификатор (идентификатор пользователя)
Найдите @userinfobot или @getmyid_bot в окне поиска Telegram.

Нажмите «Пуск».

Бот немедленно ответит вашим идентификатором пользователя (строкой цифр).

Если вы хотите узнать чужой идентификатор: просто перешлите отправленное вам сообщение боту, и он отобразит идентификатор этого пользователя.


#### Получить идентификатор группы (ID группы)
Добавьте указанных выше ботов (например, @getmyid_bot) в свою группу.

Введите /myid (или команду, указанную роботом) в группе.

Бот возвращает идентификатор группы.

Примечание. Обычные идентификаторы групп обычно начинаются с цифры, тогда как идентификатор супергруппы ** или канала ** обычно начинается с -100.
